# Справочник библиотеки amemo

[Reference in English](library.md) · [Назад к README](../README.ru.md)

Здесь описана библиотека Python — та часть amemo, что готова уже сейчас: модель данных, поиск,
автопроверка, очередь проверки, профили и карточки, подборки, папки и бэкапы. Служба HTTP,
CLI и сервер MCP строятся на этих же функциях (см. [дорожную карту](../README.ru.md#дорожная-карта)).

## Устройство

- **Атомы** — типизированные утверждения (факт, термин, методика, решение, вопрос,
  урок, требование, параметр). **Сущности** — вещи, о которых говорят атомы
  (проект, документ, редакция, организация, человек, место, программа, тема).
- **Объекты** — файлы-источники и ссылки, хранятся по хэшу содержимого (OCFL):
  копия, на которую ссылается источник, сохраняется навсегда.
- **Связи** — типизированные отношения между атомами и сущностями: правила пар
  концов, симметрия, вывод из оборота вместо удаления.
- **Ревизии** — ничего не перезаписывается: каждое изменение — новая ревизия
  с каноническим телом и хэшем содержимого (JSON Canonicalization Scheme, `sha256-c1:`).
- **Проверка** — источники разрешаются в версии объектов и их digest, сверка цитат находит
  цитату в реальном тексте файла, а каждая записываемая запись проходит конвейер автопроверки
  (см. [Автопроверка](#автопроверка)).
- **Пакеты домена** — словари и шаблоны подключаются пакетами
  (`amemo/packs/core` — само ядро; дополнительные — через переменную `AMEMO_PACKS`).
  Коды, которыми пользуются записи, защищены внешними ключами. Пакет может зависеть от других
  (`requires`: имя пакета → диапазон версий); пакеты грузятся в порядке зависимостей, ядро
  (версия 1.3.0) первым, цикл или не выполненный диапазон — ошибка, а `broader` понятия должен
  вести на код той же схемы в загружаемом пакете. У вида атома есть семья `family`: `source` — знание
  из документа, `work` — из работы; вид без неё считается `work`.
- **Основание и уверенность** — атом, значение которого взято не из документа об объекте, несёт
  основание `basis`: `default` (умолчание методики «в запас»), `assumed` (допущение, чтобы продолжить
  работу; требует подтверждения) или `author` (слово самого человека; ставит только агент `person:`).
  `default` и `assumed` без `derived_from` дают предупреждение: не видно правила, по которому они приняты.
  Собственная оценка модели — `confidence` (от 0 до 1); у записи человека её нет.
- **Задел под хаб** — у каждой базы есть стабильный `base_id`; атомы, перенесённые
  из другой базы, хранят `provenance.origin_base`.

## Поиск

Четыре именованных рецепта в `amemo.recipes`; каждый возвращает обычные данные, совместимые с JSON:

- `exact_fact(conn, query, agent=…)` — марки и обозначения (точно и по началу), русский полнотекст
  и вектора, слитые через RRF; точная марка всегда первой, при неоднозначности — все кандидаты;
- `similar(conn, query, agent=…)` — смысловые соседи текста или записи (ссылка `atm:` / `ent:`), с текстовым запасным вариантом;
- `what_changed(conn, ref=…, since=…, until=…)` — ревизии, решения проверки, статусы, переносы по папкам и связи за интервал;
- `around_entity(conn, ref, depth=1, rels=…, statuses=…)` — кратчайшие пути по связям и полям
  `about` / `derived_from`; уверенность пути — по слабейшей оценённой связи, `evidence_role` —
  по слабейшей роли источников.

Агенты отмечают атомы, которые помогли (`amemo.usefulness.mark_helpful`); отметки затухают со временем
и дают небольшой ограниченный подъём в выдаче — на статус и проверку они не влияют.

Вектора — локальные и необязательные: `pip install -e ".[embed]"` добавляет fastembed (модель
скачивается только с явного разрешения). `AMEMO_BACKEND=none` отключает смысловой канал — лексический
поиск продолжает работать, а выдача сообщает `semantic: unavailable`.

Смысловой канал работает на единственной активной модели из `embedding_model`. Из терминала его
включает человек — `amemo embed enable`, проверяет — `amemo embed status` (см. README). Из Python это
три шага `amemo.embed` — то же, что делает команда:

```python
from amemo import embed

provider = embed.FastembedProvider(allow_download=True)   # многоязычная модель по умолчанию, 384 измерения
model = embed.register_model(conn, provider)              # идемпотентно: имя, версия, провайдер, размерность
embed.sync_embeddings(conn, model["id"], provider)        # текущие документы без свежего вектора
embed.activate_model(conn, model["id"])                   # откажет, пока вектор есть не у каждого документа
```

- `embedding_coverage(conn, model_id)` → `{total, covered, missing, complete}` по текущим документам;
  `embed_revision(conn, target, revision_id, model_id)` считает вектор одной ревизии.
- Файлы модели — в `embed.models_dir()`: `AMEMO_MODELS`, иначе `FASTEMBED_CACHE_PATH`, иначе
  `~/.local/share/amemo/models` (а не временная папка fastembed, которую чистит перезагрузка). Без
  `allow_download=True` провайдер читает только эти файлы и в сеть не ходит.
- Запись пока сама свою ревизию не векторизует: досчитывает `sync_embeddings` (или повторный
  `amemo embed enable`), а выдача поиска сообщает покрытую долю в `embedding_coverage`.

## Автопроверка

`amemo.check.submit(conn, store, docs, proposals, links, agent=…)` — единая точка записи знаний:
проверяет пакет целиком, затем записывает его одной транзакцией.

1. схема и шаблоны — поля, типы, правила связей, единицы UCUM;
2. привязка к источнику — цитата найдена в файле, страница совпадает, числа утверждения есть
   во фрагменте; работает для PDF, Markdown, xlsx и docx;
3. здравый смысл — диапазоны значений, единицы, противоречия с имеющимися атомами;
4. дубли — по тексту и по вектору.

Ошибка уровня 1 или 2 отклоняет пакет целиком с отчётом, ничего не пишется. Иначе каждая запись
получает статус `draft`, `needs_review` или `auto_verified` (правка проверенной записи ждёт решения
человека). Ответ (`Submitted`) разделяет сделанное и поставленное в очередь: `complete` ложно, если
появились пункты проверки, `queued` перечисляет их, а уровень 5 (смысловая проверка другой моделью
или человеком) показан как `queued`. Числа, пересчитанные агентом, помечаются в источнике `role: "derived"`.
Высокий риск (`high_risk` в шаблонах пакетов, `decision` в ядре) всегда уходит к человеку.

Очередь проверки — `amemo.review`. `claim(conn, agent=…)` выдаёт самые старые пункты, которые агент
вправе решать, с арендой (по умолчанию 15 минут): параллельные проверяющие не берут один пункт;
`release` возвращает пункт, `items` — список пунктов для интерфейсов. `resolve(conn, item_id,
outcome, agent=…)` записывает вердикт и применяет его, в том числе без захвата. Модель (`model:…`)
решает только `semantic`, и не по своему пакету, с уверенностью `confidence`: `confirmed` от 0,8
делает атом `auto_verified`, иначе он уходит человеку пунктом `semantic_doubt`; статус меняется,
только пока атом ещё `draft`, иначе записывается лишь вердикт. Человек (`person:…`) решает всё
исходами `confirmed` или `refuted`: запись становится `verified` или `rejected`, остальные её
открытые пункты, кроме `source_changed`, закрываются; по `edit` правка принимается или отклоняется,
а запись остаётся `verified`. `enqueue` — ручная постановка человеком (`calibration`, `audit`),
`stats` — размер очереди, время решений, отклонённые пакеты и итоги аудита. Когда у файла появляется
новая версия (`objects.ingest`), текущие и ждущие решения ревизии со ссылкой на старую версию
получают пункт `source_changed`; записи `rejected`, `deprecated` и `superseded` пропускаются.

Запись человека (`person:…`) сразу `verified`, без риска и очереди (в очередь может попасть только
`source_changed`); уровни 1–4 работают как обычно, замечания остаются в отчёте. Правка такой записи
моделью ждёт решения человека. Низкая уверенность `confidence` (ниже 0,8) — высокий риск, если шаблон
включил правило `low_confidence`.

## Профили и карточка

У шаблона сущности (`target: entity`) может быть раздел `parameters` — профиль класса сущности:
какие величины (коды словаря `property`) описывают такую вещь. Правило задаёт величину, `required`
(блокер, если значения нет), `group`, `origin` (откуда обычно берётся значение, словарь
`parameter_origin`), `default` (показывается, но значением не считается) и `ask` / `hint` / `when`
(кого спросить, где искать, когда применимо). Профили наследуются через `extends`: правило потомка
заменяет правило предка с той же величиной.

`group` — код. Чтобы группы показывались словами, пакет может добавить необязательный словарь
`parameter_group` (код и подпись); ядро его не проверяет, а веб-UI без него показывает сам код
(`operating_conditions` → «Operating conditions»). Всё это есть в пакете-образце `tools/sample-pack/meteo`.

`amemo.profile.card(conn, ref, ancestors=True)` собирает карточку сущности (формат `amem.card/1`)
по действующим атомам `parameter` о ней; ничего не хранится. У каждого поля в `fields` есть `state`:

- `known` — одно значение (или несколько равных); в поле же `status` атома, кто записал (`by`),
  `basis`, `confidence`, `rank`, роль источника и `sources`; прочие значения — в `candidates`;
- `conflict` — разные значения без единственного `preferred` либо «не относится» против значения;
- `na` — документ говорит, что величина не относится к объекту;
- `asked` — значения нет, но есть вопрос (атом `question`) об этой величине;
- `missing` — пока ничего не известно.

В `extra` — атомы о величинах вне профиля (у сущности без профиля есть только `extra`), `summary`
считает поля по состояниям, открытые блокеры (`blockers_open`) и поля с основанием, а `ancestors` —
карточки сущностей выше по `part_of`. `amemo.profile.rules_for_entity(conn, entity_class)` возвращает
правила, которые класс получает из своих шаблонов.

`amemo.records.rebuild_projections(conn)` перестраивает проекции атомов по всем ревизиям (идемпотентно,
тела ревизий не меняются): `atom_property` стирается и строится заново, а `atom_about` и `atom_derived`
защищены от удаления — в них дописываются только недостающие строки.

## Подборки

Подборка (`amem.bundle/1`) — отобранные записи, которые переносят из одной базы в другую: папка или
zip с той же структурой. `manifest.json` пишется последним и хранит sha256 каждой части; части —
`atoms.jsonl`, `entities.jsonl`, `links.jsonl`, `sources.jsonl`, `objects.jsonl` и `concepts.jsonl`,
а по желанию — файлы документов-источников (`objects/sha256/…`), история ревизий и копии пакетов.

```python
from amemo import bundle

bundle.export(conn, store=store, folder=Path("out/shared"), agent="person:anna",
              selection=bundle.Selection(tags=("shared",), kinds=("parameter",)),
              with_files=True, with_history=False, with_packs=False)
bundle.inspect(Path("out/shared"))        # проверка целостности, база не нужна
bundle.import_(conn, store, Path("out/shared"), agent="person:boris", trust="keep", dry_run=True)
```

**Экспорт.** `Selection` отбирает по `tags`, `kinds`, `entity_classes`, явным `refs`, `project`,
`statuses` и `since`; запись должна подходить под все заданные условия. По умолчанию берутся все
статусы, кроме `rejected`, а приватное (`visibility: private`) не попадает, пока не задано
`include_private=True`. Затем отбор замыкается по ссылкам: сущности, о которых атомы, издания
источников, связи с обоими концами в подборке, записи объектов всех источников и пакеты, которым
принадлежат использованные коды. `with_files` добавляет файлы из хранилища объектов, `with_history` —
все ревизии вместо текущей, `with_packs` — копии папок пакетов. Подборка собирается рядом и появляется
под своим именем только целиком.

**Проверка.** `bundle.inspect(path)` возвращает манифест и `ok`, `damaged` (части, которых нет или
чей sha256 не совпал) и `unexpected` (файлы вне манифеста). Zip проверяется до распаковки: имена,
символические ссылки, общий размер, число записей и степень сжатия.

**Импорт.** `bundle.import_(conn, store, folder, agent=…, trust="keep" | "review", dry_run=…)` ничего
не перезаписывает и идёт одной транзакцией:

- записи, которой нет в базе, создаётся с тем же id; её `provenance` говорит, из какой базы она,
  каков хэш исходной ревизии и кто был исходным агентом;
- запись, содержание которой база уже видела (любая локальная ревизия с таким же телом), не
  меняется — повторный импорт той же подборки ничего не делает;
- отличающаяся запись получает новую ревизию `pending` и пункт очереди с причиной `imported`;
  текущая ревизия не меняется;
- запись с другим `key` или `key`, занятый другой записью, — коллизия: импорт отвергается до записи
  (при `dry_run` коллизии перечисляются вместо отказа); локальные `deprecated` и `superseded` записи
  пропускаются с предупреждением.

Пакеты манифеста должны быть загружены с тем же именем, версией и digest; иначе `BundleError` с
`code="bundle_pack_missing"` скажет, что требуется и что есть (и путь, который добавить в
`AMEMO_PACKS`, если пакеты лежат в подборке). Остальные отказы тоже с кодом: `bundle_key_collision`
(и id связи, занятый связью с другим `rel` или концами), `bundle_object_conflict`, `bundle_damaged`,
`bundle_level1` (с отчётом `amem.check/1`). Файл, который уже есть в обеих базах, сопоставляется по digest (страница
сайта и переписка — по адресу или названию), и копия второй раз не хранится. При `trust="keep"`
статус из подборки сохраняется, кроме импорта моделью (не `person:…`): тогда запись, проверенная или
решённая там (`verified`, `auto_verified`, `rejected`, `deprecated`, `superseded`), запись с
`basis: author` и запись, написанная человеком, ждут проверки (`needs_review`, пункт `imported`). При `trust="review"` всё созданное — `needs_review`.
Итоги сверки источников на веру не берутся: они считаются заново по своим копиям файлов, а где файла
нет — `no_file`; атом, место которого так не подтвердилось (`fuzzy`, `not_found`, `no_file`), ждёт
проверки. Связь импорт выводит из оборота, только если это та же связь (тот же id, `rel` и концы);
понятия агентов принимаются только для величин (`property`), по схеме и с единицей UCUM. Объекты с
новыми версиями, путями или файлами принимаются до записи, каждый своей транзакцией (`objects.adopt`):
исключительная блокировка объектов держится только на время одного объекта и его копий, как у
`objects.ingest`; своя сверка идёт без неё, а транзакция записи держит разделяемую, как `submit`, — и
`submit` импорт не ждёт. Если после этого импорт отвергнут, принятое остаётся, как после
`objects.ingest`: объекты с копиями, пункты `source_changed` для новой версии известного объекта, кэш
текста и агент; повторный импорт примет объекты как есть. Повтор той же подборки исключительную
блокировку не берёт — кроме объекта с пропущенной копией (в хранилище нет копии предыдущей версии): он
принимается при каждом повторе, пока копии не придут. `dry_run=True` ничего не пишет и возвращает
план: счётчики по действиям, предупреждения, коллизии и отчёт уровня 1. В ответе `Imported` также
`changeset_id`, `queued` и `complete`.

## Папки, списки и карточка объекта

- **Папки** (`amemo.folders`) раскладывают записи для людей; папка — путь вида `Проекты/Альфа`,
  в ревизию он не входит. Реестр хранит папки (`create`, `delete`, `rename`; у новой базы четыре:
  Проекты, Области, Ресурсы, Архив); `move(conn, ref, folder, agent=...)` переносит атом или сущность
  без новой ревизии и пишет перенос в журнал; `tree(conn)` отдаёт дерево со счётчиками (запись
  в `a/b` учтена и в `a`) и число записей без папки. `lookup.get` показывает `folder` записи.
- **Ссылки** — `atm:` и `ent:` принимают UUID или ключ `key` (`ent:sp20_13330`); старый ключ не находится
  (`records.resolve`, `RecordNotFound`). У базы есть имя: `db.set_base_name` / `db.base_name`.
- **Списки** — `lookup.list_records(conn, folder=, kinds=, statuses=, tag=, about=, limit=, cursor=)`
  отдаёт сводки, новые сверху, по курсору, и `total` по фильтру. `about` — сущность (`ent:...`) или объект
  (`obj:<UUID>` или голый UUID): записи, у чьей текущей ревизии есть на него источник.
  `lookup.labels(conn, refs)` даёт подписи многих ссылок одним запросом.
- **Карточка объекта** — `lookup.object_view(conn, id)`: объект с версиями, `status` (последняя отметка),
  `cited_by` (источники текущих ревизий: запись, версия объекта, селекторы, цитата, итог сверки),
  `pages` (из кэша текста, `None`, если текст не извлекали; чтение сам не извлекает) и `sheets`
  (имена листов xlsx/xlsm, иначе `None`).
- **Окно листа** — `objects.sheet(conn, store, id, n, name, "B2:D10")` возвращает `{name, range, rows}`;
  значения ячеек — как в тексте для сверки. За вызов не больше 10 000 ячеек (считается прямоугольник,
  пустые ячейки тоже); без диапазона — окно `A1:L40`, обрезанное по данным. `ObjectError.code` —
  `not_found`, `invalid` или `too_large`.

## Бэкап

`amemo.backup` нужен клиент PostgreSQL 18 (`pg_dump`, `pg_restore`, `psql`) — в `PATH` или в папке
из `AMEMO_PG_BIN`.

- `create(dsn, folder)` — дамп `pg_dump -Fc` и манифест JSON (SHA-256, `base_id`, миграции, числа
  записей — из того же снимка, что дамп); хранятся последние 14 копий;
- `snapshot(dsn, objects_root, folder)` — полный снимок: дамп и копия хранилища объектов OCFL,
  связанные по `base_id` и SHA-256;
- `restore(source, dsn, objects_root=…)` — только в пустую базу (и пустую папку), всё проверяется
  до записи;
- `verify(source, dsn)` — настоящее пробное восстановление во временную базу и поиск, затем уборка.

Хранилище — PostgreSQL 16+ с pgvector; единственное описание схемы — LinkML
(`amemo/schema/amemo_v1.yaml`), из него генерируются модели Pydantic и JSON Schema.
