## 1. Что делает веб-UI

| Задача человека | Где в UI | Что из библиотеки |
|---|---|---|
| Найти факт, код, формулировку | Поле поиска в верхней строке, страница результатов | `recipes.exact_fact`, `recipes.similar` |
| Прочитать утверждение и убедиться в нём | Страница записи: утверждение рядом с цитатой на странице файла | `lookup.get`, `lookup.revisions_sources`, `objects.text`, файл версии |
| Понять объект: какие параметры известны, чего не хватает | Страница сущности, вкладка «Карточка» | `profile.card` (`amem.card/1`) |
| Увидеть окрестность объекта | Вкладка «Граф» | `recipes.around_entity` |
| Решить спорное | «Проверка»: очередь слева, пункт справа, «Подтвердить» / «Отклонить» | `review.items`, `review.resolve`, `review.enqueue` |
| Узнать, что изменилось | «Изменения» | `recipes.what_changed` |
| Записать своё | «Записать»: заметка человека (сразу `verified`) | `check.submit` от агента `person:` |
| Обменяться веткой знаний, собрать антологию | Меню → «Подборки» | `bundle.export` / `inspect` / `import_` |
| Посмотреть состояние базы | Меню → «База» | `review.stats`, пакеты, `backup.backups` |

## 2. Решения

| Вопрос | Решение |
|---|---|
| Кому UI | Человеку — владельцу или участнику базы. Агентам — нет |
| Поставка | Как в редакции 2: `amem[web]`, статику отдаёт служба по `/ui`. Сборка — отдельный дистрибутив `amem-web` (Python-пакет с готовой статикой), extra `web` его требует (разд. 7.4). CI ядра фронтенд не собирает |
| Фреймворки | React 19 + HeroUI v3 (React Aria Components + Tailwind CSS v4) + TanStack Router и Query, Vite; force-graph и 3d-force-graph; pdf.js (разд. 3) |
| Направление дизайна | Минимализм в духе Apple и Google — обязательство из брифа. Impeccable: режим Operate (с моментами Read на странице записи). Hallmark: экраны приложения (`--scope app`), жанр modern-minimal, палитра Cobalt без её орнамента, системный шрифт (разд. 4) |
| Навигация | Верхняя строка: знак, поиск, «Проверка», «Изменения», «Записать», меню. Боковой панели нет: направлений пять (Hallmark: панель — только от семи) |
| Состояние | Фильтры, вкладки, глубина графа, выбранный пункт — в URL. Тема, язык, черновик заметки — в `localStorage` (с защитой от недоступности) |
| Темы | Светлая и тёмная, по умолчанию — как в системе; выведены из одних токенов, не инверсией |
| Язык | Русский и английский; по умолчанию — язык браузера |
| Связь со службой | HTTP-контракт v1 (разд. 6) — OpenAPI 3.1 в `docs/api/http-v1.openapi.yaml`; типы клиента генерируются из него; моки MSW проверяются по нему |
| Кто пишет | Агент записи определяет служба по сессии (`person:…`); UI агента не передаёт |
| Решение в очереди | Отправляется через 6 с с кнопкой «Отменить» (окно отмены вместо диалога подтверждения) |
| Граф | «Созвездие»: окно ночного неба на странице сущности и записи, не отдельный раздел. 2D по умолчанию, 3D — по переключателю, грузится по требованию. Звёзды — атомы и объекты в цветах семей знания, выбранная звезда подсвечивает соседей, новая запись загорается рядом с тем, о чём она (разд. 4.4) |
| Цвет | Три семьи знания вместо восьми цветов видов: из источников (синий), из работы (оранжевый), объекты (бирюзовый). Палитра проверена валидатором на различимость при дальтонизме в обеих темах (разд. 4.2) |
| Запись человека | Одно поле, Enter. О чём — то, где вы сейчас (объект страницы или выбранная звезда), убирается одним нажатием. Вид выводится из текста и меняется одним нажатием. Записанное сразу `verified` (политика 3c), звезда загорается, 6 с на «Отменить». Три входа: строка «Добавить заметку» в карточке, окно по клавише N поверх любой страницы, заполнение пустого поля карточки на месте (разд. 5.9) |
| Как приложение | Экраны с панелями (небо, проверка, редактор) не прокручивают страницу: высота окна, прокручиваются панели внутри; длинные документы (запись, объект) прокручиваются как страница. Потом это же — в настольной обёртке |
| Оболочка, виджеты, плагины | Веб-UI строится как оболочка и набор виджетов на одной базе дизайна (разд. 7.5): небо, запись, карточка, очередь, редактор, источник — виджеты с объявленным контрактом; плагины добавляют виджеты, команды, маршруты и источники данных. Та же оболочка потом ляжет над ssearch (будущий asearch) и станет хабом разных служб |
| Структура | Папки, как в Obsidian: человек создаёт и вкладывает их сам, записи перетаскиваются; новая база приходит с папками PARA (Проекты, Области, Ресурсы, Архив) как начальной раскладкой. Папка — свойство записи `scope.folder`, связи от неё не зависят (разд. 5.11) |
| Источник | Файл, сайт, переписка — запись-объект со своей страницей: превью (таблицы, PDF, документы, картинки; STEP и DWG — миниатюрой от asearch), путь на диске и «Показать в папке», версии, кто ссылается и куда именно, что не разобрано («Попросить агента»). Виды источников — шаблоны `object`, свои добавляются как у записей (разд. 5.12) |
| Слои | Записи пакета можно показать или убрать слоем; `scope.visibility: private` — личное; **скрытый слой** (записи, которые ведёт агент: код проекта, служебное) человеку не показывается, пока он не включит слой; агент видит всё (разд. 5.12) |
| Плагины | ssearch (будущий asearch) — первый плагин amem: следит за папками и диском, предлагает файлы в источники; в базу попадает не весь диск, а то, что процитировано или помечено человеком, остальное живёт индексом asearch как кандидаты (разд. 7.2) |
| Атом как заметка | Запись — шапка с полями и тело в Markdown, как заметка Obsidian; связи и даты считаются сами. Три представления с переключателем: для человека (отрисованный Markdown), Markdown (правка), для агента (тело `amem.atom/1`, как его видит модель). Разд. 5.4 |
| Правка | Свои заметки человек правит в Markdown или на месте (новая ревизия `person:` сразу `verified`, 3c). Записи моделей и чужие записи в v1 не правятся — только решение в очереди или своя запись рядом |
| Модальные окна | Нет. Запись — отдельная страница, решения — с отменой, командная строка — выпадающий список у поля поиска |

## 3. Фреймворки

### 3.1 Библиотека компонентов: сравнение

| Вариант | Плюсы | Минусы |
|---|---|---|
| **A. HeroUI v3** (выбор) | Построена на React Aria Components (Adobe): клавиатура, фокус, экранные дикторы, интернационализация — лучшие в своём классе. Tailwind v4 и тема на CSS-переменных OKLCH: палитра задаётся токенами, без форка компонентов. Сдержанный вид по умолчанию, близкий к Apple. 73 компонента, включая SearchField, Table, Tabs, Disclosure, Toast, Skeleton, Kbd, Breadcrumbs. Стабильная ветка 3.2.x. Выбор зафиксирован в редакции 2 | Моложе shadcn/ui; командной палитры и виртуального списка нет — берём примитивы React Aria и TanStack Virtual |
| B. shadcn/ui (Radix + Tailwind) | Огромная экосистема; код компонентов копируется в проект | Вид по умолчанию — самый узнаваемый «сгенерированный» вид, против которого написаны оба скила; копии компонентов приходится сопровождать самим |
| C. MUI / Material Web | Готовый язык Google Material 3 | Тяжёлые, со своим рантаймом стилей; выглядят как Material, а не как Apple; спорят с токенами Hallmark |
| D. React Aria Components без обёртки | Полный контроль, та же доступность | Стили всех состояний всех компонентов писать самим — недели работы без выигрыша для пользователя |

HeroUI v3 сочетает доступность уровня React Aria с минималистичным видом и темой на токенах — то, что нужно для «Apple и Google». Паттерны HeroUI v2 (провайдер, framer-motion, плоские свойства) не применять: только составные компоненты v3 (`<Card><Card.Header>…`).

## 4. Дизайн

### 4.1 Направление

Тезис: инструмент исчезает в задаче, а база видна как ночное небо. Человек, привыкший к Почте и Настройкам Apple, Gmail и Диску Google, с первого взгляда знает, где что; выразительность — в точности и в одной подписи, которой amem отличается от всех: **утверждение рядом со своим доказательством, а вокруг — созвездие того, что с ним связано**.

Планка исполнения (Impeccable, «стандарт категории без иронии»): Apple Mail (две панели), Системные настройки и Напоминания Apple (сгруппированные списки, пустая строка — новая запись), Gmail и Google Диск (поиск в центре внимания, плотность списков). Берём уровень отделки, не вид.

Контракт направления (формат Impeccable; переносится в бриф поверхности в части A):

- **THESIS.** Утверждение и его источник на одном экране, их окрестность — звёздами рядом. Отказываемся от вики-страницы, от панели статистики на главной и от серого экрана с одним акцентом.
- **OWN-WORLD.** Светлая бумага с едва заметной прохладой, чернила почти чёрные, панели без рамок, на линиях и мягкой тени; три семьи знания — синий, оранжевый, бирюзовый — на плашках видов и на звёздах; тёмно-синее небо созвездия как одно окно на странице; системный шрифт в двух начертаниях; главное действие — чёрная (в тёмной теме белая) таблетка. В тёмной теме бумага графитовая, небо глубже.
- **POSITION.** Не блокнот, а второй мозг, с которым работает и агент: человеку — простота Obsidian и уверенность в источниках, агенту — проверенные записи и меньше токенов (короткие карточки, скрытые слои, выборки вместо сырых файлов). Конкурировать с Obsidian «в лоб» нельзя; наше — источники с местом в файле, проверка, память для агентов и плагины, которые люди и агенты делают сами и делятся конфигами.
- **STORY.** Человек видит, что ждёт его решения; открывает пункт; читает утверждение и цитату на странице файла; решает одним нажатием; замечает своё — пишет одной строкой, и звезда загорается; идёт дальше.
- **FIRST VIEWPORT.** Верхняя строка 56 px. Страница объекта: слева заголовок, профиль и полоса полноты, затем параметры сгруппированными списками (значение справа, состояние словом и значком); справа окно неба 440 px с созвездием объекта и под ним панель выбранной звезды с «Открыть» и «Заметка». Страница проверки: список пунктов слева, пункт справа с цитатой и небом, решение внизу. Всё видно без прокрутки на 1280×800.
- **FORM.** Жеребьёвка структур Impeccable: выпали «Карточка объекта» (ведущая), «Документ с пометками» и «Почта в три панели»; эскизы v3, v1, v2. Выбор основы — за пользователем (разд. 5.0); seed: `91c0b778c40cf165c7b4909a996a78a2`.
- **FINISH.** unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance.

Выбор Hallmark (экран приложения):

- **Screen** · app screens: карточка объекта, запись с источником, очередь в две панели, окно записи · states: loading, empty, error, full в каждой области
- **Theme** · custom (vibe: «calm apple grouped lists, a night sky of knowledge»); раздача r0 не подошла; материал свой, посадка full-palette (три семьи, проверены валидатором)
- **Chrome** · верхняя строка: знак, поле поиска, «Проверка» со счётчиком, «Изменения», «Записать», тема, меню · без боковой панели; на экране проверки слева — панель фильтров (семьи, объекты), она заработана: там больше семи направлений
- **Signature** · утверждение рядом с подсвеченной цитатой и созвездие рядом с утверждением; новая запись загорается звездой
- **Material** · real: модель данных amem, статусы, причины очереди, профили 3c · pictures: нет, продукт показывает себя сам · absent: снимки экрана, метрики, отзывы, логотип
- **Sweep** · `sloplint --scope app` и `impeccable detect` на четырёх эскизах чисты (FAIL 0, REFLEX 0); после каждой части — заново (разд. 9.3)

### 4.2 Токены

Источник истины — `web/src/styles/theme.css`; переменные HeroUI v3 переопределяются под `:root, [data-theme="light"]` и `[data-theme="dark"]`, режим «как в системе» — через `prefers-color-scheme` при отсутствии явного выбора. Значения — из эскизов (`shared.css` в вариантах); контраст каждой пары проверяется автоматически в обеих темах (разд. 9).

**Иконки.** Один набор (Gravity UI), 16 px в элементах управления; значок всегда рядом с текстом или с названием в подсказке. Без эмодзи.

### 4.3 Правила минимализма (проверяемые)

1. В верхней строке не больше пяти пунктов: поиск, «Проверка», «Изменения», «Записать», меню.
2. Одна заполненная кнопка на экран; остальные — контурные или текстовые.
3. На странице объекта на 1280×800 без прокрутки видны заголовок, полоса полноты, первая группа параметров и созвездие; на странице записи — заголовок, значение, статус и цитата.
4. Технические поля (id, ключ, хэш, пакет изменений, полезность, происхождение) — только под раскрытием «Подробности».
5. Сгруппированные списки вместо карточек; на главной нет карточек статистики; карточка в карточке запрещена.
6. Цвет — у семей знания, действия, выбора и статусов; остальное нейтральное. Статус никогда не передаётся только цветом.
7. Модальных окон нет: окно записи — всплывающее под кнопкой, страница остаётся живой.
8. Пустое состояние — одна строка о том, что здесь будет, и одно действие; пустое поле карточки — само приглашение заполнить.
9. Без градиентов (кроме неба), стекла, иллюстраций и маскотов; метаданные списком «подпись — значение», не строкой через точки.
10. Тексты — глаголами действия: «Подтвердить», «Записать», «Принять»; ошибки — что случилось и что делать.
11. **Сложное за кулисами, но не отнято.** На экране — то, что нужно для чтения и записи; настройки вида, виджетов, шаблонов, службы — за «настроить» и в меню. Всё, что человек может настроить в UI, агент может настроить через MCP (шаблоны — обычный пакет базы).
12. **Горячие клавиши у всего частого** (разд. 5.13); подсказка клавиш — `?`.
13. Это память, не блокнот: у записи всегда видны статус, кто записал и основание; «просто» не значит «без источника».

### 4.4 Созвездие

Окно неба — один компонент (`features/sky`), одинаковый на странице объекта, записи и пункта проверки; отличается только тем, что в центре.

- **Звёзды.** Объекты — крупнее, с тонким кольцом; атомы — точки; размер объекта растёт с числом связей (как в Obsidian). Цвет — семья знания. Ждущее решения — пунктирное кольцо. Выбранная звезда — больше, с кольцом цвета чернил; её соседи и рёбра к ним ярче, остальное приглушено.
- **Подписи.** У объектов всегда, у атомов — у выбранного и его соседей; подпись ищет свободное место (справа, слева, под, над звездой) и не накладывается на другие подписи и звёзды.
- **Наведение** показывает вид и заголовок; **нажатие** выбирает звезду и показывает её в панели под небом («Открыть», «Заметка»); двойное нажатие — созвездие строится от неё (переход).
- **Глубина** 1 · 2 · 3 (как `around_entity`), предел 300 звёзд с честной строкой.
- **Новая запись** появляется рядом с тем, о чём она, укладывается среди соседей (несколько шагов раскладки от текущих позиций, без перестройки всего неба) и вспыхивает один раз.
- **Клавиши.** N — заметка о выбранной звезде; стрелки — по соседям; Enter — открыть. Те же связи доступны списком во вкладке «Связи»: небо — дополнение, не единственный путь.
- **Небо живое.** При открытии звёзды укладываются на глазах (силовая раскладка остывает за секунду-две), звезду можно тянуть, небо — двигать и приближать колесом, двойное нажатие возвращает вид; новая звезда прогревает раскладку вокруг себя. При `prefers-reduced-motion` всё укладывается сразу, движение только от руки пользователя.
- **Реализация.** 2D — canvas (`force-graph`: укладка, перетаскивание, зум из коробки), 3D — `3d-force-graph` по требованию. `cosmos.gl` (WebGL, сотни тысяч узлов) — путь роста, если окрестности станут больше тысяч звёзд; сейчас не нужен и не работает на части iOS без расширений WebGL.

## 5. Экраны

### 5.0 Основа: три структуры и выбор

Эскизы показали три устройства экрана; они не исключают друг друга, это три экрана одного приложения:

- **«Почта в три панели»** (`v2-mail`) — для проверки и просмотра списков: слева фильтры (разделы, семьи, объекты), посередине список, справа запись с цитатой, небом и решением.
- **«Карточка объекта»** (`v3-object`, развитие — `v4-notes`) — страница сущности: параметры по группам профиля, небо объекта справа, запись своего на месте.
- **«Документ с пометками»** (`v1-document`) — страница источника: страница файла в центре, атомы на полях у своих цитат; открывается по «Открыть страницу» из записи.
- **«Небо как вход»** (`v6-sky`) — главная: всё созвездие базы во весь экран, фильтры по семьям, карточка выбранной звезды (разд. 5.2).
- **«Атом как заметка»** (`v5-atom`) — страница записи в трёх представлениях (разд. 5.4).
- **«Источник и папки»** (`v9-source`) — левая панель с папками (сначала PARA), страница источника с превью и путём на диске, стопка виджетов справа со слоями (разд. 5.11, 5.12).
- **«Запись как в Obsidian»** (`v8-note`) — итоговая страница записи: свойства по шаблону, карандаш и исходник, виджеты, конструктор вида (разд. 5.4, 5.9). Заменяет `v5-atom`; `v7-editor` оставлен как антипример перегруженной формы.

Рекомендация: вход — «Небо»; оболочка и проверка — «Почта»; объект — «Карточка»; запись — «Запись как в Obsidian»; источник — «Документ». Пользователь выбирает основу до части A; до выбора спецификация описывает все три.

Все пути — под `/ui/`. В каждой области данных четыре состояния: загрузка (скелет той формы, что придёт), пусто (строка и действие), ошибка (что сломалось и «Повторить»), данные.

### 5.1 Верхняя строка

`amem` (знак, ведёт на главную) · поле «Поиск по базе» с подсказкой `⌘K` / `Ctrl K` · «Проверка» со счётчиком открытых пунктов (обновляется при возврате на вкладку и раз в минуту) · «Изменения» · справа «Записать» (текстовая кнопка со значком «+») и меню (База, Подборки, Настройки, Тема, Язык, кто вошёл). Высота 56 px, линия снизу появляется при прокрутке. Уже 60rem: поле поиска сворачивается в значок, ссылки уходят в меню.

Поле поиска — командная строка: при фокусе (`⌘K`) под ним выпадает список — до 6 записей по запросу (`exact_fact`) и команды («Открыть проверку», «Записать», «Тёмная тема»…); стрелки, Enter, Escape (комбобокс React Aria). Enter без выбора — страница результатов.

### 5.2 Главная `/`: небо как вход (эскиз `v6-sky`)

Главная — всё созвездие базы во весь экран под верхней строкой: объекты крупными звёздами с подписями, записи точками в цветах семей, связи тонкими линиями. Слева сверху — имя базы (или проекта) и строка итога: «29 записей о 8 объектах, 3 ждут решения»; под ней плашки-фильтры «Из источников · Из работы · Объекты · Ждут решения» (несколько сразу; остальное приглушается, не исчезает). Нажатие на звезду — карточка справа (вид, статус, заголовок, одна строка, «Открыть», «Окрестность», «Заметка»); Esc снимает выбор. Наведение — вид и заголовок. Клавиши: `/` — в поиск, `N` — заметка о выбранной звезде. Снизу — легенда и подсказки клавиш. Больше 300 звёзд — показываются объекты и самые связанные записи, строка об этом и совет искать или открыть объект; у большой базы небо входа строится от проекта (`scope.project`).

Та же главная словами: по `⌘K` и в меню — «Все записи» (список), «Ждут решения», «Изменения». Пустая база: небо с одной строкой по центру «В базе пока ничего нет. Агенты пишут в неё через MCP или CLI, а вы можете записать первую заметку» и кнопкой «Записать заметку».

### 5.3 Результаты `/search?q=&kind=&status=&class=`

Строка фильтров: «Вид», «Статус», «Класс» (выпадающие, множественный выбор), справа — число найденного. Если смысловой канал выключен — тихая строка «Поиск по смыслу недоступен: ищем по словам и кодам». Строки: заголовок (ссылка), вид, статус словом и значком, сущность `about`, фрагмент с подсветкой совпадения. Точное совпадение кода — первой строкой с подписью «Точное совпадение кода»; несколько точных — все, без выбора за человека. «Показать ещё» увеличивает лимит до 100. Клавиши: ↑↓, Enter.

### 5.4 Запись `/atom/:ref` (эскиз `v8-note`)

Запись устроена как заметка в Obsidian, и это главный экран продукта: ею должно быть удобно пользоваться, иначе не будут. Сверху вниз:

1. **Строка пути и режимов.** Слева путь по объектам (станция → датчик), справа статус словом, **карандаш** (правка, `⌘E`), **скобки** (исходник), «⋯».
2. **Заголовок** — крупно, в правке редактируется на месте.
3. **Свойства** — как «Properties» в Obsidian: строки «значок типа · имя · значение». Первая строка — **Вид** (плашка семьи; нажатие открывает список по пакетам: «Ядро», пакеты домена, «Мои виды», с поиском и ссылкой «настроить»). Остальные строки задаёт шаблон вида; их типы: **объект** (плашка, подставляется объект страницы), **запись** (плашка-ссылка на другую запись), **число с единицей** (величина из словаря, значение, единица UCUM), **дата** или период, **выбор из словаря**, **теги**, текст. Пустое обязательное — слово «нужно». В правке: «+ Объект», «+ Величина», «+ Тег» в строке и «+ Свойство» внизу (любое свойство: из шаблона или своё; своё уходит в `qualifiers`). В чтении — только заполненные.
4. **Тело** — Markdown, отрисованный по-настоящему (заголовки, списки, цитаты, `**жирный**`, `[[ссылки]]`, формулы KaTeX). Карандаш включает правку в том же месте, с маленькой панелью: **B**, *I*, код, H2, цитата, список, `[[ ]]`, формула (`⌘B`, `⌘I`). Скобки показывают **исходник**: шапку YAML со свойствами и тело текстом, как файл. Тело может быть пустым: «Без текста: запись из одних свойств».
5. **Виджеты** — панели связанных записей под телом, набор задаётся шаблоном вида и меняется на странице («+ Виджет»): **Источники** (связанные записи-источники в своём виде: тип файла, версия, место в файле, цитата или фрагмент таблицы, итог сверки), **Связи** (вид связи → запись, в обе стороны), **Окрестность** (небо), «Таблица значений», «Похожие», «Дочерние объекты». Виджет — тот же компонент, что и на других экранах (разд. 7.2).
6. **Низ** — кто и когда записал, изменено, ревизия, `atm:`.

**Источник — тоже запись.** Файл, сайт или переписка в базе — объект со своей страницей (просмотр файла, версии, кто на него ссылается) и своей звездой семьи «объекты». «+ Источник» в записи — выбрать существующий объект или добавить файл (он становится новой записью-объектом), затем место в нём по виду файла: страница и цитата (PDF), лист и диапазон (таблицы), прямоугольник (чертежи, сканы), раздел и строки (текст). В теле записи-источника — короткий бриф, его свойства — путь, версии, формат; всё это тоже из шаблона `object`, не зашито.

**Представление для агента** — пункт «⋯ → Как видит агент»: тело `amem.atom/1` (YAML для чтения, JSON для копирования). Это отдельный экран, не третий режим: человеку нужны чтение, правка и исходник, как в Obsidian.

**Правила перевода документа в атом** (те же в обе стороны): заголовок — `label`; первый абзац — `summary_plain`; свойства из шаблона — поля атома (`about`, `content.values`, `valid_from`/`valid_to`, `tags`, `basis`), свои свойства — `qualifiers`; ссылки `[[…]]` в теле — связи `see_also` (или `about`, если на объект); цитата в теле под источником — `sources[].quote`, уровень 2 ищет её в файле. Своя запись после правки — новая ревизия `person:`, сразу `verified` (3c); запись модели или чужая — правка недоступна, кнопка карандаша показывает «Поставить на проверку» и «Записать своё рядом».

### 5.5 Сущность `/entity/:ref?tab=card|atoms|history` (эскизы `v3-object`, `v4-notes`)

Две колонки от 1100 px: слева карточка, справа небо (440 px) и панель выбранной звезды; уже — небо под заголовком.

- **Заголовок:** путь по `part_of` (проект → станция → датчик), имя, класс плашкой, профиль словами, **полоса полноты** (известно / ждёт / вопрос / нет) и строка итога: «Известно 2 из 5. Одно ждёт решения, один открытый вопрос, нет обязательного: рабочая температура».
- **Карточка** — сгруппированные списки по группам профиля (`amem.card/1`). Строка: имя параметра, под ним подпись (источник и страница; «Ждёт решения: сомнение модели»; «Где искать: …» из `hint`; «Вы спросили 4 ноября»), справа значение с единицей и статус значком. Состояния: известно; ждёт решения; расходятся («2 значения», значок внимания, панель справа показывает кандидатов с цитатами); не применяется; спросили («Вопрос открыт»); нет данных («Нет данных», обязательное — «Нужно» красным). Унаследованное по `part_of` — «из: Мачта М-2». Умолчание профиля — серым `60 с` с кнопкой «Принять» (разд. 5.9).
- **Группа «Заметки и решения»** — записи человека и агентов из семьи «из работы» о сущности; последняя строка всегда пустая — «Добавить заметку» (разд. 5.9).
- **Небо** (разд. 4.4) с объектом в центре; **панель выбранной звезды**: вид, статус, заголовок, одна строка о записи («Ваша запись без документа: основание, ваше слово» / «Запись с источником: откройте, чтобы увидеть цитату»), «Открыть», «Заметка».
- Вкладки «Атомы» (список `about`) и «История» (`what_changed`) — под карточкой; «Граф» отдельной вкладкой не нужен: небо на странице.

### 5.6 Небо на странице записи и в проверке

На странице записи и в пункте проверки небо — то же окно под утверждением и цитатой, высотой 340 px, с записью в центре и глубиной 2; панель выбранной звезды — та же. Полноэкранный режим — кнопка в углу неба.

### 5.7 Проверка `/review`, `/review/:itemId?reason=&state=`

Две панели от 1100 px: слева список (380 px, виртуальный), справа пункт; уже — список и пункт на разных экранах.

- **Список.** Фильтр «Причина» и «Открытые / Решённые». Строка: заголовок записи, причина словами (смысловая проверка, замечание проверки, высокий риск, сомнение модели, правка, источник изменился, аудит, калибровка, импорт), кто записал, давность.
- **Пункт.** Одна строка о том, что спрошено (по причине). Затем то же утверждение с источником, что на странице записи. Замечания автопроверки списком (значок важности и текст). Для «Правка» — сравнение текущей и предложенной ревизии по полям, изменённые слова подсвечены. Для «Источник изменился» — фрагмент старой и новой версии файла. Для «Сомнение модели» — вердикт модели, уверенность, её заметка.
- **Решение** — полоса внизу правой панели: необязательная заметка, «Отклонить» (контурная), «Подтвердить» (заполненная, главная). Клавиши (по `event.code`, работают и в русской раскладке): `J`/`K` — следующий и предыдущий, `Y` — подтвердить, `N` — отклонить, `S` — пропустить, `/` — к поиску; подсказки в названиях кнопок.
- **После решения** пункт уходит из списка, открывается следующий, внизу слева — «Подтверждено. Отменить» на 6 с; запрос уходит по истечении окна или при уходе со страницы (`fetch` с `keepalive`). Ответ службы «уже решено» — строка «Уже решено: <кто>, <когда>» и переход к следующему.
- **Пусто:** «Очередь пуста. Новые пункты появятся, когда агенты запишут что-то спорное.»

### 5.8 Изменения `/changes?who=&since=`

События по дням («Сегодня», «Вчера», «4 ноября»): время, событие словами (новая запись, новая ревизия, решение проверки, смена статуса, связь), заголовок записи ссылкой, кто. Фильтры: «Все / Люди / Агенты», период.

### 5.9 Запись человека (эскиз `v4-notes`)

Правило: **одно поле, Enter, звезда**. Всё остальное выводится из того, где человек находится, и меняется одним нажатием. Записи человека по политике 3c сразу `verified`, без очереди; уровни 1–2 проверяют схему и, если дана цитата, её наличие в файле.

Три входа, один и тот же пакет (`check.submit` с одной записью, `basis: author`):

1. **Строка «Добавить заметку»** — последняя строка группы «Заметки и решения» на странице объекта (как новая строка в Напоминаниях). Нажали, написали, Enter. `about` — объект страницы.
2. **Окно записи** — по клавише N на любой странице и по кнопке «Записать». Всплывает под кнопкой (520 px), страница остаётся живой; Esc закрывает и хранит черновик в `localStorage`. Сверху — плашка «О чём: <объект страницы или выбранная звезда>» с крестиком; внизу — плашка вида и «Записать». По N с выбранной звездой — запись о ней.
3. **Заполнение пустого поля карточки на месте.** Строка «Нет данных» — само приглашение: нажали — поле ввода с единицей из словаря (`___ °C`), подсказка из профиля («Где искать: паспорт, раздел 3. Спросить: поставщик»), Enter — параметр записан (`basis: author`), строка стала «известно», полоса полноты выросла. Рядом «Не знаю, запишу вопрос» — атом `question` с `value_state: unknown`, строка стала «Вопрос открыт», агенты увидят открытый вопрос. Умолчание профиля — кнопка «Принять»: атом с `basis: default` и `derived_from` на правило.

Что выводится из текста (и меняется одним нажатием на плашку вида): текст заканчивается «?» — вопрос; начинается с «Решили», «Решение», «Принято» — решение; «Имя: число единица» — параметр (семья «из источников»); «Урок», «Оказалось» — урок; иначе — заметка. Первая строка — заголовок, остальное — тело. В тексте `@` подсказывает объекты (меняет `about`), `#` — теги. Источник к записи — по желанию: «+ источник» раскрывает путь к файлу, страницу и цитату; тогда уровень 2 ищет цитату в файле.

После Enter: строка появляется в списке, звезда загорается в небе рядом с объектом, внизу — «Записано: вопрос · Отменить» на 6 с; запрос уходит по истечении окна или при уходе со страницы (`keepalive`), как у решений в очереди. Отказ уровней 1–2 — замечания у поля, ничего не записано.

Дальше запись живёт как любая: находится поиском (семья «из работы», плашка «Заметка»), видна агентам через MCP, стоит в «Изменениях», в карточке объекта и в небе. На своей странице заметка — текст абзацами, «Вы записали 6 ноября, ваше слово», **правится на месте** (нажали на текст — поле, Enter или уход с поля — новая ревизия `person:`, сразу `verified`). Записи моделей и чужие — не правятся (разд. 11).

**Новая запись `/new`** — тот же экран записи (разд. 5.4), открытый в правке: пустой заголовок, «Вид: Заметка», «О чём» подставлено из места (объект страницы или выбранная звезда), тело пустое с подсказкой. Смена вида подставляет свойства шаблона. Окно по `N` — этот же экран в свёрнутом виде: одно поле тела, вид выведен из текста, «Все поля» разворачивает. Эскиз `v7-editor` показывает, как **не надо**: длинный ряд видов плашками, все поля формой, подписи про Markdown и формулы на виду; он оставлен как антипример.

**Конструктор вида** (эскиз `v8-note`, выдвижная панель «настроить» из списка видов). Ничего не зашито: виды и их свойства — это шаблоны пакетов (`Template` с `fields`, 3c), а человек может заводить **свои виды и свойства** в пакете «Мои виды»: имя свойства, тип (объект, запись, текст, число с единицей, дата, выбор из словаря, теги), «нужно», подсказка; тело — желательно, обязательно или не нужно; какие виджеты показывать на странице. Сохранённый вид тут же доступен и агентам (это обычный пакет базы, `AMEM_PACKS`); ядро менять нельзя. Для свойства типа «запись» и «объект» указывается, какие виды и классы оно принимает (как `entity_classes` и `rel` в правилах шаблона). Конструктор — часть D; шаблон, созданный в UI, проходит те же проверки, что пакет из файла.

### 5.10 База `/base`, Подборки `/bundles`, Настройки `/settings` (из меню)

- **База:** записи по статусам (таблица), очередь по причинам (ждут, в работе, медиана решения за 7 дней), итоги сверки источников, пакеты домена (имя, версия, digest; «Мои виды» — среди них), бэкапы (список), `base_id`, версия amem. Только чтение.
- **Подборки:** «Экспорт» — отбор (теги, проект, виды, классы, статусы, с даты), «с файлами», готовый отбор «Антология: проверенное и предпочтительное»; «Собрать подборку» — ссылка на zip и сводка; для антологии — ещё читаемый HTML-отчёт. «Импорт» — выбрать zip → проверка (`inspect`) → пробный импорт (`dry_run`) с отчётом → «Влить в базу».
- **Настройки:** тема (как в системе, светлая, тёмная), язык, кто вошёл, адрес службы, «Выйти» (если вход по токену); за кулисами — шаблоны видов (конструктор, разд. 5.9), виджеты экранов, клавиши.

### 5.11 Папки (эскиз `v9-source`, левая панель)

Левая панель — **папки**, как в Obsidian: человек создаёт их сам («+ Папка»), вкладывает одну в другую и перетаскивает записи между ними. Новая база приходит с четырьмя папками по PARA — **Проекты, Области, Ресурсы, Архив** — это только начальная раскладка, дальше каждый ведёт по-своему (GTD, Zettelkasten, что угодно). Ниже всегда «Все записи» и «Теги».

Папка — свойство записи `scope.folder` (путь через `/`, одна папка у записи; пусто — «Без папки»), а не копия и не ссылка: записи при этом остаются связанными между собой как угодно, папка лишь место на полке. Перенос — перетаскиванием в панели или из меню записи; агент переносит через MCP так же. Объекты-источники по умолчанию лежат в «Ресурсы», новые записи — в папку открытого объекта или в «Без папки». Поле `scope.folder` добавляется в ядро (решение к подпроекту 4; до него UI хранит папки в пакете `ui`).

### 5.12 Источник, слои и плагин asearch (эскиз `v9-source`)

**Страница источника.** Заголовок с типом файла, свойства: вид (шаблон `object`: таблица, документ, чертёж, сайт, переписка; свои виды — через конструктор), путь на диске с «Показать в папке» и «Скопировать», версия с датой, размером и digest, листы или страницы, кто следит (asearch, когда проверен), о чём, теги. **Превью** по формату: таблицы листами с подсветкой цитируемых диапазонов, PDF страницами с подсветкой цитат, документы текстом, картинки; STEP, DWG и прочее — миниатюра и свойства от asearch. **Бриф** — короткое тело, правится карандашом. Виджеты: «Ссылаются на этот файл» (запись и место в файле), «Версии» (у старой версии — сколько записей сверено, пункты пересмотра), «Не разобрано» с кнопкой «Попросить агента» (ставит задачу атомизации, спорное придёт на проверку).

**Слои** (виджет справа): пакеты как слои (Ядро всегда, домены по выбору), «Личное» (`scope.visibility: private`), **скрытый слой** — записи, которые ведёт агент для себя (код проекта как у графа кода, служебные заметки, промежуточные выводы): человеку не показываются в небе, списках и поиске, пока слой не включён; агенту видны всегда. Так человек видит, что «есть проект, в нём пишется код», а подробности остаются агенту. Для скрытого слоя в ядро добавляется значение `visibility: hidden` (решение к подпроекту 4; до него — пакет `agent` как слой).

**asearch как плагин.** Служба слежения за папками и диском (ssearch, будущее имя asearch) подключается к amem плагином: регистрирует источник данных (индекс файлов), виджеты «Файлы рядом» и «Кандидаты в источники», команду «Добавить в базу». В базу попадает не весь диск: источник появляется, когда файл процитирован записью, помечен человеком или нужен агенту для задачи; остальное остаётся в индексе asearch как кандидаты с превью. Удалённый или перемещённый файл asearch находит по digest и обновляет путь; новая версия ставит записи на пересмотр (3b).

## 6. HTTP-контракт v1

Источник истины — `docs/api/http-v1.openapi.yaml` (OpenAPI 3.1), пишется в части A по этой таблице. Подпроект 4 реализует его и отдаёт по `/api/v1/openapi.json`, его тесты сверяют ответы службы со схемой; UI генерирует из файла типы (`npm run api:types`, в CI — проверка, что файл типов свежий) и проверяет по нему фикстуры моков. Изменения контракта — правкой файла в PR, который проходит обе стороны.

Все ответы — JSON, форматы — те, что уже отдаёт библиотека (`exact_fact`, `amem.card/1`, `Submitted`, пункты очереди, `Imported`); служба лишь добавляет к ним поля, нужные экрану (подписи записей). Время — ISO 8601 с поясом. Ссылки на записи — `atm:`/`ent:` с UUID или ключом.

Вход, права и CORS решает подпроект 4; UI присылает `Authorization: Bearer`, только если служба его потребовала.

Каждая папка `features/*` — одна задача человека со своими компонентами, запросами и тестами; соседние фичи общаются только через маршруты и `ui/`. Компоненты HeroUI оборачиваются, только если обёртка добавляет поведение amem (состояния области, статус словами); иначе используются напрямую.

### 7.2 Оболочка, виджеты, плагины

Веб-UI — не набор страниц, а **оболочка с виджетами на одной базе дизайна**, чтобы потом та же оболочка легла над ssearch (будущий asearch) и собирала в один хаб виджеты разных служб.

- **База дизайна** (`web/src/ui`, `styles/`): токены (разд. 4.2), компоненты HeroUI с обёртками amem, состояния областей, плашки семей и статусов, окно неба. Это и есть «библиотека виджетов»; её выделение в пакет `@amem/ui` — когда появится второй потребитель (asearch).
- **Оболочка** (`web/src/app`): верхняя строка, палитра команд, маршруты, темы и язык, сессия службы, реестр виджетов и команд. Экраны — раскладки из слотов (`main`, `side`, `rail`, `bottom`), в слоты ставятся виджеты.
- **Виджет** — модуль с контрактом: `id`, какие данные ему нужны (запросы к контракту v1 по `ref`), какие события он даёт (`select`, `open`, `note`), какие команды регистрирует, свои состояния (loading, empty, error, full). Виджеты v1: `sky` (небо), `record` (запись в трёх представлениях), `source` (страница источника с цитатой), `card` (карточка объекта), `queue` и `review-item` (проверка), `editor` (запись по онтологии), `changes`, `tree` (объекты), `bundles`, `base`.
- **Плагин** — пакет, который при подключении регистрирует в оболочке виджеты, команды палитры, маршруты и **источники данных** (адаптер к контракту другой службы). Ядро amem — первый плагин оболочки; asearch станет вторым: его результаты поиска по файлам встанут в те же слоты и в то же небо. Контракт плагина фиксируется в части A как TypeScript-интерфейсы (`Plugin`, `Widget`, `Command`, `DataSource`); динамическая загрузка чужих плагинов — не в v1, они собираются вместе с оболочкой. **Конфиг** человека — пакеты с его видами, набор видов панели, виджеты экранов, клавиши — экспортируется и импортируется подборкой (3c, `amem.bundle/1` с частью `ui`), чтобы им можно было делиться; агент пишет и читает тот же конфиг через MCP.
- **Как приложение.** Экраны с панелями фиксируют высоту окна: `html, body { overflow: clip }`, прокрутка — у панелей (`overflow: auto` в слотах); страницы-документы (запись, объект) прокручиваются целиком. Это же поведение позже без изменений переносится в настольную обёртку (Tauri или Electron — решение вне подпроекта).

### 7.3 Данные и состояние

- Запросы — фабрики `queryOptions` в `api/queries/` по ресурсам; компоненты не знают путей API. Ошибка ответа — `ApiError` из `problem+json`.
- Параметры поиска маршрутов проверяются схемой (zod) — фильтры, вкладки, глубина графа всегда валидны и переживают перезагрузку и ссылку.
- Решение в очереди — хук `useUndoableDecision`: оптимистично убирает пункт, держит запрос 6 с, отменяет или отправляет; при уходе со страницы — `keepalive`.
- `localStorage` только для удобств одного человека (тема, язык, черновик, токен), каждое чтение и запись — в `try/catch`; без него всё работает.

### 7.4 Перевод

Каталоги `ru.json` и `en.json` с одинаковыми ключами (тест проверяет совпадение); множественные формы — суффиксы i18next (`_one`, `_few`, `_many`, `_other`); даты и «2 ч назад» — `Intl.DateTimeFormat` и `Intl.RelativeTimeFormat`; подписи словарей amem — из `vocab` службы на языке интерфейса. Текст пользователя и записей не переводится.

### 7.5 Поставка

- `npm run build` собирает статику с `base: "/ui/"` в `web/python/amem_web/dist/`.
- Дистрибутив `amem-web` (`web/python/pyproject.toml`, hatchling) содержит только статику и функцию `amem_web.static_dir() -> Path`; версия совпадает с amem. В `amem` добавляется extra `web = ["amem-web==<версия>"]`.
- Служба (подпроект 4) монтирует `/ui`, если `amem_web` установлен: файлы с хэшем в имени — `Cache-Control: immutable`, `index.html` — `no-cache`, неизвестные пути под `/ui/` — `index.html` (маршрутизация на клиенте).
- Разработка: `npm run dev` (прокси `/api` на локальную службу) и `npm run dev:mock` (MSW в браузере, служба не нужна).
- Профиль compose `web` — служба с установленным `amem[web]` (делает подпроект 4).

## 8. Ошибки и пограничные состояния

| Ситуация | Что видит человек |
|---|---|
| Служба недоступна | Область — «Нет связи со службой amem по адресу …» и «Повторить»; верхняя строка работает |
| 401 | Страница входа с полем токена; после входа — возврат туда же |
| 403 / `can_write: false` | «Записать» и решения скрыты; на пункте — «Решать может только участник с правом записи» |
| 404 записи | «Записи atm:… нет. Возможно, ссылка из другой базы» и поиск |
| Запись отклонена или заменена | Статус словами сверху; для `superseded` — ссылка на заменившую |
| Смысловой канал выключен | Строка на странице результатов, поиск по словам работает |
| Пункт решён другим | «Уже решено: …», переход к следующему |
| Отказ проверки при записи | Замечания у полей, сводка сверху, ничего не записано |
| Файл источника недоступен (`no_file`) | В панели источника — итог сверки и цитата текстом, без просмотра |
| Очень длинные значения (заголовок, код, путь) | Перенос по словам, моно-строки — с переносом по символам; нет горизонтальной прокрутки страницы |

## 9. Качество

### 9.1 Доступность

WCAG 2.2 AA в обеих темах: контраст текста 4.5:1, крупного текста, значков и краёв полей 3:1; кольцо фокуса у каждого элемента; полный путь с клавиатуры (поиск, запись, очередь, граф заменяется списками); ориентиры (`header`, `main`, `nav`), один `h1` на странице, уровни заголовков подряд; `aria-live` для «Подтверждено. Отменить» и счётчика очереди; `lang` по языку интерфейса.

### 9.2 Производительность

| Бюджет | Значение |
|---|---|
| JS первой загрузки (gzip) | ≤ 220 КБ |
| CSS (gzip) | ≤ 40 КБ |
| Граф 2D, 3D, pdf.js | отдельные куски, только по требованию |
| Отклик на действие (INP) | < 200 мс |
| Очередь 1000 пунктов | прокрутка без рывков (виртуальный список) |

Бюджеты проверяет `size-limit` в CI.

### 9.3 Тесты и проверки дизайна

- **Компоненты (Vitest + Testing Library + MSW):** четыре состояния каждой области; параметры URL; окно отмены решения (таймеры); подсветка цитаты (поиск цитаты в спанах слоя текста, нормализация пробелов и переносов); совпадение ключей ru/en.
- **Контракт:** фикстуры моков валидны по `http-v1.openapi.yaml` (ajv); `api:types` в CI сверяет сгенерированные типы.
- **E2E (Playwright на моках):** поиск → запись → цитата подсвечена; очередь — подтвердить, отменить, отклонить с клавиатуры; карточка со всеми состояниями полей; граф строится, узел открывает панель; заметка — успех и отказ; подборка — пробный импорт; смена темы и языка. Ширины 375, 768, 1280, 1920.
- **Доступность:** axe на каждом маршруте в обеих темах, без нарушений уровней serious и critical.
- **Снимки:** `toHaveScreenshot` ключевых экранов в обеих темах, только в CI (контейнер Playwright — одни шрифты).
- **Дизайн:** в конце каждой части — `impeccable detect --json` по изменённым файлам и `sloplint.mjs --scope app --url …/ui/<маршрут> --render` по её экранам: FAIL исправляется, REFLEX исправляется или снимается с причиной. Штамп Hallmark — первые строки `web/src/styles/app.css`. Часть G — `/impeccable critique`, `audit`, `polish`, `harden` по каждому экрану, финальный обзор свежим взглядом (агент `impeccable-finish-reviewer`), затем `/impeccable document` пишет `web/DESIGN.md`.

### 9.4 CI

Отдельный workflow `.github/workflows/web.yml`, запускается при изменениях в `web/**` и `docs/api/**`: `npm ci`, Biome, `tsc`, `api:types --check`, Vitest, сборка, `size-limit`, Playwright (Chromium) с отчётом при падении. Рабочий процесс ядра (`ci.yml`, проверка `test`) не меняется. После стабилизации проверка `web` добавляется в набор правил `main` (решение части G).

## 11. Чего не делаем в v1

Динамическая загрузка сторонних плагинов и asearch как плагин — после подпроекта 6 (контракт плагина есть с части A, плагины собираются вместе с оболочкой).

Правка и удаление записей моделей и чужих записей из UI (свои заметки человек правит на месте, разд. 5.9; редактор значений и источников чужих записей — следующая версия); переключение между базами и хаб; управление пользователями и правами; мгновенные уведомления (счётчик опрашивается); работа без сети; Electron и мобильные приложения; телеметрия любого вида; показ очков полезности агентам.

## 12. Риски

| Риск | Что делаем |
|---|---|
| Контракт разойдётся со службой подпроекта 4 | Один файл OpenAPI; обе стороны сверяются с ним в CI; изменения — только через него |
| В HeroUI v3 нет нужного (палитра, виртуальный список) | Примитивы React Aria (на них построена HeroUI) и TanStack Virtual — тот же вид через токены |
| Системные шрифты разные на разных ОС | Шкала и плотность рассчитаны с запасом; снимки-эталоны — только в контейнере CI |
| PDF без слоя текста (скан) | Страница целиком, цитата текстом, честная строка; итог сверки из базы (`fuzzy`, `by_locator`) |
| Рост бандла | `size-limit` в CI; граф и PDF — ленивые куски |
| Большая окрестность в графе | Глубина 1–3 (её ограничивает библиотека), предел 300 узлов |
| Node-инструменты в Python-репозитории | Всё фронтенд-хозяйство — в `web/`, свой CI; ядро не меняется |
| Приватное попадёт в фикстуры или снимки | Нейтральная предметная область образцов — метеостанция (как пакет-пример в тестах); проверка дерева на приватное перед каждым PR, как раньше |
| Чрезмерное «упрощение» спрячет нужное | Правила разд. 4.3 прячут только технические поля и редкие действия; всё, что нужно для решения, — на виду (разд. 4.3, п. 3) |
| Вид записи выведен неверно | Плашка вида видна до Enter и меняется одним нажатием; после — правка на месте |
| Заметки превратятся в свалку без связей | `about` подставляется из места (объект страницы, выбранная звезда); заметка без объекта — личная, видна в поиске и «Изменениях»; семьи и плашки видов держат порядок |
| Три семьи вместо видов обеднят небо | Вид — словом на плашке и в подсказке звезды; семьи различимы при дальтонизме, восемь цветов — нет (валидатор) |

## 13. Связь с подпроектом 4

Подпроект 4 берёт из этой спецификации: таблицу разд. 6 как минимальный HTTP-контракт для UI (свой MCP и CLI он проектирует сам), монтирование `/ui` из `amem_web` (разд. 7.4), коды ошибок и `problem+json`, правило «агент записи — из сессии». Всё, что подпроект 4 решит иначе, меняется правкой `docs/api/http-v1.openapi.yaml` и этой спецификации.
