# amemo — обновления: версия, релизы GitHub, автообновление

**Задача (пользователь, 10.11).** Приложение показывает текущую версию, следит за релизами на GitHub и обновляется само. Автообновление включено по умолчанию, его можно выключить.

## 1. Что есть сейчас

- **Версия.** `amemo.__version__` и `amemo_web.__version__` — одна и та же (`tools/release.py versions` сверяет). Сейчас `0.1.0a1`. Служба отдаёт её в `GET /api/v1/session` (`amemo_version`); веб показывает в «Настройках».
- **Релиз.** Метка `v*` на `main` запускает workflow `release`: сборка веба, sdist и колёса, проверка в чистом окружении, загрузка на PyPI. Релиза на GitHub (GitHub Release) workflow **не создаёт** — следить пока не за чем.
- **Установка** бывает трёх видов:
  - `pipx install "amemo[web]"` — основной путь из README;
  - образ Docker (`Dockerfile`, `docker-compose.yml`);
  - исходники для разработки (`pip install -e`).

## 2. Решения

1. **Источник правды о релизах — GitHub Releases** (`GET https://api.github.com/repos/empty-complete/amemo/releases`), как просил пользователь. Пакет ставится с PyPI той же версии: релиз GitHub создаёт workflow `release` после успешной загрузки на PyPI, поэтому версия из релиза на PyPI уже есть.
2. **Канал** — по текущей версии.
   - Сейчас стоит предварительная (`a`, `b`, `rc`) — служба видит и предварительные релизы.
   - Сейчас стоит стабильная — только стабильные.

   Сравнение — `packaging.version.Version`.
3. **Проверка** — при старте и раз в 6 часов, с `If-None-Match` (ETag). Это укладывается в лимит API без токена: 60 запросов в час с адреса. Без сети или при ошибке API — тихо, следующая попытка по расписанию; в «Настройках» — время и итог последней проверки.
4. **Автообновление — по умолчанию включено.**
   - Выключается настройкой `auto_update = false` (`amemo.toml` или `AMEMO_AUTO_UPDATE`) или переключателем в «Настройках». Переключатель пишет в файл состояния службы `AMEMO_STATE/updates.json`, а не в `amemo.toml`: конфиг пользователя служба не переписывает.
   - Если выключено, служба только сообщает «доступна версия X» и даёт кнопку «Обновить сейчас».
5. **Как ставится** — зависит от вида установки, определяется при старте:

   | Установка | Признак | Обновление |
   |---|---|---|
   | pipx | `sys.prefix` внутри venvs pipx | `pipx install --force "amemo[web]==X"` (именно X, не «последняя») |
   | pip в venv | venv пишется текущим пользователем, пакет не editable | `python -m pip install "amemo[web]==X"` |
   | Docker | `/.dockerenv` или `AMEMO_IN_CONTAINER` | не ставит; «Доступна X — обновите образ» и команда |
   | исходники (editable) | `direct_url.json` с `editable` | не ставит; только сообщает |

6. **Перезапуск — в простое и с проверкой новой версии до него.**
   1. **Установить** новую версию.
   2. **Проверить.** Отдельным процессом новой версии `python -m amemo.service --check`: импорт, миграции в сухую, сборка `/ui` на месте.
      - Не прошла — откат: `==` прежней версии, отметка «обновление до X не встало: …», повтора этой версии нет.
   3. **Сделать бэкап** базы перед миграцией (`backup.create`), если у новой версии есть новые миграции.
   4. **Перезапуститься в простое:** нет запросов 2 минуты и нет открытой записи. `os.execv` того же процесса с теми же аргументами; при старте `db.prepare` применяет миграции.
   5. **В вебе:** при возврате связи веб видит новую версию в `/session` и предлагает перезагрузить страницу.
7. **Общая служба (`AMEMO_TOKENS`).**
   - Обновляется так же, но включать, выключать и «Обновить сейчас» может только токен `person:` с правом записи.
   - Модель и токены только для чтения версию и статус видят, менять не могут.
8. **Безопасность.**
   - Ставится только точная версия с PyPI из релиза нашего репозитория. Адрес репозитория зашит в код, из настроек его не взять.
   - Без токенов и без запуска чужих скриптов: только `pipx` и `pip` той же среды.
   - В журнале службы: что, когда и каким способом ставилось.

## 3. Контракт

- `GET /api/v1/updates` → `UpdateStatus`:
  - `current` — текущая версия;
  - `latest` — версия и адрес релиза или `null`;
  - `channel` — `stable` или `pre`;
  - `install` — `pipx`, `pip`, `docker` или `source`;
  - `auto` — `true` или `false`;
  - `state` — `idle`, `checking`, `available`, `installing`, `ready`, `restarting` или `failed`;
  - `checked_at`;
  - `message` — словами: что произошло, что делать.
- `PUT /api/v1/updates` `{auto}` — только человек.
- `POST /api/v1/updates/check` — проверить сейчас.
- `POST /api/v1/updates/install` — поставить доступную сейчас. При `docker` и `source` — 409 `update_unsupported` с командой словами.

## 4. Веб

- **Настройки → «Версия и обновления».**
  - Текущая версия.
  - Итог последней проверки («Последняя проверка: 10 минут назад, обновлений нет»).
  - «Доступна 0.1.0a2» — ссылка на релиз, кнопка «Обновить сейчас».
  - Переключатель «Обновляться автоматически», по умолчанию включён.
- **Верхняя строка** — значок только в двух случаях:
  - «Обновление установлено — перезапуск, когда служба освободится»;
  - «Обновление не встало».

  В остальное время — ничего: тихо.
- **После перезапуска** — плашка «amemo обновлён до X — перезагрузите страницу», если версия в `/session` отличается от той, с которой открыта страница.

## 5. Части и порядок

| Часть | Что | Кто |
|---|---|---|
| U1 | Workflow `release` создаёт GitHub Release (заметки из коммитов с прошлой метки) после загрузки на PyPI | сессия релизов |
| U2 | `amemo/updates.py`: проверка, канал, вид установки, установка с проверкой и откатом, перезапуск в простое, состояние в `AMEMO_STATE/updates.json`; `amemo update` в CLI; пути `/updates` в контракте и службе; тесты с подставным API GitHub и подставным `pip` | служба (или веб по согласованию) |
| U3 | Веб: «Версия и обновления» в настройках, значок в верхней строке, плашка после перезапуска; моки по контракту; e2e на моках | веб |

Проверки — в CI. Ничего не ставить и не перезапускать на машине разработчика при тестах: установщик и перезапуск подставляются.

## 6. Риски

| Риск | Что делаем |
|---|---|
| Новая версия не запускается | Проверка отдельным процессом до перезапуска, откат на прежнюю `==` |
| Миграция портит базу | Бэкап перед перезапуском, если у новой версии новые миграции |
| Обновление посреди работы | Перезапуск только в простое; запись с окном отмены досылается до перезапуска (`keepalive`) |
| Лимит API GitHub | Раз в 6 часов, ETag, без токена |
| Docker и исходники | Не ставим, только сообщаем — образ и рабочую копию человек обновляет сам |
