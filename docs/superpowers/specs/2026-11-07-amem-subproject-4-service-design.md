# amem — подпроект 4: служба, CLI и память агентов

Редакция 1 (07.11.2026), с правками по ревью спецификации:
- доверие локальной службе (Host, Origin, cookie человека);
- задача (`activity`) для отметки пользы;
- таблица соответствия контракту;
- правки библиотеки вынесены в часть 4.0;
- хук `Stop` отложен;
- хук не пишет запросы пользователя;
- безопасность раздачи файлов и загрузок.

Продолжение спецификации ядра (подпроект 4 «Сервер и память агентов»), библиотечных подпроектов 2–3c и спецификации веб-интерфейса `2026-11-06-amem-subproject-5-web-ui-design.md`. Веб-интерфейс уже описал HTTP-контракт `docs/api/http-v1.openapi.yaml`: служба реализует его, а где решает иначе — меняет файл контракта своим PR по согласию с вебом.

Учтены практики:
- **claude-mem:** хуки на события сессии, поиск в три шага, метка `<private>`, один установщик для разных агентов;
- **Graphify:** установщик по матрице платформ с `--project` и чистым `uninstall`, хук «сначала спроси память», честная неоднозначность, журнал запросов, «ничего не уходит наружу без явной настройки».
- **ECC** (affaan-m/ECC, разбор 08.11): «память — непроверенный контекст, а не исполняемая политика», напоминание перед сжатием контекста вместо хука `Stop`, поиск следов секретов при записи как страховка к `<private>` — разд. 6.6.

## Цель

amem становится программой, которой пользуются, а не только библиотекой. Агенты пишут и читают память через MCP и хуки, человек — через CLI и веб-интерфейс.

Готово, когда:
- служба и CLI ставятся одной командой (`pipx install amem`);
- они работают с Claude Code и Codex CLI;
- веб-интерфейс подключается к настоящей службе вместо моков.

Состав — пять частей, у каждой своя ветка от `main` и свой PR с автослиянием после зелёной проверки `test`:
- **4.0 — библиотека для службы:**
  - папки (миграция 0008);
  - задача сессии для отметки пользы;
  - список записей и подписи;
  - ссылки по ключу;
  - фильтры и `limit` у рецептов;
  - коды ошибок очереди;
  - семья вида;
  - имя базы.
- **4a — служба и HTTP:**
  - настройки и пул соединений;
  - сессия, вход и защита;
  - `problem+json`;
  - все пути контракта v1;
  - `/ui`;
  - тест сверки с контрактом.
- **4b — CLI и MCP:** команды с кодами выхода, инструменты MCP с поиском в три шага, отметка пользы, `<private>`, журнал запросов.
- **4c — память агентов:**
  - хуки Claude Code;
  - установщик по матрице (Claude Code и Codex CLI, `--project`, `uninstall`);
  - навыки ядра, в том числе смысловой проверяющий;
  - образ и профиль compose;
  - документация.
- **4d — запись человека** (пути части D веба, разд. 6a): формы по шаблонам видов, «Мои виды» в базе, поиск и загрузка объектов, задачи агентам.

Не входит:
- установщик с PostgreSQL внутри для Windows и macOS (отдельная задача поставки);
- облачный режим;
- связь с ssearch (подпроект 6);
- задачи из спецификации веба без данных в библиотеке: `visibility: hidden`, папки объектов-источников, настройки UI через MCP. Их делает тот подпроект, который введёт нужные данные. Конструктор видов (пакет «Мои виды») и загрузка файла-источника через веб — часть 4d (разд. 6a);
- хук конца сессии (`Stop`). По протоколу Claude Code вывод хука `Stop` модель не видит, а ответ «продолжай» добавляет лишний ход каждой задаче. Напоминание записать выводы и отметить помогшее даётся в начале сессии и в навыках.

## Решения

| Вопрос | Решение |
|---|---|
| HTTP | Starlette + uvicorn. Контракт OpenAPI — источник истины, его копия лежит в пакете (`amem/service/http-v1.openapi.yaml`, тест сверяет её с `docs/api/`), служба отдаёт её по `/api/v1/openapi.json`. FastAPI построил бы свою схему, которая разошлась бы с файлом |
| MCP | Официальный Python SDK `mcp`. Транспорты: stdio (агент запускает `amem mcp`) и streamable HTTP в службе (`/mcp`) |
| Операции | `amem/api.py` — операции в форме ответов контракта, без Starlette. Их зовут HTTP, MCP и CLI, поэтому три входа не расходятся. `amem/service/` — тонкий слой: маршруты, сессия, ошибки |
| Синхронная библиотека в асинхронной службе | Обработчики Starlette синхронные (пул потоков), соединение — из `psycopg_pool` (autocommit) на запрос. Инструменты MCP зовут операции через `anyio.to_thread` с соединением из того же пула; stdio-сервер держит маленький пул (1–2) с переподключением после `OperationalError` |
| Порт | `127.0.0.1:8767` по умолчанию. Наружу — только явным `--host` |
| Человек и модель | Человеком (`person:`) служба считает только браузер со своей cookie сессии, токен `person:` и CLI в обычном терминале. Остальные клиенты — модель (`model:…`): их записи идут через проверку |
| Папки | Метаданные записи, как статус, а не ревизия: столбец `folder`, журнал `folder_log`, реестр `folder` для пустых папок |
| Отметка пользы | Задача (`activity`) вида `session` на сессию MCP. Выдача и отметка пользы — в одной задаче |
| `<private>` | Вырезается до поиска, журнала и записи на любом входе |
| Журнал запросов | Локальный JSONL явных поисков (MCP, CLI, HTTP); отключается `AMEM_QUERY_LOG=off`. Запросы хука в журнал и в базу не пишутся |
| Хук «сначала amem» | На запрос пользователя — лексический поиск напрямую в базе (без векторов и без записи выдачи) с бюджетом 1,5 с; при превышении бюджета или любой ошибке хук молча пропускает (fails open) |
| Агенты | Claude Code (MCP, хуки, навыки) и Codex CLI (MCP, блок в `AGENTS.md`, навыки) — глобально или в проект; `uninstall` убирает только своё |

## 1. Часть 4.0 — библиотека для службы

Всё, чего не хватает библиотеке, чтобы служба оставалась тонкой. Один PR, тесты на обеих версиях PostgreSQL.

### 1.1. Папки

**Путь.** Сегменты через `/`. Каждый сегмент:
- непустой после обрезки пробелов;
- без `/`, без управляющих символов и знаков форматирования (категория Cf, кроме ZWNJ и ZWJ — U+200C, U+200D), не `.`, не `..` и не `-`;
- в NFC, не длиннее 100 знаков.

Глубина — до 8 сегментов. Регистр сохраняется, сравнение — как есть (`COLLATE "C"`: и префикс идёт по индексу при любой локали базы). Сегмент `-` запрещён в любом месте: путь `-` в контракте означает «без папки», а папку `-/x` нельзя было бы ни показать, ни удалить. У записи одна папка или ни одной (`NULL`).

**Миграция 0008:**
- `atom.folder` и `entity.folder` — `text COLLATE "C" NULL` с CHECK длины и запрета пустого;
- `folder (path PRIMARY KEY, created_at, created_by)` — реестр, в нём живут пустые папки; `path` — `COLLATE "C"`, `created_by` у четырёх папок новой базы — служебный агент `model:amem-init`;
- `folder_log (id, target, record_id, folder_from, folder_to, agent, changed_at)` — журнал переносов, неизменяемый, как `status_log`;
- индекс по `folder`.

**Модуль `amem/folders.py`:**
- `check(path) -> str` — нормализованный путь или `FolderError`;
- `move(conn, ref, folder, *, agent)` — под блокировкой записи меняет столбец, пишет `folder_log`, добавляет путь и его родителей в реестр. Ревизии нет, `content_hash` прежний. Переносить вправе и модель: это порядок, а не утверждение о мире;
- `create(conn, path, *, agent)` — папка в реестре. Если она уже есть — `FolderError` с кодом `exists`;
- `delete(conn, path)` — удаляет только пустую папку без вложенных и без записей, иначе `FolderError` с кодом `not_empty`; несуществующая папка — `not_found`;
- `rename(conn, path, new_path, *, agent)` — переносит папку с вложенными и записями, по строке `folder_log` на запись. Занятый новый путь — `exists`, несуществующая папка — `not_found`, перенос в собственного потомка — `invalid`;
- `tree(conn)` — реестр вместе с путями записей. `count` считается по вложенности: запись в `a/b` учтена и в `a`. Ответ: `folders` с `children` (по имени: без учёта регистра, ё как е, при равенстве — как есть), `unfiled`, `total`.

Префикс в SQL проверяется как `folder = %s OR starts_with(folder, %s || '/')`, без `LIKE`. Четыре папки — «Проекты», «Области», «Ресурсы», «Архив» — создаёт `db.prepare` в той же транзакции, где у базы впервые появляется `base_id`. В уже существующей базе миграция их не добавляет. `recipes.what_changed` получает события `folder` (`from`, `to`). Подборки папку не переносят: это порядок одной базы.

## 2. Настройки и запуск

Порядок источников: явный аргумент → окружение → `amem.toml` (`$AMEM_CONFIG`, затем `~/.config/amem/amem.toml`). Ключи `amem.toml` — имена настроек без `AMEM_` строчными (`dsn`, `data`, …, `ui_origins` и `allowed_hosts` — списки, `query_log`, `state_quota`); неизвестный ключ — ошибка, а не тихо пропущенная опечатка. Относительный путь в `amem.toml` считается от папки файла. При запуске служба выполняет `db.prepare` (миграции, словари, `base_id`).

| Настройка | Окружение | По умолчанию |
|---|---|---|
| База | `AMEM_DSN` | — (обязательна) |
| Хранилище копий | `AMEM_DATA` | `~/.local/share/amem/objects` |
| Папка документов | `AMEM_DOCS` | — без неё источник с `path` получает замечание `source_unresolved` («папка документов не настроена») |
| Состояние службы (загрузки, подборки, журнал) | `AMEM_STATE` | `~/.local/state/amem` |
| Каталог бэкапов | `AMEM_BACKUPS` | `AMEM_STATE/backups` |
| Адрес службы | `AMEM_HOST`, `AMEM_PORT` | `127.0.0.1`, `8767`. `AMEM_HOST` — IPv4, IPv6 (в скобках или без) или имя хоста, без порта и схемы; иное — ошибка настройки |
| Человек локальной службы | `AMEM_AGENT` | `person:` + имя пользователя ОС, приведённое к шаблону агента |
| Модель для клиентов без cookie и токена | `AMEM_MODEL_AGENT` | `model:local` |
| Разрешённые источники интерфейса (dev-сервер веба) | `AMEM_UI_ORIGINS` | — пусто |
| Имена службы в `Host` сверх локальных и адреса привязки | `AMEM_ALLOWED_HOSTS` | — пусто; список имён или адресов без порта (порт в `Host` любой). Нужен при `--host 0.0.0.0`: адрес «на всех интерфейсах» — не имя, и без списка служба отвечает только на `127.0.0.1`, `localhost`, `[::1]`. В compose — имя службы: `AMEM_ALLOWED_HOSTS=amem` принимает `Host: amem:8767` |
| Токены общей службы | `AMEM_TOKENS` | — файл; если задан, без токена — 401 |
| Журнал запросов | `AMEM_QUERY_LOG` | `AMEM_STATE/queries.jsonl`; `off` — выключен |
| Предел места подборок и загрузок одного владельца | `AMEM_STATE_QUOTA` | `10G` (10 ГиБ); целое число байт или с единицей `K`, `M`, `G`, `T` (двоичные) |

`amem init` подготавливает базу (`db.prepare`) и хранилище. `amem serve` запускает службу; до CLI (часть 4b) — `python -m amem.service [--host H] [--port P] [--no-auth]`, обе зовут `amem.service.serve(settings, no_auth=…)` (uvicorn).
- **Проверка открытости перед запуском.** Адрес не loopback (`0.0.0.0`, адрес сети, имя, кроме `localhost`) без `AMEM_TOKENS` и без `--no-auth` — отказ с объяснением, код 2: локальная служба считает любой запрос без cookie моделью с правом записи, и в сети это запись для всех. `--no-auth` снимает отказ (закрытая сеть, compose) и печатает громкое предупреждение; с `AMEM_TOKENS` `--no-auth` ничего не меняет. Неверная настройка (адрес с портом, нет `AMEM_DSN`) — тоже код 2.
- **Таймауты.** Тело записи и загрузки: следующий кусок служба ждёт не дольше 30 с, JSON-тело целиком — не дольше 120 с (загрузку подборки — только 30 с тишины: большой файл законно идёт долго); дальше — 408 `body_timeout` с `Connection: close`. Тяжёлые чтения — `/graph` (обзор неба и окрестность) — идут в транзакции с `SET LOCAL statement_timeout = 15 s`: превышение база обрывает сама, ответ — 503 `timeout`, соединение возвращается в пул без следа настройки. Значения — константы службы (`BODY_IDLE`, `BODY_TOTAL`, `HEAVY_TIMEOUT_MS` в `amem/service/http_v1.py`); настройками станут, когда понадобится. Готовый PostgreSQL с pgvector пользователь поднимает сам или через `docker compose` из репозитория. Своя установка PostgreSQL в amem не входит.

## 3. Служба и HTTP v1

### 3.1. Кто пишет: сессия и защита

**Защита запросов** — для каждого запроса, в любом режиме:
- `Host` — один из разрешённых: `127.0.0.1`, `localhost`, `[::1]`, адрес из `--host` и имена `AMEM_ALLOWED_HOSTS` (порт в `Host` любой). Чужой `Host` (DNS rebinding) — 421;
- `Origin`, если пришёл, — тот же источник, что и служба, или один из `AMEM_UI_ORIGINS`. Чужой — 403. Запасная проверка: запрос без `Origin`, но с `Sec-Fetch-Site: cross-site` или `same-site` — тоже 403, у любой записи и у любого `/api/v1/…`, кроме `/health` (иначе `<img>` с чужой страницы писал бы поиски в журнал выдачи и засорял полезность);
- запись (`POST`, `PUT`, `PATCH`, `DELETE`) с телом принимает только `application/json`. Запись без тела (`DELETE /folders/{path}`) проверять нечего: межсайтовый запрос из браузера всё равно несёт `Origin` и упирается в проверку выше. Исключение — `/bundles/inspect` (multipart), для него `Origin` обязателен;
- у `/mcp` — те же проверки через `Guard` службы (он стоит перед менеджером сессий SDK, имена сравнивает без учёта регистра). Своя защита SDK (`TransportSecuritySettings`, DNS rebinding) выключена: вторая проверка с другими правилами только расходилась бы с первой.

**Локальная служба** (без `AMEM_TOKENS`):
- **Браузер.** Интерфейс получает cookie `amem_session`: `HttpOnly`, `SameSite=Strict`, `Path=/`, случайная на каждый запуск службы. Её выдаёт `/ui/index.html` и `GET /api/v1/session`, если запрос пришёл со своей страницы (`Sec-Fetch-Site: same-origin`) или с разрешённого источника `AMEM_UI_ORIGINS`. По умолчанию список пуст; при разработке там dev-сервер веба, например `http://127.0.0.1:5173`. Запрос с cookie — человек `AMEM_AGENT`, `can_write: true`; запрос, которому cookie выдаётся, — тоже: интерфейс узнаёт о человеке из первого же ответа `/session`. Межсайтовые запросы браузер отправляет без такой cookie, поэтому подделать запрос с чужой страницы нельзя.
- **Прочие клиенты** — запрос без cookie (`curl`, скрипт, агент). Это модель `AMEM_MODEL_AGENT`, `can_write: true`: всё записанное идёт через проверку.
- **`/mcp`** — всегда модель. Агента задаёт заголовок `X-Amem-Agent: model:<имя>`, который пишет установщик; иначе `AMEM_MODEL_AGENT`. Значение не `model:` отвергается.

**Общая служба** (`AMEM_TOKENS`):
- файл `amem-tokens.toml` с правами 0600 хранит строки `[[token]] hash = "sha256:…", agent = "person:anna" | "model:…", write = true` (без `write` — только чтение). Файл, в который могут писать другие пользователи, и файл чужого владельца (не пользователь службы и не root) служба не принимает: туда можно вписать свой токен; читаемый другими — предупреждение. Права и владелец проверяются по уже открытому файлу (`fstat`);
- токен — 32 случайных байта, его выдаёт `amem token create --agent … [--read-only]` и показывает один раз;
- без токена — 401; токен без права записи — 403 на запись; cookie браузера в этом режиме не выдаётся. `/health` и статика интерфейса (`/`, `/ui`, `/ui/…`) отвечают без входа; API — по токену. Токен только для чтения может `POST /bundles/export`, `/bundles/inspect` и пробный `/bundles/import` (`dry_run: true`); настоящий импорт — 403 `read_only`.

**`GET /session`** отвечает: агент, `base`, `base_name`, `amem_version`, `semantic` (есть ли активная модель и провайдер), `can_write`.

**Остаточный риск.** Процесс под учётной записью пользователя (в том числе агент с доступом к shell) видит DSN базы и может писать в неё напрямую или нарочно получить cookie человека, подделав заголовки браузера. Cookie отличает человека от случайной записи модели, а не от злонамеренного локального процесса. Служба этого не меняет. CLI помечает такие записи моделью, если узнаёт окружение агента (разд. 5).

Права решения в очереди проверяет библиотека: человек решает всё, модель — только `semantic`. Пункт вручную (`enqueue`) ставит только человек. Структуру папок (создать, удалить, переименовать) меняет только человек — у модели 403 `forbidden`; переносить запись в папку вправе и модель (разд. 1.1). Тело записи (JSON) — до 1 МиБ: служба читает его потоком и обрывает на пределе (413 `too_large`), не доверяя `Content-Length`, — `<private>` и проверки идут по всему тексту.

Параметры запроса `amem/api.py` разбирает одинаково для HTTP, MCP и CLI: пустой список фильтра (`kind`, `status`, `entity_class`, `rels`, в строке запроса — и `?status=`) — «без фильтра», как отсутствующий параметр; пустой `range` листа — окно по умолчанию библиотеки; пределы и перечисления — по контракту, до вызова библиотеки (400 `bad_request`).

Тест сверки:
- ответ каждого пути контракта проверяется по схеме ответа из файла контракта (jsonschema, OpenAPI 3.1 = JSON Schema 2020-12) строго: у схем со списком `properties` лишние поля запрещены (кроме `Problem` — расширения RFC 9457), открытые объекты без `properties` (`payload`, `details`, `summary`, `channels`) остаются открытыми;
- отдельный тест (`tests/test_service_contract.py`) проверяет, что все пути и методы контракта реализованы маршрутами и что служба не отвечает на пути вне контракта. Исключения — `/api/v1/openapi.json`, `/health`, `/mcp` (часть 4b), `/`, `/ui`, `/ui/…`. Пути части D веба (`/templates`, `/packs/mine/templates/{code}`, `GET`/`POST /objects`, `/tasks`) — в списке «будет в 4d» того же теста; тест следит, чтобы сделанный путь из списка убрали.

### 3.4. Файлы, загрузки и `/ui`

- **Файл версии** (`/objects/{id}/versions/{n}/content`) — копия из хранилища с поддержкой `Range` (206).
  - Типы из белого списка (`application/pdf`, `image/png`, `image/jpeg`, `image/gif`, `image/webp`, `text/plain`) отдаются как есть, остальные — `application/octet-stream` с `Content-Disposition: attachment`.
  - Всегда `X-Content-Type-Options: nosniff` и `Content-Security-Policy: sandbox`.
- **Отчёт антологии** (`/bundles/{id}/report`) — HTML с `Content-Disposition: inline` (открывается в новой вкладке), `Content-Security-Policy: sandbox; default-src 'none'; style-src 'unsafe-inline'; img-src data:` (без `allow-scripts` — документ без своего источника) и `nosniff`. Zip подборки (`/download`) — `attachment` с безопасным именем (заголовок антологии без опасных знаков, иначе `amem-<id>.zip`; не ASCII — `filename*`).
- **Подборки и загрузки.**
  - Id — UUIDv7, по ним ищутся только файлы в своих папках `AMEM_STATE/bundles/<id>/` и `AMEM_STATE/uploads/<id>/`; `meta.json` (владелец, время, имя файла) пишется последним — недописанная папка не видна.
  - Подборка и загрузка принадлежат тому, кто их сделал: токену в общей службе, агенту запроса в локальной. Чужая — 404, как несуществующая.
  - Срок хранения — 24 часа. Старше — удаляется при запуске службы и раз в час (фоновая задача lifespan); обращение к просроченной удаляет её сразу и отвечает 404.
  - Размер загрузки (`/bundles/inspect`) считается потоково при записи на диск. Предел — 4 ГиБ (`bundle.MAX_UNPACKED`), иначе 413.
  - Предел места — `AMEM_STATE_QUOTA` (10 ГиБ) на владельца: его живые подборки и загрузки (`bundles/` и `uploads/`, распакованные) вместе (`api.state_usage`). Экспорт, после которого занятое превысило бы предел, удаляется; загрузка обрывается, как только файл перерос остаток, а распакованная сверх остатка — удаляется; ответ — 507 `quota_exceeded` с занятым и пределом. Одновременные запросы одного владельца могут ненадолго перешагнуть предел — он защищает диск от накопления, а не от гонки.
- **Экспорт и импорт подборок** идут синхронно в запросе. Долгая подборка держит запрос, а интерфейс показывает ожидание. Фоновые задачи — когда понадобятся.
- **Антология.** `anthology: true` зовёт `amem.anthology.export` (часть F веба); `title` — заголовок отчёта; `with_packs` у антологии — 400. Отказ (`BundleError`, например пустая антология) — 422.
- **Импорт** — `dry_run` по умолчанию `true`; настоящий импорт (`dry_run: false`) — только человек, у модели 403 `forbidden`.
- **`/ui`.** Если установлен пакет `amem_web`, служба монтирует `amem_web.static_dir()` через `StaticFiles` (без перехода по симлинкам, только внутри папки):
  - файлы сборки с хэшем в имени — `Cache-Control: immutable`: под `assets/`, имя как у vite (`имя-хэш.расш`, хэш 8+ знаков base64url или hex, не одни строчные буквы) и, если в сборке есть манифест vite (`.vite/manifest.json`, `build.manifest: true`), — только файлы из него; прочие — `no-cache`;
  - сегменты пути с точкой в начале (`.vite/…`) — 404;
  - `index.html` — `no-cache` и выдача cookie сессии;
  - неизвестные пути под `/ui/` — `index.html`;
  - без пакета `/ui` отвечает 404 с подсказкой `pip install amem[web]`;
  - `/` ведёт на `/ui`, если веб есть.

| `amem_vocab(scheme)` | Коды словаря с подписями |

**Задача сессии.** Сервер MCP при старте сессии (stdio — процесс, `/mcp` — сессия SDK) получает задачу `usefulness.session_activity(conn, "mcp:<id>")`. Её передают все поиски и отметки этой сессии. `amem_helpful` отмечает только атомы выдачи этой же сессии.

**Сессия `/mcp` и вход.** Сессия SDK привязана к входу (токен или локальная служба) и агенту, которые её открыли: служба кладёт их в `scope["user"]` (`AuthenticatedUser`), SDK запоминает его на `initialize` и любому другому входу с тем же `Mcp-Session-Id` (`tools/call`, `tools/list`, `DELETE`) отвечает 404, как будто сессии нет.

**Клиенты без сессии** (протокол 2026-07-28 и новее не открывают сессий). Их задача — на вход и агента; она режется по простою: после 30 минут тишины следующий вызов получает новую метку `mcp:http:<вход и агент>:<UUIDv7>`. `amem_helpful` такого клиента сверяет не задачу, а саму выдачу: её агент и вход (по метке её задачи) должны совпасть с вызывающим — `retrieval_id` служит доказательством, поэтому отметка проходит и после разреза задачи, и после перезапуска службы, а пишется в задачу выдачи.

**Чужая выдача.** `amem_helpful` с выдачей другой сессии, другого агента или входа — 403 `forbidden`; нет такой выдачи или атом не из неё — 400 `bad_request`.

**Неоднозначность.** Поиск без явного лидера отдаёт кандидатов с `ambiguous: true`, а не первый попавшийся (практика Graphify). Неизвестная ссылка — ошибка с подсказкой найти запись через `amem_search`.

## 6. Память агентов

### 6.1. Хуки Claude Code

`amem hook <event>` читает JSON события со stdin и пишет ответ по протоколу хуков Claude Code: `hookSpecificOutput.additionalContext`. Хук идёт в базу напрямую коротким соединением (`AMEM_DSN`), без службы. Векторный канал не используется, выдача не записывается (`log=False`), журнал запросов не пишется.

| Событие | Что делает |
|---|---|
| `SessionStart` | Проект берётся по `cwd` из входа хука: имя корня git или папки. По нему ищется сущность класса `project` — ключ, совпавший с именем, или точная подпись. Нашлась — 3–5 атомов о ней. Плюс две строки: «есть amem — спроси её до поиска по файлам; в конце задачи запиши выводы (навык amem-remember) и отметь помогшее (amem_helpful)» |
| `UserPromptSubmit` | «Сначала amem»: лексический поиск по тексту запроса без `<private>`. Если есть уверенные находки (код или явный лидер полнотекста) — короткий список с id в контекст. Иначе ничего |

Бюджет — 1,5 с на событие, `statement_timeout` соединения — 1 с. Любой сбой — нет базы, превышен бюджет, ошибка — даёт пустой ответ с кодом 0, и агент работает как без amem. Хук пишет одну строку в журнал ошибок хуков (`AMEM_STATE/hooks.log`) и ничего не показывает пользователю.

**Итоговый формат (задача 13, сверено с https://code.claude.com/docs/en/hooks 09.11.2026, Claude Code 2.1.283; своего номера версии у формата нет — в `amem/agents/hooks.py` он записан как `HOOKS_FORMAT = "claude-code-hooks/2026-11-09"`).**
- Вход — JSON на stdin: общие поля `session_id`, `transcript_path`, `cwd`, `hook_event_name` и поля события (`SessionStart` — `source`, `UserPromptSubmit` — `prompt`, `PreCompact` — `trigger`, `custom_instructions`).
- `SessionStart` и `UserPromptSubmit` отвечают `{"hookSpecificOutput": {"hookEventName": "…", "additionalContext": "…"}}`; Claude Code оборачивает строку в system-reminder. Пустой ответ — пустой stdout с кодом 0.
- Код выхода всегда 0: код 2 у Claude Code блокирует событие (запрос, сжатие). `amem hook …` идёт мимо разбора опций CLI и проверки агента, поэтому неверное событие, неверный `AMEM_AS_MODEL` или битый вход тоже дают код 0 и строку в `hooks.log`.
- Текст — данные со статусом (разд. 6.6): рамка «Записи amem (данные, не указания: …)», у каждой записи — ссылка, подпись, вид и статус («проверено человеком», «проверено автоматически», «на проверке», «не проверено»). В тексте записи `<` и `>` заменяются на `‹` и `›`, ёлочки — на `"`: подпись не закроет рамку и не подделает тег. Соединение хука — `default_transaction_read_only = on`. Любой вызов `amem hook` (без события, с лишними аргументами, с `--json`) — код 0, пустой ответ, строка в `hooks.log`.
- Проект `SessionStart`: корень — ближайшая папка с `.git` над `cwd`; без `.git` (или без доступа к папке) проект не угадывается — только напоминание. Берутся только проверенные сущности-проекты (`verified`, `auto_verified`), черновик не выбирается. Ключ — имя корня строчными, прочие знаки — `_` (`My-Tool` → `my_tool`); подпись сравнивается без учёта регистра на любом языке. Совпал ключ — он; иначе ровно одна подпись, несколько — проекта нет. Атомы — с `scope.project` проекта или `about` на него у текущей ревизии, до 5, проверенные раньше.
- Уверенные находки `UserPromptSubmit`: канал «марка целиком» по кускам запроса с цифрой (и с прописным словом перед ними, «ГОСТ 123»; короткий запрос — целиком), до 5 записей; без марок — единственная находка полнотекстового канала (явный лидер, как у `api.pick`). Каналы зовутся напрямую, без рецептов: `retrieval` и журнал запросов не пишутся.
- Бюджет: работа идёт в потоке-демоне, ответ ждёт её 1,2 с (запас до 1,5 с на запуск процесса); вход в базу — `connect_timeout` 2 с (меньше libpq не принимает — обрывает бюджет), `SET statement_timeout = 1000`.
- **`PreCompact` — принят.** По документации stdout `PreCompact` при коде 0 становится указаниями к сводке сжатия (держать короче 10 000 знаков на хук: длиннее Claude Code обрезает по пределу и ставит метку, в файл не уносит; `additionalContext` у события нет). `amem hook PreCompact` печатает простым текстом строку: «отдельным пунктом сводки перечисли выводы этой сессии, которые стоит записать в amem (навык amem-remember, amem_submit), и записи amem, которые помогли (ссылки для amem_helpful)». База не нужна; без `AMEM_DSN` ответ пустой. Установщик (задача 14) регистрирует три события.

### 6.2. Установщик

`amem install claude-code` и `amem install codex` — глобально или с `--project DIR`. Матрица платформ — один модуль `amem/agents/platforms.py` с версией формата.

| Платформа | MCP | Хуки | Навыки и инструкции |
|---|---|---|---|
| Claude Code, глобально | `claude mcp add --scope user amem -- amem mcp --agent model:claude-code`, если команда `claude` есть; иначе — правка `~/.claude.json` с предупреждением, что Claude Code может переписать файл при работе | `hooks` в `~/.claude/settings.json`: три события (SessionStart, UserPromptSubmit, PreCompact) → `AMEM_AS_MODEL=claude-code amem hook …`, timeout 5 с | `~/.claude/skills/amem-*/SKILL.md` |
| Claude Code, `--project` | `.mcp.json` проекта | `.claude/settings.json` проекта | `.claude/skills/` |
| Codex CLI, глобально | таблица `[mcp_servers.amem]` в `$CODEX_HOME/config.toml` (`~/.codex`), `env = { AMEM_AS_MODEL = "codex" }` | `$CODEX_HOME/hooks.json` (формат Claude Code): SessionStart и UserPromptSubmit; PreCompact у Codex stdout в сжатие не отдаёт — не ставится | блок в `$CODEX_HOME/AGENTS.md`; навыки — `~/.agents/skills/` |
| Codex CLI, `--project` | `.codex/config.toml` проекта — Codex читает его только у доверенного проекта (предупреждение) | `.codex/hooks.json` проекта | блок в `AGENTS.md` проекта; навыки — `.agents/skills/` |

Форматы сверены 09.11.2026 (`CLAUDE_FORMAT = "claude-code/2026-11-09"`, `CODEX_FORMAT = "codex-cli/2026-11-09"`, Codex rust-v0.165.0), источники — в `amem/agents/platforms.py`. Сервер MCP и хуки обоих агентов получают `AMEM_AS_MODEL` (`claude-code` / `codex`): иначе модель в обычном терминале писала бы от имени человека. Команда amem глобально — полный путь из `PATH`, без неё — текущий интерпретатор с `-m amem.cli` (объявляется); в файлах проекта — голая `amem` (путь машины не попадает в репозиторий, amem нужен в `PATH` агента). Codex получает `env_vars = ["AMEM_DSN", "AMEM_CONFIG", "AMEM_STATE", "PGPASSFILE", "PGSERVICE"]` — секреты в `config.toml` не пишутся. Файл с BOM не правится; блоки TOML и Markdown — с концами строк файла; стёртая метка конца — отказ установки и предупреждение удаления; упавший `claude mcp add` после `remove` возвращает прежнюю запись.

Правила:
- **Пометки.** Установщик правит только своё:
  - в JSON — ключи `amem`, а в списках хуков — элементы с командой `amem hook`;
  - в TOML — таблицу `mcp_servers.amem` текстовым блоком между `# amem:begin` и `# amem:end`, без библиотеки записи TOML;
  - в Markdown — блок между `<!-- amem:begin -->` и `<!-- amem:end -->`.
- **Резервная копия.** Перед первой правкой файл копируется рядом с суффиксом `.amem-backup`.
- **Чистое удаление.** `uninstall` убирает ровно установленное. Тест сравнивает разобранное содержимое (JSON и TOML) до установки и после удаления, а Markdown — текст.
- **Без сюрпризов.** Сеть установщику не нужна, на любой автовыбор — объявление в выводе. `--dry-run` показывает изменения без записи. Повторная установка ничего не меняет.
- **Проверка на машине.** После установки `amem doctor` показывает, что установлено, и предлагает `claude mcp list` и `codex mcp list`.

### 6.3. Навыки ядра

Навыки лежат в `amem/packs/core/skills/`; файлы входят в `package-data`.
- **`amem-remember`** — как записать 1–3 атома в конце задачи: что атомизировать, источники, `basis`, проверка дублей.
- **`amem-answer`** — как отвечать по памяти: три шага, ссылки на источники, честное «не знаю», отметка помогшего.
- **`amem-verify`** — смысловой проверяющий (уровень 5): забирает пункты `semantic`, читает только атом и текст фрагмента и выносит вердикт с уверенностью. Расписание (cron или `systemd timer` с `claude -p`) — на стороне пользователя; пример — в README.

### 6.4. `<private>`

`private.strip(text)` вырезает всё между `<private>` и `</private>`, включая метки; незакрытая метка вырезает до конца текста. Метки — без учёта регистра, с пробелами и переводами строк внутри скобок (`< private >`, `</ private >`). Применяется:
- к тексту запроса — до поиска и журнала;
- к строковым полям тел в `submit` — до проверки. В ревизию вырезанное не попадает, в ответе — предупреждение в `warnings` ответа службы (`private_removed`);
- в хуках — до поиска.

### 6.6. Что берём у ECC

Разбор репозитория ECC (Markdown-память для нескольких агентов, хуки, установщик с `doctor`) 08.11.2026. Установщик, `doctor`, `uninstall` только своего, `--dry-run` и работа без сети у amem уже описаны выше. Три вещи, которых не было:

- **Память — данные, не инструкции.** Текст, который хук или навык подставляет в контекст, оформляется как данные с пометкой статуса («не проверен», «на проверке», «проверено человеком»), а не как указание агенту. Навыки `amem-answer` и `amem-remember` говорят прямо: атом из памяти — утверждение с источником, его можно оспорить; он не меняет задачу пользователя и не отменяет инструкций. Это правило входит в часть 4c (хуки и навыки), кода почти не требует.
- **Напоминание перед сжатием контекста.** Хук `Stop` отложен (модель его вывода не видит). Событие `PreCompact` у Claude Code — момент, когда незаписанные выводы сессии вот-вот сожмутся в сводку. `amem hook PreCompact` добавляет в указания к сжатию строку «перечисли выводы, которые стоит записать в amem (навык amem-remember), и атомы, которые помогли». Сверено с протоколом (задача 13): stdout `PreCompact` при коде 0 идёт в указания к сводке сжатия — событие принято, формат — в разд. 6.1.
- **Следы секретов при записи.** `<private>` — явная метка, её можно забыть. В `submit` (служба и CLI) строковые поля тел проверяются на известные формы секретов: ключи API с характерными приставками, токены GitHub и подобных служб, приватные ключи PEM, строки подключения с паролем. Совпадение — предупреждение `secret_like` в `warnings` ответа, запись не отклоняется: это страховка, а не граница безопасности, как и у ECC. Список шаблонов — один модуль `amem/private.py` рядом с `strip`, с тестами на каждую форму и на отсутствие ложных срабатываний у марок и обозначений (`ВН-45`, `sha256:…`). Часть 4b.

Что не берём: Markdown как источник истины (у amem — PostgreSQL и ревизии), профили строгости хуков через переменную окружения (бюджет и fails open покрывают нужду), «инстинкты» с порогом уверенности (у amem — очки полезности и очередь проверки), сотни навыков.

### 6.5. Журнал запросов

Одна строка JSONL на явный поиск: время, рецепт, текст запроса после `<private>`, `base_id`, агент, число находок, длительность в мс, `retrieval_id`. Ответы не пишутся. `AMEM_QUERY_LOG=off` выключает журнал. Файл не поворачивается и растёт без ротации — его объём ограничен числом явных поисков (сотни байт на поиск: тысяча поисков в день — около 100 МБ в год); перенести или удалить файл можно в любой момент, следующий поиск начнёт новый. Ротация — когда понадобится. Права файла — 0600, и у файла, созданного раньше с правами шире (служба поправит их по открытому дескриптору). Журнал — сигнал пользы для будущей настройки ранжирования; служба его не читает.

## 6a. Часть 4d — формы, свои виды, загрузка, задачи агентам

Пути части D веба (план веба — PR #21, моки — `web/src/mocks/handlers-d.ts`): `GET /templates`, `PUT`/`DELETE /packs/mine/templates/{code}`, `GET`/`POST /objects`, `GET`/`POST /tasks`. План — `docs/superpowers/plans/2026-11-09-amem-subproject-4d-writing.md`. Контракт не меняется, кроме мест, названных ниже.

### 6a.1. Семья вида

`Concept.family` схемы v1 — `source | work`, только у видов атомов. Контракт (`TemplateView.family`, `TemplateDraft.family`) знает ещё `object` — у шаблонов сущностей. Служба выводит `object` для `target: entity`. В черновике сущности допустима только `object`, у атома — `source | work`, иначе 422 `template_invalid`. Схема v1 не меняется.

### 6a.2. Блок `ui` и форма из шаблона

- **Блок `ui`** — необязательный слот `Template.ui` схемы v1: `body` (`wanted | required | none`), `widgets` (из `sources`, `links`, `around`, `values_table`, `similar`, `children`), `fields` — подписи, подсказки и тип по пути поля (`{<path>: {label, hint, type?}}`). Проверка пакета сверяет ключи `fields` с путями `FieldRule.path` и `parameters` шаблона: лишний путь — ошибка пакета. На проверку записей блок не влияет.
- **Форма** (`amem/forms.py`) — поле `FormField` на каждое правило поля и каждый параметр шаблона. Тип — из `ui.fields[path].type`, иначе по пути:
  - `about` → `object`;
  - `content.values[property=X]` → `quantity` (`property` = X, `unit` — UCUM из словаря property или правила поля);
  - `valid_from`, `valid_to` → `date`, оба сразу — одно поле `period`;
  - `tags` → `tags`;
  - поле со словарём → `choice` (`scheme`);
  - ссылка на запись через `rel` → `record` (`accepts`: `rel`, классы сущностей или виды);
  - иначе `text`.
- **Подпись и подсказка** — из `ui.fields`, иначе из словаря property (`label`, `definition`), иначе из пути. `required` — из правила поля. `body` по умолчанию `wanted`, `widgets` — `[sources, links]`.
- **`GET /templates?target=`** — действующие шаблоны (`template_active`) с формой; `editable` — шаблон из «Моих видов»; `records` — число записей вида (одним запросом на все виды).

### 6a.3. «Мои виды»

- **Пакет `mine` в базе.** Строка в таблице `pack` с именем `mine`, версия `0.0.N` растёт с каждой правкой, digest — `canon.content_hash` всех действующих шаблонов mine. Шаблоны — строки `template`: каждая правка — новая версия шаблона, `template_active` переключается. Понятия видов — `concept` с `origin = 'mine'`.
- **Те же проверки, что у пакета из файла.** Из базы собирается пакет mine и проверяется вместе с загруженными пакетами. Запись своего вида проходит те же проверки, что запись вида из пакета.
- **Код** — `[a-z][a-z0-9_]{1,63}` и не совпадает с кодом из пакетов-файлов (409 `template_exists`). Если пакет из файла позже принесёт тот же код, `db.prepare` отказывает (`MigrationError` с кодом и пакетом).
- **Перезапуск.** `db.load_vocab` не считает понятия `origin = 'mine'` осиротевшими и после пересборки `template_active` возвращает в неё действующие шаблоны mine (последнюю версию каждого неудалённого кода).
- **Удаление** — 409 `template_in_use`, если есть записи этого вида (любого статуса). Иначе шаблон уходит из `template_active`, понятие удаляется, пакет получает новую версию. Старые версии шаблона остаются: на них ссылаются проверенные ранее записи.
- **Подборки.** `export(with_packs=True)` кладёт mine как обычный пакет (`packs/mine/`, шаблоны собраны из базы). Импорт добавляет в mine шаблоны, которых в базе нет; тот же код с другим содержимым — коллизия `bundle_pack_conflict` в отчёте; `dry_run` показывает, что будет добавлено.

### 6a.4. Поиск и загрузка объектов

- **`GET /objects?q=&limit=&cursor=`** — объекты по части имени или пути без учёта регистра, с курсором; пустой `q` — последние объекты.
- **`POST /objects`** (multipart: `file`, необязательный `path`). Путь в папке документов — `path` или `Загрузки/<имя файла>` (NFC, те же правила относительного пути, что у объектов):
  - тот же файл по пути (тот же digest) — 200 с `ObjectView`;
  - по пути лежит другой файл — 409 `object_path_taken`, файл на диске не тронут;
  - иначе файл пишется атомарно (временный рядом, затем замена) и разбирается — 201;
  - нет `AMEM_DOCS` — 503 `docs_unavailable`.
- **Пределы и защита.** Предел размера — как у загрузки подборки (`UPLOAD_LIMIT`, 413, недокачанное удаляется). Квота `AMEM_STATE_QUOTA` не тратится: файл ложится в папку документов, а не в состояние службы. Нужен `Origin` своей службы, как у `/bundles/inspect`.

### 6a.5. Задачи агентам

- **Таблица `task`** (миграция 0012): id (UUIDv7), `kind` (`parse`), объект и версия, `note`, `state` (`open | claimed | done | cancelled`), кто поставил и когда, кто взял и до какого времени (аренда 30 мин, как у очереди проверки), когда закрыта, `result` (что сделано — ссылки записей). Входит в счётчики бэкапа.
- **Одна открытая задача на (kind, объект, версия).** Повтор `POST /tasks` возвращает тот же `task_id` (202).
- **MCP:** `amem_tasks` (открытые и свои), `amem_task_claim`, `amem_task_release`, `amem_task_done` (с `result`). Истёкшую аренду берёт другой агент.
- **CLI:** `amem tasks list [--state]`, `amem tasks cancel ID`.

### 6a.6. Права

- Свои виды правит и удаляет только человек (`person:`): модель — 403 `forbidden`, токен только для чтения — 403 `read_only`.
- Загружать файлы и ставить задачи могут человек и модель; токен только для чтения — нет.
- Брать и закрывать задачи — только модель (через MCP). Отменить — тот, кто поставил, или человек.

## 7. Поставка

- **Зависимости ядра:** `starlette`, `uvicorn`, `psycopg_pool`, `mcp`, `python-multipart`. CLI — на стандартной библиотеке.
- **`pyproject`:** скрипт `amem = amem.cli:main`; extra `web` тянет `amem-web`; в `package-data` — копия контракта и навыки.
- **compose:** образ службы, `db` (pgvector pg18, том) и служба `amem`.
  - Служба запускается как `amem serve --host 0.0.0.0` внутри сети compose; наружу публикуется только `127.0.0.1:8767`.
  - `AMEM_AGENT` задаётся явно в `.env`.
  - Разрешённый `Host` — `localhost` и имя службы в сети (`AMEM_ALLOWED_HOSTS=amem`); `AMEM_TOKENS` по желанию, без них — `--no-auth` (порт наружу только на `127.0.0.1`).
  - Профиль `web` — служба с `amem[web]`.
- **Одной командой:** `pipx install amem` (или `uv tool install amem`), затем `amem init` (DSN — из готового PostgreSQL или compose) и `amem install claude-code`; `amem doctor` проверяет результат.

## 8. Тестирование

- **Часть 4.0.** Папки:
  - правила пути;
  - перенос без новой ревизии;
  - реестр, переименование, удаление;
  - дерево со счётчиками;
  - журнал и события в `what_changed`.

  Ещё ссылки по ключу, `list_records` (фильтры, курсор), подписи, `log=False`, `session_activity` с отметкой пользы, коды `ReviewError`, `family`, имя базы.
- **Служба.** `starlette.testclient` на настоящей базе, на обеих версиях PostgreSQL:
  - каждый путь контракта со сверкой ответа по схеме;
  - ошибки 401, 403, 404, 409, 413, 421, 422, 503;
  - cookie человека и запросы без неё;
  - `Host` и `Origin`;
  - `Range`, `nosniff`, `attachment`;
  - выход за папку `/ui`;
  - чужой id загрузки.
- **MCP.** Клиент SDK через память, без сети:
  - поиск в три шага, `helpful` в той же задаче;
  - `submit` от `model:`;
  - неоднозначность.
- **CLI.** `main(argv)` с перехватом вывода: коды выхода по таблице 5.1, `--json`, агент по окружению.
- **Установщик.** На временном `HOME` и временном проекте: файлы до установки, после неё и после удаления; повторная установка; чужие ключи на месте; `--dry-run`. Команда `claude` подменяется заглушкой в `PATH`.
- **Хуки.** События из образцов протокола:
  - бюджет — база «зависает», хук укладывается в бюджет и отдаёт пустое;
  - сбой базы;
  - `<private>`;
  - проект по `cwd`;
  - ничего не записано в `retrieval` и журнал.

## 10. Риски

| Риск | Что делаем |
|---|---|
| Контракт и служба разойдутся | Один файл; копия в пакете с тестом совпадения; сверка в CI службы и `api:check` в CI веба; изменения — PR с правкой файла |
| Протоколы хуков и конфигов агентов меняются | Матрица платформ в одном модуле с версией формата; тесты на образцах; `amem doctor` показывает, что установлено |
| Хук замедлит агента | Бюджет 1,5 с, `statement_timeout`, только лексический поиск, fails open |
| Служба открыта в сеть без входа | По умолчанию только `127.0.0.1`; наружу без токенов — только явным `--no-auth` с предупреждением; `Host` и `Origin` проверяются всегда |
| Модель запишет от имени человека | Человек — только браузер с cookie службы, токен `person:` и CLI без признаков агента; остальное — `model:`. Остаточный риск — прямой доступ к базе по DSN (разд. 3.1) |
| Запросы пользователя осядут в базе навсегда | Хук не пишет выдачу и журнал; журнал — только явных поисков, отключается |
