# amemo — установщик для Windows и загрузки в релизах GitHub

**Задача (пользователь, 10.11).** amemo должны ставить люди, которые не работают в Claude Code: скачал установщик со
страницы релизов, прошёл несколько страниц мастера, нажал «Готово» — и amemo работает и подключён к приложению Claude
(в том числе Cowork). Без окон UAC, без команд в терминале, без «агент просит вас выполнить». На рабочем столе —
значок amemo: по нажатию открывается окно приложения с веб-интерфейсом, а не вкладка браузера.

## 1. Что есть сейчас

- **Установка** — `pipx install "amemo[web]"`, образ Docker или инструкция для агента `docs/install-agent.md`. Путь
  без WSL в Windows (PR #59) требует прав администратора дважды: PostgreSQL ставится службой Windows, pgvector
  собирается через Visual Studio Build Tools (2–3 ГБ).
- **Человек в цикле.** Часть команд amemo разрешает только человеку: `backup restore`, `embed enable`,
  `ocr install`. Когда ставит агент, он вынужден просить пользователя.
- **Claude.** `amemo install` подключает Claude Code и Codex; `amemo install cowork` (PR #66) собирает zip-плагин,
  который человек загружает в приложении Claude.
- **Релизы.** Метка `v*` на `main` публикует колёса на PyPI, а с PR #65 — и релиз на GitHub (колёса в нём). Метка
  `v0.1.0a1` — первая предварительная версия: «0.1.0», alpha 1. Она поставлена до появления шага `github-release`,
  поэтому страницы релиза у неё нет, есть только метка и пакет на PyPI.
- **CI** уже собирает pgvector 0.8.1 под Windows (job `windows` в `ci.yml`) и проверяет amemo в Windows без WSL.

## 2. Решения

1. **Формат — `amemo-setup-windows-x64.exe`: свой установщик с окном на веб-технологиях**, а не стандартный мастер
   Inno Setup или MSI.
   - Установщик сам выглядит как приложение amemo: окно без системной рамки, те же цвета, шрифты и тёмная тема, что
     в веб-интерфейсе (`web/DESIGN.md`), плавные переходы между шагами. Серые кнопки «Далее» стандартных мастеров
     не годятся — это первое, что человек видит.
   - Оболочка — та же, что у окна приложения (п. 7): pywebview и системный WebView2; страницы мастера — отдельная
     точка входа проекта `web/` (Vite), поэтому общие компоненты и стили берутся оттуда. Установщик собирается
     PyInstaller в один exe (~20–30 МБ).
   - Установщик **сетевой**: сам он маленький, а комплект (PostgreSQL, Python с amemo) качает из релиза GitHub.
     Для машин без сети — полный офлайн-комплект `amemo-setup-offline-<версия>-windows-x64.exe` (тот же exe с
     комплектом внутри), позже.
   - MSI (WiX) — позже, если попросят организации для массовой раскладки.
2. **Всегда последняя версия.**
   - Первым делом установщик спрашивает GitHub API о последнем релизе (канал — как у службы: стабильные, а с
     предварительной версией — и предварительные). Если сам установщик старее, он качает установщик новой версии
     из релиза, сверяет SHA-256 и перезапускается им, не показывая шагов старого — человек не поставит старую
     версию, даже скачав старый файл.
   - Комплект качается той же версии, что выбранный релиз; каждый файл сверяется по SHA-256 из релиза.
   - Без сети: стартовая страница честно говорит «нет связи с GitHub» и предлагает повторить или (если есть)
     офлайн-комплект.
3. **Экран установки знакомит с amemo.**
   - Пока идут загрузка и настройка (минуты), окно показывает ход по шагам (загрузка → база → хранилище →
     подключение агентов) и рядом — карусель «что умеет amemo»: анимации из README (`docs/assets/readme/<ru|en>/`
     `demo-sky`, `demo-write`, `demo-source`, `demo-review`, `demo-card`) с короткой подписью на языке, выбранном
     на первой странице. Новые сюжеты добавляются туда же и попадают и в README, и в установщик.
   - Анимации входят в установщик (не качаются отдельно): ~5–10 МБ; при сборке они пережимаются в WebP или MP4.
   - Последний экран — «Готово»: три подсказки, с чего начать (найти, записать, проверить), и кнопка «Открыть
     amemo».
4. **Без прав администратора — нигде.**
   - PostgreSQL — не служба, а процесс пользователя. В установщике — двоичные файлы PostgreSQL 18 (архив EDB «zip
     binaries», лицензия PostgreSQL, распространять можно), без pgAdmin, StackBuilder и документации.
   - pgvector — готовая `vector.dll` и файлы расширения, собранные в том же workflow релиза (те же команды, что в
     `ci.yml`). У пользователя ничего не компилируется.
   - Python — переносимый CPython 3.12 (python-build-standalone, тот, что ставит uv) с колёсами amemo и
     зависимостями, поставленными при сборке. Системный Python не нужен.
   - Всё ставится в `%LOCALAPPDATA%\Programs\amemo` (меняется на странице мастера).
   - Веб-интерфейс входит всегда (`amemo[web]`): для человека без терминала это и есть программа, ставить amemo
     без него из мастера смысла нет. Без веба — `pipx install amemo`, как сейчас.
5. **Страницы мастера.**
   1. Язык интерфейса amemo (русский, английский) — `lang` в `amemo.toml`. Сам мастер — на языке Windows.
   2. Папка программы.
   3. Папка данных: база PostgreSQL и хранилище копий файлов, на которые ссылаются записи. По умолчанию
      `%USERPROFILE%\amemo-data`. Свободное место — проверка с предупреждением.
   4. Папка документов — откуда amemo цитирует файлы (`docs`). Можно пропустить и задать потом в «Настройках».
   5. Возможности: распознавание сканов (языки Tesseract — флажки), смысловой поиск (загрузка модели ~250 МБ).
      Загрузки идут после установки, с полосой хода; без сети — пропускаются и включаются потом.
   6. Подключение: приложение Claude (Cowork), Claude Code, Codex — флажки, отмечены найденные на машине.
   7. Готово: «Значок на рабочем столе», «Запускать при входе в Windows», «Открыть amemo» — отмечены.
6. **Что мастер делает после загрузки** — одной командой `amemo setup --non-interactive …` (новая,
   из параметров страниц), чтобы та же логика работала и без мастера:
   - `initdb` в папку данных (кодировка UTF8, локаль C — без зависимости от языка Windows), `pg_hba` — только
     loopback и scram, `listen_addresses = 'localhost'`, свободный порт начиная с 5436;
   - пароль роли `amemo` — случайный, в `amemo.toml` с правами только пользователя (ACL), на экран не выводится;
   - расширения `vector` и `btree_gist` в базе и в `template1`, миграции, ядро и пакеты;
   - OCR и смысловой поиск — если отмечены: это действия человека, и их выбрал человек в мастере;
   - подключение агентов — `amemo install claude-code|codex`, для приложения Claude — п. 9.
7. **Окно приложения — pywebview, а не Electron.**
   - `amemo-app.exe` (запускалка на том же переносимом Python) открывает собственное окно с веб-интерфейсом
     `http://127.0.0.1:8767/ui/` через pywebview. В Windows pywebview рисует страницу системным WebView2 (Edge),
     он есть в Windows 10 и 11; если его нет — мастер ставит WebView2 Runtime для пользователя, без прав
     администратора.
   - Почему не Electron: он везёт свой Chromium (+100–150 МБ) и Node, а сервер amemo всё равно на Python. Tauri
     легче, но добавляет Rust в сборку. pywebview — несколько мегабайт и тот же Python, что уже в комплекте.
   - Оболочка общая с установщиком (п. 1). Окно: заголовок и значок amemo, размер и положение запоминаются, ссылки на внешние сайты открываются в
     браузере, а не в окне. Стиль — тот же веб-интерфейс; тёмная и светлая темы — по Windows.
   - Значки: «amemo» на рабочем столе (флажок на последней странице, отмечен) и в меню «Пуск».
8. **Что работает в фоне.**
   - При входе в Windows ключ `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` запускает
     `amemo-app.exe --background`: PostgreSQL (`pg_ctl start`) и служба `amemo serve` на `127.0.0.1:8767`, без
     окна. Фон нужен агентам: сервер MCP приложения Claude и Claude Code ходит в базу, даже когда окно закрыто.
   - Значок в области уведомлений (pystray): «Открыть amemo», «Пауза» (остановить службу и базу), «Выход».
     Закрытие окна фон не останавливает.
   - Нажатие на значок на рабочем столе при уже запущенном фоне только открывает окно; если фона нет —
     поднимает его и открывает окно, пока база стартует — экран «amemo запускается».
9. **Приложение Claude и Cowork.**
   - Мастер собирает расширение `amemo.mcpb` (локальный сервер MCP: полный путь к `amemo.exe`, `mcp --agent
     model:claude`) и открывает его — приложение Claude само показывает окно установки с одной кнопкой. Это
     нажатие обойти нельзя и не нужно: так приложение защищает пользователя. По документации Anthropic локальные
     серверы, в том числе из `.mcpb`, работают в сессиях Cowork на этом компьютере.
   - Навыки (`amemo-remember`, `amemo-answer`, `amemo-verify`) через `.mcpb` не ставятся. Их суть — в инструкциях
     самого сервера MCP (поле `instructions` ответа `initialize`): модель получает их при подключении. Проверить,
     что приложение Claude их передаёт; если нет — мастер предлагает загрузить zip-плагин (`amemo install cowork`)
     и показывает, куда нажать.
10. **Обновления.** Служба уже следит за релизами GitHub (спецификация обновлений). Для установки мастером она
   скачивает `amemo-setup-<новая>-windows-x64.exe` из релиза, сверяет SHA-256 из того же релиза и запускает его
   в тихом режиме (`--update`, параметры прежней установки — из `amemo.toml` и реестра); перед этим — бэкап базы,
   как при обновлении через pipx. Выключатель тот же: `auto_update`.
11. **Удаление** — «Приложения» Windows или ярлык: останавливает PostgreSQL и службу, убирает ключ автозапуска,
   подключения агентов (`amemo uninstall …`) и папку программы. Папку данных спрашивает отдельно, по умолчанию
   оставляет.
12. **Релизы GitHub.**
   - Workflow `release` получает job `windows-installer` (`windows-latest`): pgvector, переносимый Python, колёса из
     job `build`, PostgreSQL zip → комплект `amemo-bundle-<версия>-windows-x64.zip`; страницы мастера из `web/`,
     анимации, PyInstaller → `amemo-setup-<версия>-windows-x64.exe`; к каждому файлу — `.sha256`.
   - Проверка перед загрузкой: тихая установка установщика в чистый профиль раннера, `amemo doctor`, запись и
     поиск, `/health` службы, тихое удаление.
   - `github-release` прикладывает установщик к релизу рядом с колёсами. В описании релиза — блок «Скачать» со
     ссылками для Windows и командой `pipx` для остальных.
   - README: раздел «Скачать» вверху — ссылка `releases/latest/download/amemo-setup-windows-x64.exe` (постоянная
     ссылка на последнюю версию: файл с тем же именем без версии прикладывается вторым).
   - Для `v0.1.0a1` релиз создаётся задним числом без установщика (только колёса) — чтобы страница релизов не была
     пустой; установщик появится с первой версией после реализации.
13. **Подпись.** Первая версия — без подписи: SmartScreen покажет «Windows защитила ваш компьютер», README
    объясняет «Подробнее → Выполнить в любом случае». Подпись (Azure Trusted Signing или сертификат OV) —
    отдельной частью, она стоит денег и требует решения владельца.
14. **macOS и Linux** — вне этой спецификации. Там `pipx` и Docker работают; установщики (`.pkg`, AppImage) — по
    той же схеме позже.

## 3. Части и порядок

| Часть | Что | Проверка |
|---|---|---|
| D1 | `amemo setup --non-interactive` (initdb, порт, пароль, расширения, миграции, агенты) — работает и без мастера | тест в CI Windows и Linux на переносимом PostgreSQL |
| D2 | Сборка комплекта: PostgreSQL zip без лишнего, pgvector, переносимый Python с колёсами | размер ≤ 250 МБ, `amemo --version` из комплекта |
| D3 | Установщик: оболочка pywebview, страницы мастера в `web/`, проверка версии и самозамена, загрузка комплекта, экран с анимациями, вызов D1, ярлыки, автозапуск, удаление | тихая установка, самозамена старым установщиком и удаление в CI; вид — ручная проверка и снимки Playwright страниц мастера |
| D4 | `amemo-app.exe`: окно pywebview, фон, значок в области уведомлений, автозапуск | `--background` в CI — `/health`; окно — ручная проверка |
| D5 | `amemo.mcpb` и инструкции сервера MCP | расширение открывается приложением Claude (ручная проверка) |
| D6 | Обновление через установщик | обновление с версии N на N+1 в CI с сохранением базы |
| D7 | Релизы: job `windows-installer`, вложения, README «Скачать», релиз `v0.1.0a1` задним числом | релиз-кандидат `v0.1.0a2` |

## 4. Риски

- **Путь с кириллицей.** Профиль `C:\Users\Анна` — PostgreSQL в Windows исторически плохо переносит не-ASCII путь
  каталога данных. Проверить в CI с таким профилем; если не проходит — по умолчанию `C:\amemo-data` (создать папку
  в корне диска пользователь может без прав администратора) с предупреждением на странице.
- **Длинные пути.** Хранилище копий даёт пути около 260 символов: проверка `LongPathsEnabled`; если выключено —
  предупреждение и короче корень хранилища.
- **Антивирусы.** Неподписанный установщик, собранный PyInstaller, и PostgreSQL в профиле пользователя иногда
  помечаются как подозрительные. Подпись снимает большую часть; если ложных срабатываний много — оболочку
  установщика переписать на Tauri (тот же WebView2 и те же страницы `web/`, нативный exe без PyInstaller).
- **Лимит GitHub API.** Проверка версии без токена — 60 запросов в час с адреса: хватает; при отказе API установщик
  берёт `releases/latest/download/…` по постоянной ссылке.
- **Занятый порт.** Свой PostgreSQL у пользователя на 5432 — не трогаем, берём свободный.
- **Лицензии.** В комплект входят библиотеки PostgreSQL (OpenSSL, ICU, libxml2 и др.) — их тексты кладутся в папку
  программы (`THIRD-PARTY-NOTICES.txt`), как требуют лицензии; в колёса PyPI они не попадают.
- **WebView2.** В редких сборках Windows его нет — мастер ставит его для пользователя; без сети — окно не
  откроется, и запускалка открывает веб-интерфейс в браузере.
- **Размер.** PostgreSQL и Python дают ~150–250 МБ — терпимо для загрузки; модель смыслового поиска не входит,
  качается по выбору.
