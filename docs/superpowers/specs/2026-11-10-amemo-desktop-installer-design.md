# amemo — приложение для Windows на Tauri v2 и загрузки в релизах GitHub

**Задача (пользователь, 10.11).** amemo должны ставить люди, которые не работают в Claude Code: скачал установщик со
страницы релизов, прошёл красивый мастер, нажал «Готово» — и amemo работает и подключён к приложению Claude (в том
числе Cowork). Без окон UAC, без команд в терминале, без «агент просит вас выполнить». На рабочем столе — значок
amemo: по нажатию открывается окно приложения, а не вкладка браузера. Человек всегда получает последнюю версию, даже
скачав старый установщик. Пока идёт установка, окно знакомит с amemo. Оболочка — Tauri v2 (решение пользователя).

## 1. Что есть сейчас

- **Установка** — `pipx install "amemo[web]"`, образ Docker или инструкция для агента `docs/install-agent.md`. Путь
  без WSL в Windows (PR #59) требует прав администратора дважды: PostgreSQL ставится службой Windows, pgvector
  собирается через Visual Studio Build Tools (2–3 ГБ).
- **Человек в цикле.** Часть команд amemo разрешает только человеку: `backup restore`, `embed enable`,
  `ocr install`. Когда ставит агент, он вынужден просить пользователя.
- **Claude.** `amemo install` подключает Claude Code и Codex (сервер MCP, хуки, навыки); `amemo install cowork`
  (PR #66) собирает zip-плагин — сервер MCP и навыки, без хуков, — который человек загружает в приложении Claude.
- **Смысловой поиск** — `amemo embed enable` (только человек): fastembed качает модель
  `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` (Apache-2.0, ~250 МБ) с Hugging Face в
  `~/.local/share/amemo/models`, считает вектора и включает канал. Без него работают марки и полнотекстовый поиск.
- **Релизы.** Метка `v*` на `main` публикует колёса на PyPI, затем релиз на GitHub (шаг `github-release`, PR #65).
  Метка `v0.1.0a1` — первая предварительная версия («0.1.0», alpha 1); она поставлена до появления шага
  `github-release`, поэтому страницы релиза у неё нет — только метка и пакет на PyPI.
- **Самообновление службы** (PR #65) ставит новую версию через pipx и включено по умолчанию.
- **CI** уже собирает pgvector 0.8.1 под Windows (job `windows` в `ci.yml`) и проверяет amemo в Windows без WSL.
- **Анимации** для знакомства уже есть: `docs/assets/readme/<ru|en>/demo-{sky,write,source,review,card}.gif`.

## 2. Решения

1. **Одно приложение Tauri v2 — `desktop/`** (Rust и страницы из `web/`). Оно же мастер установки, оно же окно
   amemo, оно же значок в области уведомлений и фоновый запуск. Почему Tauri: системный WebView2 вместо своего
   Chromium (установщик ~10 МБ против 100+ у Electron), подписанные обновления и сборка установщика из коробки,
   нативный exe без PyInstaller (меньше ложных срабатываний антивирусов).
   - **Версия — Tauri 2 (стабильная ветка, 2.12.x на 10.11.2026), с переходом на Tauri 3 после его стабильного
     выпуска.** Tauri 3 сейчас в альфе (`tauri-v3.0.0-alpha.6` от 06.11.2026; плагины updater, single-instance,
     shell — `3.0.0-alpha.3`): между альфами меняется API, документация описывает v2, а первый выпуск amemo для
     людей не должен зависеть от альфы. Чтобы переход был заменой версии, а не переписыванием: артефакты
     обновлений — в формате v2 (`createUpdaterArtifacts: true`, без `v1Compatible`, который в v3 убран), логика
     приложения — в своих модулях Rust поверх небольшого набора API Tauri (окно, tray, updater, autostart,
     single-instance). Пересмотреть, когда у Tauri 3 выйдет кандидат в выпуск (rc).
2. **Установщик — NSIS из сборщика Tauri**, `amemo-setup-<версия>-windows-x64.exe`.
   - Режим установки по умолчанию — для текущего пользователя, в `%LOCALAPPDATA%`, без прав администратора и без
     UAC (https://v2.tauri.app/distribute/windows-installer/). `perMachine` и `both` не используем.
   - WebView2 — `downloadBootstrapper` (в Windows 10 с 2018 г. и в Windows 11 он уже есть; иначе докачивается).
   - Страницы NSIS сведены к одной: «Установить» с полосой хода. Настоящий мастер — первый запуск приложения
     (п. 4): там свои стили, а NSIS их не даёт.
3. **Всегда последняя версия — плагин updater Tauri.**
   - Обновления подписаны (ключевая пара Tauri, отключить нельзя): открытый ключ — в `tauri.conf.json`, закрытый —
     секрет `TAURI_SIGNING_PRIVATE_KEY` в GitHub Actions (владелец создаёт один раз, п. 12).
   - Источник — `https://github.com/empty-complete/amemo/releases/latest/download/latest.json` (статичный файл
     в релизе: `version`, `notes`, `pub_date`, `platforms.windows-x86_64.{signature,url}`), режим `passive`.
   - Первый запуск после установки сначала проверяет обновление. Если установщик был старым — приложение
     обновляется (окно с ходом), перезапускается и только потом показывает мастер. Человек не поставит старую
     версию, даже скачав старый файл.
   - Канал — как у службы: стабильная версия видит только стабильные, предварительная — и предварительные
     (`latest.json` — по последнему стабильному релизу; предварительный канал — файл `latest-pre.json`).
4. **Мастер первого запуска — в стиле amemo.**
   - Окно без системной рамки (`decorations: false`, свой заголовок с `data-tauri-drag-region` и кнопками окна), те
     же цвета, шрифты и тёмная тема, что в веб-интерфейсе (`web/DESIGN.md`), плавные переходы между шагами.
     Страницы мастера — отдельная точка входа проекта `web/` (Vite): общие компоненты и стили — оттуда.
   - Шаги:
     1. Язык amemo (русский, английский) — `lang` в `amemo.toml`.
     2. Папка данных: база PostgreSQL и хранилище копий файлов, на которые ссылаются записи. По умолчанию
        `%USERPROFILE%\amemo-data`; проверка места с предупреждением.
     3. Папка документов — откуда amemo цитирует файлы (`docs`). Можно пропустить и задать потом в «Настройках».
     4. Возможности: распознавание сканов (языки — флажки). Смысловой поиск ставится всегда, без флажка: это
        часть amemo, а не дополнение; выключить можно потом в «Настройках».
     5. Подключение: приложение Claude (Cowork и Claude Code), Codex — флажки, отмечены найденные на машине
        (п. 10).
     6. Установка (п. 5) — ход и знакомство.
     7. Готово: три подсказки, с чего начать (найти, записать, проверить); флажки «Значок на рабочем столе»,
        «Запускать при входе в Windows» (отмечены); кнопка «Открыть amemo».
5. **Экран установки знакомит с amemo.**
   - Слева — ход по шагам: загрузка комплекта и модели → база → хранилище → смысловой поиск → распознавание сканов
     → подключение агентов. Справа —
     карусель «что умеет amemo»: анимации из README (`docs/assets/readme/<ru|en>/demo-*.gif`) с короткой подписью
     на выбранном языке. Новые сюжеты кладутся туда же и попадают и в README, и в приложение.
   - Анимации входят в приложение (~5–10 МБ; при сборке пережимаются в WebP или MP4), не качаются отдельно.
6. **Комплект — отдельный архив релиза, качается мастером.**
   - `amemo-runtime-<версия>-windows-x64.zip`: PostgreSQL 18 (архив EDB «zip binaries», лицензия PostgreSQL;
     без pgAdmin, StackBuilder и документации), готовые `vector.dll` и файлы расширения pgvector (сборка в том же
     workflow релиза, команды как в `ci.yml`), переносимый CPython 3.12 (python-build-standalone) с колёсами
     `amemo[web,embed]` и зависимостями (fastembed и onnxruntime). У пользователя ничего не компилируется,
     системный Python не нужен.
   - Модель смыслового поиска — отдельный архив релиза `amemo-model-paraphrase-multilingual-MiniLM-L12-v2.zip`
     (~250 МБ, файлы в раскладке кэша fastembed, лицензия Apache-2.0 и NOTICE модели — внутри). Зеркало в релизе
     GitHub, а не загрузка с Hugging Face: тот бывает медленным или недоступным, а установка не должна от него
     зависеть. Архив меняется только с моделью — новый релиз amemo ссылается на прежний файл, если модель та же.
   - Версия комплекта — та же, что у приложения; SHA-256 — из релиза. Распаковка в
     `%LOCALAPPDATA%\amemo\runtime\<версия>`; прежняя версия удаляется после успешного запуска новой.
   - Веб-интерфейс входит всегда (`amemo[web]`): без него приложение не нужно; без веба — `pipx install amemo`.
7. **Настройка — одна команда amemo** `amemo setup --non-interactive …` (новая; та же логика без приложения):
   - `initdb` в папку данных (UTF8, локаль C), `pg_hba` — только loopback и scram, `listen_addresses =
     'localhost'`, свободный порт начиная с 5436;
   - пароль роли `amemo` — случайный, в `amemo.toml` с правами только пользователя (ACL), на экран не выводится;
   - расширения `vector` и `btree_gist` в базе и в `template1`, миграции, ядро и пакеты;
   - смысловой поиск — всегда: модель распаковывается в `models_dir()`, затем то же, что `amemo embed enable` без
     загрузки (регистрация модели, вектора всех документов, включение канала); это действие человека, и
     установку запустил человек;
   - OCR — если отмечены языки: тоже действие человека, выбранное в мастере;
   - агенты — `amemo install claude-code|codex`, приложение Claude — п. 10;
   - `auto_update = false`: обновляет приложение (п. 3 и 11), а не служба — второй механизм не нужен.
8. **Окно amemo.**
   - После мастера приложение открывает окно с веб-интерфейсом службы `http://127.0.0.1:8767/ui/`. Окну
     разрешены только команды окна (`core:window:*` через capability с `remote.urls` для `http://127.0.0.1:*`),
     ничего больше: страница службы не получает доступа к файлам и процессам.
   - Веб-интерфейс, открытый в Tauri, показывает свой заголовок окна с кнопками (по признаку `window.__TAURI__`);
     в браузере — как сейчас.
   - Ссылки на внешние сайты открываются в браузере. Размер и положение окна запоминаются. Тема — по Windows.
   - Плагин single-instance: второй запуск только выводит окно вперёд.
9. **Фон и значок в области уведомлений.**
   - Приложение запускает PostgreSQL (`pg_ctl start`) и службу `amemo serve` дочерними процессами из комплекта
     (Rust, `std::process`; сайдкары Tauri не нужны — комплект не входит в установщик) и следит за ними.
   - Закрытие окна фон не останавливает: агентам (сервер MCP приложения Claude и Claude Code) база нужна и без
     окна. Значок в области уведомлений (`tray-icon`): «Открыть amemo», «Пауза» (остановить службу и базу),
     «Выход».
   - Автозапуск — плагин autostart с флагом `--background` (без окна). Механизм в Windows документация не
     называет — проверить, что он ставится без прав администратора (ожидаемо ключ `Run` в `HKCU`).
   - Значок на рабочем столе и в меню «Пуск» — от NSIS; если фон уже работает, только открывается окно; если
     нет — экран «amemo запускается», пока поднимается база.
10. **Приложение Claude, Cowork и Claude Code — один плагин amemo: сервер MCP, навыки и хуки.**
    - Мастер собирает плагин (`amemo install cowork`, расширенный хуками) — тот же набор, что `amemo install
      claude-code`: сервер MCP (`mcp --agent model:claude`), навыки `amemo-remember`, `amemo-answer`,
      `amemo-verify` и хуки `SessionStart`, `UserPromptSubmit`, `PreCompact` в форме exec (без оболочки, как в
      Windows у Claude Code). Путь к amemo — постоянный `%LOCALAPPDATA%\amemo\bin\amemo.exe` (запускатель текущей
      версии комплекта), поэтому плагин не устаревает с обновлением.
    - **В аккаунт плагин загружает человек — одно действие, обойти его нельзя.** Anthropic даёт добавить плагин
      только в приложении (Customize → Plugins → Add → Upload plugin); командой или API этого не сделать. Мастер
      делает всё вокруг: кладёт zip, открывает приложение Claude и папку с файлом, показывает короткую анимацию
      «куда нажать» и ждёт. Плагин сохраняется в аккаунте: приходит в Cowork и сам синхронизируется в Claude Code
      на этом и других компьютерах.
    - **Claude Code работает сразу, без ожидания загрузки:** мастер ставит `amemo install claude-code`. Когда
      плагин из аккаунта появился в Claude Code (приложение amemo видит его среди синхронизированных плагинов),
      прямая установка убирается сама (`amemo uninstall claude-code`) — дублей сервера и хуков нет.
    - **Где работает.** Локальный сервер MCP и хуки — в сессиях Cowork на этом компьютере и в Claude Code. В
      облачных сессиях Cowork amemo нет; Cowork загружает хуки плагина и там — проверить, что отсутствующая
      команда даёт тихий отказ, а не ошибку на каждом сообщении. Если ошибка видна — хук вызывается через обёртку,
      которая молча выходит, когда amemo на машине нет.
    - **Codex** — `amemo install codex`, как сейчас.
    - Расширение `.mcpb` (установка одной кнопкой) не используется: в нём только сервер MCP, без навыков и хуков.
11. **Обновления после установки.** Приложение проверяет `latest.json` при запуске и раз в 6 часов. Новая версия:
    бэкап базы (`amemo backup create`), обновление приложения (updater, `passive`), затем новый комплект и
    миграции; при ошибке — откат на прежний комплект. Выключатель — «Настройки» приложения.
12. **Релизы GitHub.**
    - Workflow `release` получает job `desktop` (`windows-latest`): комплект (п. 6), страницы мастера из `web/`,
      анимации, `tauri build` → `amemo-setup-<версия>-windows-x64.exe`, `.sig` для updater, `.sha256` для всех
      файлов; `latest.json` (и `latest-pre.json`) собирает `tools/release.py`.
    - Проверка перед загрузкой: тихая установка в чистый профиль раннера, `amemo setup --non-interactive` из
      комплекта, `amemo doctor`, запись и поиск, `/health`, обновление с прошлой версии, удаление.
    - `github-release` прикладывает всё к релизу рядом с колёсами. Описание релиза — блок «Скачать» со ссылкой
      для Windows и командой `pipx` для остальных.
    - README: раздел «Скачать» вверху — `releases/latest/download/amemo-setup-windows-x64.exe` (тот же файл без
      версии в имени прикладывается вторым — постоянная ссылка на последнюю версию).
    - Для `v0.1.0a1` страница релиза создаётся задним числом (колёса, без приложения), чтобы раздел не был пустым.
    - **Один раз — владелец репозитория:** создать ключевую пару updater (`npm run tauri signer generate`) и
      положить закрытый ключ и пароль в секреты Actions (`TAURI_SIGNING_PRIVATE_KEY`,
      `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`). Без них обновления не подпишутся.
13. **Удаление** — «Приложения» Windows: NSIS останавливает фон, убирает автозапуск, подключения агентов
    (`amemo uninstall …`), приложение и комплект. Папку данных спрашивает отдельно, по умолчанию оставляет.
14. **Подпись exe** (Authenticode) — первая версия без неё: SmartScreen покажет «Windows защитила ваш компьютер»,
    README объясняет «Подробнее → Выполнить в любом случае». Подпись (Azure Trusted Signing или сертификат OV)
    — отдельной частью, стоит денег, решение владельца. Это не то же, что подпись обновлений (п. 3).
15. **macOS и Linux** — вне этой спецификации, но Tauri собирает их той же сборкой (`.dmg`, AppImage); комплект
    там — свой. Позже.

## 3. Части и порядок

| Часть | Что | Проверка |
|---|---|---|
| D1 | `amemo setup --non-interactive` (initdb, порт, пароль, расширения, миграции, агенты, `auto_update = false`) | тесты в CI Windows и Linux на переносимом PostgreSQL |
| D2 | Комплект `amemo-runtime-…-windows-x64.zip`: PostgreSQL без лишнего, pgvector, Python с колёсами `amemo[web,embed]`; архив модели смыслового поиска | размер комплекта ≤ 250 МБ, `amemo --version`, `pg_ctl` и вектор пробного текста из комплекта в CI |
| D3 | Каркас `desktop/` на Tauri v2: окно без рамки, single-instance, tray, NSIS для пользователя, updater, capability окна службы | `tauri build` в CI; тихая установка и удаление |
| D4 | Мастер первого запуска в `web/` (точка входа `setup`), экран установки с каруселью | снимки Playwright страниц мастера в обеих темах и языках |
| D5 | Управление фоном: запуск и остановка PostgreSQL и службы, автозапуск, запускатель `bin\amemo.exe` | `--background` в CI — `/health`; перезапуск — ручная проверка |
| D6 | Плагин amemo с хуками (`amemo install cowork`), запускатель `bin\amemo.exe`, экран «загрузите плагин», снятие прямой установки Claude Code после синхронизации; модель смыслового поиска в релизе и её включение в `amemo setup` | состав zip и хуки — тесты; синхронизация и облачная сессия — ручная проверка; смысловой поиск включён после тихой установки в CI |
| D7 | Обновления: `latest.json`, обновление приложения и комплекта с бэкапом и откатом | обновление N → N+1 в CI с сохранением базы |
| D8 | Релизы: job `desktop`, вложения, README «Скачать», страница `v0.1.0a1` | релиз-кандидат `v0.1.0a2` |

## 4. Риски

- **Путь с кириллицей.** Профиль `C:\Users\Анна` — PostgreSQL в Windows исторически плохо переносит не-ASCII путь
  каталога данных. Проверить в CI с таким профилем; если не проходит — по умолчанию `C:\amemo-data` (создать папку
  в корне диска пользователь может без прав администратора) с предупреждением.
  *Итог D2 (11.11):* программы PostgreSQL открывают пути ANSI-функциями — символ вне кодовой страницы системы
  (кириллица в английской Windows) становится «?», и initdb не находит себя. `amemo/localpg.py native` передаёт
  такие пути короткими именами 8.3 (на C: они включены по умолчанию), бэкап — тоже; без них `amemo setup` отказывает
  с подсказкой. CI (`runtime.yml`) проверяет комплект в `%USERPROFILE%\Проверка комплекта\Анна` на раннере с
  кодовой страницей 1252. Мастеру (D4) остаётся: если `native` отказывает — предложить `C:\amemo-data`.
- **Длинные пути.** Хранилище копий даёт пути около 260 символов: проверка `LongPathsEnabled`; если выключено —
  предупреждение и короче корень хранилища.
- **Антивирусы и SmartScreen.** Неподписанный exe и PostgreSQL в профиле пользователя иногда помечаются как
  подозрительные; подпись Authenticode снимает большую часть.
- **Окно службы в Tauri.** Страница с `http://127.0.0.1:8767` в окне Tauri — удалённый адрес: capability только на
  команды окна. Проверить, что cookie сессии человека и правило `Origin` службы работают в WebView2 так же, как в
  браузере.
- **Предварительный канал.** `releases/latest/download/…` не видит предварительные релизы и черновики — поэтому
  предварительный канал читает `latest-pre.json`, который прикладывается к каждому релизу.
- **Объём загрузки.** Комплект (~250 МБ) и модель (~250 МБ) качаются при установке: экран установки показывает
  скорость и остаток; прерванная загрузка продолжается с места (HTTP Range), а не с начала.
- **Хуки плагина в облаке.** Поведение хука с отсутствующей командой в облачной сессии Cowork документация не
  описывает — проверить до выпуска (п. 10).
  *Итог D6 (11.11):* хуки в плагине — в форме exec с путём запускателя (`hooks/hooks.json`); в CI проверены состав
  zip, путь запускателя в плагине и в Claude Code и ответ хука через запускатель. Облачная сессия и синхронизация
  плагина (`amemo@synced` → снятие прямой установки, `amemo install claude-code --unless-synced`) — ручная проверка;
  если облачная сессия показывает ошибку хука, нужна обёртка (п. 10). Анимации «куда нажать» на шаге плагина нет:
  снимков интерфейса приложения Claude в репозитории нет — шаги названы словами.
- **Занятый порт.** Свой PostgreSQL у пользователя на 5432 — не трогаем, берём свободный.
- **Лицензии.** Библиотеки PostgreSQL (OpenSSL, ICU, libxml2 и др.) и Tauri — тексты в `THIRD-PARTY-NOTICES.txt`
  в папке приложения; в колёса PyPI они не попадают.
- **Rust в сборке.** Нужен только в CI (`windows-latest`); локально разработчику веба он не обязателен — страницы
  мастера проверяются в браузере на моках.
