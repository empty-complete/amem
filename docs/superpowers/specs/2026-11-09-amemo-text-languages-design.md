# amemo — язык текста записей: ru и en на равных

Редакция 1 (09.11.2026). Небольшая правка схемы v1, службы и веба, а не подпроект.

## Задача

Схема v1 требует слот `ru` у каждого LangString, служба отдаёт подписи только из `ru`, веб читает `.ru` напрямую,
полнотекстовый поиск индексирует только `ru`. Англоязычный пользователь вынужден писать английский текст в слот
`ru` (так делает образец README `tools/seed_sample_en.py`). Нужно: базу можно вести по-английски без обмана схемы,
а английский интерфейс показывает `en`, когда он есть.

## 1. Правило схемы

**У LangString хотя бы один из слотов `ru`, `en` — строка.** По отдельности ни один не обязателен.

Отвергнутый вариант — «у базы основной язык, его слот обязателен». Он делает проверку тела зависимой от настроек
базы: подборка из английской базы не входит в русскую без перевода, а правило уровня 1 перестаёт быть свойством
одной схемы. Показу основной язык базы тоже не нужен — его решает язык читателя (разд. 2).

- Правило только ослабляет схему: всё, что было валидно, валидно и сейчас. Версия схемы остаётся `amemo/1`, хэши
  ревизий не меняются, миграции тел нет.
- LinkML: на классе `LangString` — `any_of` из двух `slot_conditions` (`ru` required, `en` required). Генератор
  JSON Schema переводит его в `anyOf`. gen-pydantic такие правила не исполняет, поэтому `tools/gen_schema.py`
  добавляет классу `model_validator` по тому же `any_of` (источник правила — только YAML); `--check` в CI
  по-прежнему сравнивает результат.
- Пустота для правила `required` шаблона (уровень 1): LangString пуст, если ни в одном слоте нет непустой строки.
  Было: пуст, если пуст `ru`.
- Сообщение правила шаблона (`message` — LangString) берётся на языке запроса (разд. 2).
- Слоты ограничены `ru`, `en`. Третий язык — новый слот схемы и строка в `amemo/lang.py` (порядок замены
  и конфигурация полнотекстового поиска); не делаем сейчас.

## 2. Язык показа

`amemo/lang.py`: языки `LANGS = ("ru", "en")`; порядок замены — запрошенный язык, затем остальные по `LANGS`.
Пустая строка слота считается отсутствием. Без запроса — `ru`, затем `en`, как было до правки.

- HTTP: заголовок `Accept-Language` (веса `q`, первый поддерживаемый язык; `en-GB` → `en`). Нет поддерживаемого —
  порядок по умолчанию. Язык ставится на время запроса там же, где берётся соединение из пула (`app.connection`),
  поэтому его видят все операции `amemo/api.py`.
- MCP: аргумент `lang` (`ru` | `en`) у инструментов чтения (`amemo_search`, `amemo_similar`, `amemo_timeline`,
  `amemo_get`, `amemo_card`); без него — настройка `lang` (`AMEMO_LANG` или `lang` в `amemo.toml`), затем порядок
  по умолчанию.
- CLI: общая опция `--lang ru|en`; без неё — та же настройка `lang`.
- Что выбирается: строковые подписи ответов (`label` у RefLabel, сводок списка, находок поиска, ленты, карточки,
  полей профиля), фрагмент находки (`snippet`), подписи CLI, хуков агента и антологии. Тела записей (`payload`)
  отдаются целиком, со всеми слотами: выбирает клиент.
- Формы JSON контракта HTTP не меняются: `label` остаётся строкой. В контракте LangString — одна схема
  `components.schemas.LangString` (`minProperties: 1` вместо `required: [ru]`), `Accept-Language` описан в
  `info.description`.

## 3. Полнотекстовый поиск

- Индекс (`search_document.search_vector`): слоты `ru` и языконезависимый текст (содержимое атома, aliases,
  марки) — конфигурация `russian`, как было (ASCII-слова она и так ведёт английским стеммером); слоты `en` —
  конфигурация `english`. Веса A–D те же.
- Запрос: `websearch_to_tsquery('russian', q) || websearch_to_tsquery('english', q)` — запрос на любом языке
  находит текст в любом слоте; расхождение стеммеров (не-ASCII буквы в английском тексте) закрывает вторая половина.
- Документ эмбеддинга: по весам сначала фрагменты `ru`, затем `en`. У записи без `en` документ прежний, хэши
  векторов совпадают — пересчёт эмбеддингов не нужен, `SEARCH_TEXT_VERSION` остаётся 1.
- Фрагмент находки строится из текста выбранного языка (с заменой), а не из общего документа.
- Перестройка: `meta.search_projection` — версия проекции (2). `db.prepare` перестраивает поиск, если версия в базе
  меньше; под рекомендательной блокировкой, чтобы две службы не строили разом.
- Уровень 4 (дубли): лексемы подписей — по обеим конфигурациям. Бэкап: пробный атом — по подписи любого языка,
  проверка восстановления — тем же двуязычным запросом.

## 4. Веб

- Один помощник выбора текста — `web/src/ui/lang.ts`: `pickText(ls, lang)` (тот же порядок замены, что у службы)
  и `useText()` — он же, привязанный к языку интерфейса. Прямых `.ru` в компонентах не остаётся.
- Клиент API ставит `Accept-Language` по языку интерфейса; смена языка сбрасывает кэш запросов.
- Запись: новый текст — в слот языка интерфейса; правка существующего текста — в тот слот, из которого текст
  показан (иначе правка русской подписи в английском интерфейсе завела бы `en` с русским текстом); остальные
  слоты сохраняются.

## 5. Образец и README

- `tools/seed_sample_en.py` пишет текст в `en`; оговорка в README «Good to know» уходит.
- Снимки README — заново workflow `readme-shots` (артефакты `readme-shots-en`, `readme-shots-ru` →
  `docs/assets/readme/{en,ru}`).

## Чего не делаем

- Перевод: amemo не переводит. Показ с заменой честно отдаёт текст на другом языке.
- Основной язык базы: хватает языка запроса и настройки `lang` процесса (она — только язык показа, проверка тел
  от неё не зависит).
- Языковые варианты (`en-GB`, `pt-BR`) как отдельные слоты.
