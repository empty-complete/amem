# amem — подпроект 3: автопроверка и очередь проверки

Редакция 1 (05.11.2026).

Продолжение спецификаций `2026-10-19-schema-v1-postgres-reatomize-design.md` (разд. 3 «Автопроверка», разд. 6), `2026-10-25-amem-core-split-design.md` (разд. 1, строка 3) и `2026-11-03-amem-subproject-2-engine-design.md`. Учтены заметки к этапу 3 из плана 2.2 (итог сверки в `source`, xlsx и docx, кэш «текста нет») и уроки разбора Graphiti и Graphify: ответ «принято», когда обработка ещё только в очереди, вводит в заблуждение (getzep/graphiti#1574); исходы проверки — машиночитаемые; любое ослабление проверки объявляется в ответе.

## Цель

Одна точка записи знаний — `check.submit`. Пакет предложенных атомов, сущностей и связей проходит уровни 1–4. Дальше два исхода:
- пакет отклоняется целиком, и агент получает отчёт;
- пакет записывается: у записей появляются статусы, у источников — итоги сверки с файлом, в очереди проверки — пункты.

Очередь наблюдаема: у каждого пункта есть состояние, у очереди — метрики, а ответ записи разделяет, что уже сделано и что только поставлено в очередь.

Состав подпроекта:
- уровни 1–4 из спецификации v1: схема и шаблон, привязка к источнику, здравый смысл, дубли;
- извлечение текста xlsx/xlsm и docx и сброс старого кэша «текста нет» у этих файлов;
- очередь `review_item`: причины, состояния, захват с арендой, решение с журналом вердиктов `verification`, выборка аудита, метрики;
- новая версия объекта ставит записи, которые ссылаются на старую версию, в очередь пересмотра;
- повторная сверка источников (`recheck_sources`).

Результат — библиотека `amem`, миграция `0006_check.sql` и тесты на PostgreSQL 18 и 16.

Что не входит в подпроект:
- **исполнитель уровня 5** — навык смыслового проверяющего и его ночной запуск: подпроект 4;
- **сервер MCP/HTTP и CLI**: подпроект 4;
- **страница «Проверка»** в веб-интерфейсе: подпроект 5.

Для них здесь готовы очередь, захват и функции решения.

## Решения

| Вопрос | Решение |
|---|---|
| Где проверка | Пакет `amem.check`. `records.commit` остаётся низкоуровневой записью без проверок: ею пользуются миграции данных и тесты |
| Ошибка уровня 1 или 2 | Пакет отклоняется целиком: `records.reject` с отчётом. Копии файлов, принятые разбором источников, остаются — как в 2.2: копия — содержимое, а не утверждение |
| Новый атом | `needs_review`, если есть предупреждение или высокий риск. Иначе `draft` и пункт `semantic` в очереди — ждёт уровня 5 |
| Сущность | Уровни 1 и 4. Без замечаний — `auto_verified` (и выборка аудита), иначе `needs_review` |
| Правка записи, проверенной человеком | Ревизия ждёт решения (`review_state = pending`) и текущей не становится; пункт `edit` |
| Правка выведенной из оборота записи | Ошибка `retired_record`: сначала вернуть статус |
| Высокий риск | Правила `high_risk` в шаблонах пакетов (`always`, `numeric`). Противоречие уровня 3 и сомнение уровня 5 — всегда высокий риск. Ядро помечает так вид `decision` |
| Единицы | UCUM через `ucumvert` (MIT; pint и lark). Минимальный Python — 3.11 |
| xlsx | `openpyxl`: лист — страница, у формул — сохранённые значения |
| docx | Стандартная библиотека (zipfile + ElementTree). Страницы — по разрывам страниц, в том числе сохранённым Word |
| Дубли | Полнотекстовый поиск по словам подписи и вектор активной модели, если есть provider. Пороги — константы до калибровки в пилоте |
| Очередь | Таблица `review_item`: причина, состояние `queued → claimed → done` или `obsolete`, аренда. Вердикты — неизменяемая таблица `verification` |
| Кто решает | `semantic` — любой агент, кроме автора пакета. Остальные причины — только `person:` |
| Аудит | 2 % записей, перешедших в `auto_verified`. Если в последних 50 проверках аудита этого автора или типа файла больше 5 % ошибок — 20 % |
| Ответ записи | `complete` — сделано ли всё. `queued` — что поставлено в очередь. Уровни — `done`, `queued`, `skipped` или `not_applicable` |
| Новая версия объекта | В той же транзакции, что и версия: пункты `source_changed` для текущих ревизий, которые ссылаются на старую версию |
| Сеть | Не нужна: уровень 4 берёт provider по правилам подпроекта 2, без provider идёт только текстом и объявляет это |

## 1. Устройство

| Модуль | Что делает |
|---|---|
| `amem/check/__init__.py` | `submit`, `Proposal`, `Submitted`: порядок уровней, статусы, запись |
| `amem/check/report.py` | `Issue`, перечень кодов, отчёт формата `amem.check/1` |
| `amem/check/templates.py` | Сведение шаблонов; правила полей и связей |
| `amem/check/level1.py` … `level4.py` | Уровни проверки |
| `amem/check/numbers.py` | Числа атома и числа во фрагменте текста |
| `amem/check/units.py` | UCUM: проверка кода и перевод величины в другую единицу |
| `amem/extract.py` | Текст xlsx/xlsm и docx; `sources.extract_pages` передаёт ему эти файлы |
| `amem/review.py` | Очередь: постановка, захват, решение, аудит, метрики, повторная сверка |
| `amem/sql/0006_check.sql` | Таблицы очереди и вердиктов, активные шаблоны, сброс кэша |

`sources.py` по-прежнему не знает о базе. `objects.py` по-прежнему пишет объекты отдельной транзакцией до пакета изменений.

### 1.1. Порядок `submit`

```python
check.submit(conn, store, docs, proposals, links=(), *, agent, activity=None, reason=None,
             provider=None) -> Submitted
```

`Proposal(target, payload, record_id=None)` — предложенная ревизия: новая запись, если `record_id` нет, иначе новая ревизия существующей. Статус агент не предлагает: его ставит автопроверка.

1. **Разбор.** Тело проверяется Pydantic в строгом режиме JSON: `AtomPayload`, `EntityPayload`, `LinkPayload`. Это уровень 1, часть «схема». Если тело не разобралось, остальные уровни для этой записи не идут.
2. **Ссылки.** @имена пачки, ключи и UUID существующих записей сопоставляются с записями: какой вид атома, какой класс сущности, какой статус. Это нужно правилам шаблонов и концам связей. Неизвестная ссылка — ошибка `ref_unknown`.
3. **Уровень 1** — коды словаря, шаблоны, жёсткие правила, концы связей, UCUM (разд. 3).
4. **Уровень 2** — разбор источников в объекты, версии, текст, сверка цитаты и чисел, подстановка редакции (разд. 4).
5. **Есть хотя бы одна ошибка (`violation`)** — `records.reject` с отчётом, ответ `rejected`. Уровни 3 и 4 не выполняются.
6. **Уровни 3 и 4** — только у пакета, прошедшего уровни 1 и 2 (разд. 5, 6).
7. **Запись — одна транзакция** (разд. 7.5):
   - блокировки существующих записей и перечитывание их статусов;
   - `records.commit` — внутри него точка сохранения;
   - итоги сверки в строки `source`;
   - устаревшие пункты очереди закрываются;
   - новые пункты очереди, выборка аудита.
8. **Ответ** `Submitted` (разд. 2.3).

Если `records.commit` отказал поздно (ключ занят, сроки редакций пересекаются), транзакция откатывается. Тогда пакет записывается отклонённым с кодом `record_error`.

Ошибки окружения не превращаются в отклонённый пакет — в базе ничего не появляется, исключение уходит вызывающему:
- `StoreError`: корня хранилища нет или пропала копия версии;
- сбой соединения с базой;
- `EmbedError` от явно переданного provider.

Уровни 1–4 читают базу вне транзакции записи. Два параллельных пакета с одинаковым атомом оба могут пройти уровень 4 без предупреждения — это допустимо. Уровни 1 и 2 опираются на неизменяемые объекты и версии и на редко меняющиеся словари и шаблоны. Статус существующей записи решает политику правки, поэтому он перечитывается под блокировкой уже в транзакции записи.

## 2. Отчёт и исходы

### 2.1. Замечание

`Issue(level, severity, code, where, message, details)`:
- `level` — 1–4;
- `severity` — `violation`, `warning` или `info` (перечень `Severity`);
- `code` — из закрытого перечня `CheckCode` схемы;
- `where` — метка записи (`@имя`, `items[i]`, `links[i]`) и путь поля: `@a1: sources[0].quote`;
- `message` — по-русски, для человека;
- `details` — JSON для машины: точный текст документа при нечёткой цитате, кандидаты в дубли, найденные числа.

### 2.2. Коды

| Код | Уровень | Важность | Когда |
|---|---|---|---|
| `schema` | 1 | violation | Тело не проходит Pydantic; `details.loc`, `details.msg` |
| `unknown_code` | 1 | violation | Нет кода `kind`, `entity_class`, `rel` или типа селектора в загруженных пакетах |
| `ref_unknown` | 1 | violation | Ссылка на запись, которой нет |
| `template` | 1 | из правила | Не выполнено правило шаблона; `details`: шаблон, путь правила, вид правила |
| `ucum` | 1 | из правила | Единица — не код UCUM |
| `unit_required` | 1 | violation | Есть `amount` или границы, нет `unit` |
| `bounds_order` | 1 | violation | `lower_bound` больше `upper_bound` или `amount` вне границ |
| `link_not_allowed` | 1 | violation | Исходящая связь вида, которого нет в `links.allowed` шаблона |
| `link_required` | 1 | из правила | Нет обязательной связи шаблона |
| `link_pair` | 1 | violation | Концы связи не из `pairs` её вида |
| `retired_record` | 1 | violation | Правка записи со статусом `deprecated` или `superseded` |
| `record_error` | 1 | violation | Поздний отказ `records.commit` |
| `source_unresolved` | 2 | violation | Путь источника не разобрался (`ObjectError`) |
| `version_missing` | 2 | violation | У объекта нет указанной версии |
| `digest_mismatch` | 2 | violation | `digest` не совпадает с версией |
| `pdf_page_required` | 2 | violation | У PDF нет селектора страницы |
| `pdf_quote_required` | 2 | violation | У PDF нет дословной цитаты |
| `quote_not_found` | 2 | violation | Цитаты в тексте нет |
| `quote_fuzzy` | 2 | violation | Цитата найдена только нечётким поиском; `details`: точный текст, страница, схожесть |
| `number_not_found` | 2 | violation или warning | Числа атома нет во фрагменте; warning, если у атома есть источник с `role: derived` |
| `page_moved` | 2 | info | Цитата на другой странице — номер исправлен в `source.page` |
| `place_unresolved` | 2 | warning | Цитаты нет, селектор места не нашёл |
| `no_text` | 2 | warning | У файла нет текста: скан, чертёж, неподдерживаемый формат |
| `external_source` | 2 | warning | Источник — страница сайта или переписка |
| `source_error` | 2 | warning | Сбой извлечения или сверки |
| `numbers_unchecked` | 2 | info | Числа не с чем сверить: нет найденного фрагмента |
| `edition_filled` | 2 | info | Редакция подставлена по файлу |
| `unknown_property` | 3 | warning | Кода величины нет в словаре `property`, хотя словарь величин загружен |
| `out_of_range` | 3 | warning | Значение вне `plausible_min` – `plausible_max` величины |
| `unit_mismatch` | 3 | warning | Единицу значения нельзя перевести в единицу величины |
| `conflict` | 3 | warning | Другое значение той же величины у той же сущности при тех же условиях — кандидат в `contradicts` |
| `duplicate` | 4 | warning | Похоже на существующую запись (или на запись этой же пачки) — кандидат в слияние или `same_as` |
| `related` | 4 | info | Похожие записи ниже порога дубля — подсказка для связей |

### 2.3. Отчёт и ответ

Отчёт хранится в `changeset.check_report` — и у принятого пакета, и у отклонённого:

```json
{"format": "amem.check/1",
 "levels": {"1": "done", "2": "done", "3": "done", "4": "done"},
 "issues": [{"level": 2, "severity": "info", "code": "page_moved", "where": "@a1: sources[0]",
             "message": "Цитата найдена на странице 12, а не 11", "details": {"page": 12}}],
 "degraded": [{"level": 4, "channel": "vector", "reason": "no_provider"}],
 "templates": ["has_label@1.0.0", "has_source@1.0.0", "has_value@1.0.0"],
 "records": [{"label": "@a1", "target": "atom", "status": "draft", "risk": [], "review": ["semantic"]}]}
```

У отклонённого пакета уровни 3 и 4 — `skipped`, а `records` нет. Ссылок на id новых записей в отчёте нет: id появляются внутри `records.commit`, а пакет после записи не меняется. Метки сопоставляются с id по ответу.

Ответ `Submitted`:
- `state` — `approved` или `rejected`;
- `changeset_id`, `report`;
- `records` — по каждой записи: метка, вид, `record_id`, `revision_id`, `created`, `status`, `review_state`;
- `queued` — поставленные пункты очереди: id, причина, метка, `record_id`;
- `levels` — как в отчёте, плюс уровень 5: `queued`, если поставлен хоть один пункт `semantic`; `not_applicable`, если в пакете одни сущности и связи; `skipped` у отклонённого;
- `complete` — `true` только если ничего не поставлено в очередь.

Обычный пакет атомов возвращает `complete: false` и `levels["5"] = "queued"`: это сделано намеренно.

## 3. Уровень 1 — схема и шаблон

### 3.1. Коды словаря

`kind`, `entity_class` и `rel` ищутся в `concept` по своей схеме. Тип каждого селектора, включая цепочку `refined_by`, ищется в схеме `selector_type`. Нет кода — `unknown_code`. Коды величин проверяет уровень 3.

### 3.2. Шаблоны

Действуют только активные шаблоны: таблица `template_active` хранит версию каждого кода из загруженных сейчас пакетов (разд. 10). Шаблон пакета, который больше не загружается, не действует, хотя строка в `template` остаётся.

**Набор шаблонов записи:**
- все интерфейсы её `target` (`applies_to` пуст);
- шаблон её кода (`applies_to = kind`, `entity_class` или `rel`).

Каждый раскрывается так: сначала его `extends` слева направо (рекурсивно), затем его собственные правила. Правила сводятся по `path`: правило потомка заменяет правило предка с тем же путём. Порядок интерфейсов — по коду шаблона, чтобы итог не зависел от порядка строк в базе. Отчёт перечисляет применённые шаблоны как `code@version`.

**Правила полей** (`FieldRule`). Путь — через точку. `[]` у промежуточного поля значит «каждый элемент списка». Замечание называет конкретный элемент: `sources[1].selectors`.
- `required` — поле непустое:
  - список — хотя бы один элемент;
  - `LangString` — непустой `ru`;
  - объект — хотя бы одно непустое поле;
  - строка — не пустая и не из одних пробелов.
- `min_count` — в списке не меньше N элементов.
- `selector_types` — хотя бы один селектор из перечня с учётом цепочки `refined_by`. Путь ведёт на список селекторов или на источник — тогда берутся его селекторы.
- `entity_classes` — ссылка по пути ведёт на сущность одного из классов. @имя пачки берёт класс из её тела.
- `ucum` — значение по пути, если оно есть, — код UCUM (разд. 3.5).

Важность — из правила, по умолчанию `violation`. Текст — `message` правила или общий.

**Правила связей** (`LinkRules`):
- `allowed` — исходящая связь записи другого вида даёт `link_not_allowed`;
- `required` — нужна хотя бы одна связь этого вида, а при `to_classes` — к сущности одного из этих классов, иначе `link_required`.

Связи считаются вместе: действующие связи записи в базе, связи этой пачки и поля, через которые выражается вид связи (`via_field` у понятия: `about`, `derived_from`).

**Высокий риск.** Шаблон может задать `high_risk` — список правил из закрытого перечня `HighRiskRule`:
- `always` — каждая запись этого вида;
- `numeric` — атом, в котором есть числа из разд. 4.5.

Правила объединяются по всей цепочке `extends`. Ядро получает шаблон `decision` с `high_risk: [always]`; версия пакета ядра — 1.1.0.

### 3.3. Жёсткие правила

Что шаблоном не выразить, проверяется всегда, для каждой величины и уточнения:
- есть `amount`, `lower_bound` или `upper_bound` — нужна `unit` (`unit_required`); безразмерная величина — `1`;
- `lower_bound ≤ upper_bound`, а `amount`, если задан, лежит в границах (`bounds_order`).

### 3.4. Концы связей

У каждой связи пачки пара видов концов (`atom>entity` и т. п.) должна входить в `pairs` её вида, иначе `link_pair`. Вид конца берётся из ссылки: `atm:` или `ent:`, у @имени — из пачки.

### 3.5. UCUM

Код разбирает `ucumvert` с учётом регистра. Код, который не разбирается, даёт `ucum` с важностью правила; у шаблона ядра `has_value` это `violation`. Парсер и реестр pint создаются один раз на процесс, при первом обращении.

### 3.6. Проверка шаблонов при загрузке пакетов

Сейчас осмысленность шаблонов проверяют только тесты, и только у шаблонов, поставляемых с amem. Эти проверки переезжают в `packs.load_packs` и действуют для любого пакета из `AMEM_PACKS`:
- `extends` ведёт на шаблон того же `target`;
- в наследовании нет циклов;
- код `applies_to` есть в словарях загружаемых пакетов;
- пути правил ведут на настоящие поля схемы;
- коды в `selector_types` и `entity_classes` существуют.

Ошибка — `PackError` с файлом шаблона.

## 4. Уровень 2 — привязка к источнику

Уровень 2 проверяет источники атомов. У сущностей источники проверяют только разбор и `digest` (как в `records`); итог сверки у них остаётся пустым, его заполняет `recheck_sources` (разд. 8.9).

### 4.1. Объект и версия

**Источник с `path`** разбирается `objects.resolve_sources`. Если пришла `ObjectError` с местом `sources[i]`, это `source_unresolved`.

**Источник с `object`:**
- нет такой версии — `version_missing`;
- `digest` не тот — `digest_mismatch`.

### 4.2. Место в документе

Селекторы источника, включая цепочку `refined_by`, дают три вещи — ожидаемую страницу, локатор и цитату:

| Тип селектора | Что даёт |
|---|---|
| `page` | Ожидаемую страницу (`sources.as_page`); диапазон «24–25» страницы не задаёт — цитата ищется по всем страницам |
| `sheet` | Страницу: номер листа xlsx с этим именем (имя — первая строка страницы, разд. 9.1); имени нет — место не найдено |
| `table`, `clause`, `figure`, `formula`, `heading` | Локатор: `label`, иначе значение с приставкой — «табл. 11.1», «п. 5.2», «рис. 3», «формула (7)»; у `heading` — значение как есть |
| `text_quote` | Цитату, если поле `quote` пусто |
| `slide`, `range`, `lines`, `function` | Здесь место не уточняют |

Сверка — `sources.judge(text, quote, page, locator)`. Текст — `objects.text`, его кэш `object_text` по `digest`.

### 4.3. Итоги и важность

| Случай | verdict | Замечание |
|---|---|---|
| Страница сайта или переписка | `external` | warning `external_source` |
| У файла нет текста | `no_text` | warning `no_text` |
| PDF без селектора `page` | — | violation `pdf_page_required` |
| PDF без цитаты | — | violation `pdf_quote_required` |
| Цитата на указанной странице | `ok` | — |
| Цитата на другой странице | `moved`; `page` — где найдена | info `page_moved` |
| Цитата найдена нечётко | — | violation `quote_fuzzy` с точным текстом документа |
| Цитаты нет | — | violation `quote_not_found` |
| Цитаты нет, место найдено селектором | `by_locator` | — |
| Цитаты нет, место не найдено | `unresolved` | warning `place_unresolved` |
| Сбой извлечения или сверки | `error` | warning `source_error` |

PDF — объект с `media_type = application/pdf` или с именем на `.pdf`, без учёта регистра.

`fuzzy`, `not_found` и `no_file` при записи не появляются: такие пакеты отклоняются. В строках `source` эти итоги бывают только после повторной сверки (разд. 8.9). Так это и описано в коде уровня 2.

### 4.4. Фрагмент

Фрагмент источника — страница, где сверка нашла место:
- `ok` и `moved` — страница найденной цитаты;
- `by_locator` — страница локатора;
- у одностраничного документа — его страница;
- у селектора `sheet` — лист.

У `external`, `no_text`, `unresolved` и `error` фрагмента нет.

### 4.5. Числа

**Числа атома:**
- `amount`, `lower_bound`, `upper_bound` у `content.values[]`;
- то же у их `qualifiers[]` и у `qualifiers[]` атома;
- числовые ячейки `content.table.rows` — числа JSON; `true` и `false` числами не считаются.

У формул чисел для сверки нет.

**Числа фрагмента.** Из текста фрагмента извлекаются все записи чисел:
- десятичный разделитель — запятая или точка;
- группы разрядов через пробел, неразрывный или узкий пробел — только группы по три цифры;
- минус — `-`, `−`, `–` или `‒`, если перед ним не цифра (иначе это тире диапазона «5–10»);
- запись `1,5e-3`.

Неоднозначная запись даёт оба значения: «1,200» — это и 1.2, и 1200; «10 200» — и 10200, и 10 с 200.

**Сравнение** — точное: десятичная запись числа из JSON (`Decimal(str(x))`) против значений фрагмента, со знаком.

**Итог:**
- число найдено во фрагменте хотя бы одного файлового источника атома — всё в порядке;
- не найдено — `number_not_found`: violation, а если у атома есть источник с `role: derived` — warning; `details` перечисляет ненайденные числа;
- фрагмента нет ни у одного источника — info `numbers_unchecked`.

Записи вида «1,5·10⁻³» и «1,2 тыс.» не разбираются. Значение, пересчитанное агентом, помечается `role: derived` — это записано в README.

### 4.6. Подстановка редакции

Бывает, что у источника нет `edition`, а версия его объекта — источник ровно одной текущей сущности класса `edition`. Тогда эта редакция подставляется в тело и пишется info `edition_filled`. Если таких редакций несколько, ничего не подставляется.

### 4.7. Запись итогов

Итоги пишутся в транзакции записи. Каждая строка `source` находится по ревизии и позиции, обновляются `verdict`, `page`, `anchor`, `checked_at`: `checked_at` — время пакета изменений, `page` — найденная страница, `anchor` — текст для подсветки. Ревизия с телом, совпавшим с текущей (`created = false`), тоже получает свежие итоги. Тест следит, что каждое значение, которое пишет уровень 2, входит в перечень `SourceVerdict`.

## 5. Уровень 3 — здравый смысл

Уровень 3 проверяет величины атомов (`content.values[]`).

**Словарь величин.** Понятия схемы `property` в пакетах задают `unit`, `quantity_kind`, `plausible_min`, `plausible_max`.
- Если в базе нет ни одного понятия `property`, коды величин свободны, и уровень 3 только сверяет атомы между собой.
- Если словарь величин загружен, неизвестный код даёт `unknown_property` — кандидат в новое понятие, которое утверждает человек.

**Диапазон.** У величины словаря с границами значение (`amount` и границы) переводится в единицу понятия:
- значение вне `[plausible_min, plausible_max]` — `out_of_range`;
- перевести нельзя (другая размерность) — `unit_mismatch`.

**Согласие.** Сравниваются атомы, у которых совпадают:
- **сущность** — пересекаются множества `about`;
- **величина** — тот же `property`;
- **условия** — одинаковые множества уточнений атома и значения, после приведения к канонической форме;
- **срок** — `valid_from` – `valid_to` пересекаются.

Если при всём этом значение другое, это `conflict` и риск `conflict`. «Другое» значит: после перевода единиц `amount` или границы различаются больше чем на 1e-9 относительно, либо различается `value_text`. `details` — ссылки на атомы-соперники (кандидаты в `contradicts`).

Соперники ищутся среди текущих атомов со статусом `draft`, `needs_review`, `auto_verified` или `verified`, а также среди атомов этой же пачки. Поиск идёт через `atom_about` по сущностям атома, затем фильтруется в Python. Атом без `about` на согласие не проверяется.

## 6. Уровень 4 — дубли

**Атомы.** Кандидаты — текущие атомы того же вида со статусом `draft`, `needs_review`, `auto_verified` или `verified`; сама запись исключается. Каналы:
- **текст** — полнотекстовый запрос «любое из слов подписи» (лексемы `to_tsvector('russian', label)` через `|`), до 20 кандидатов. Схожесть — `rapidfuzz.fuzz.token_sort_ratio` нормализованных подписей: регистр, `ё → е`, пунктуация убрана;
- **вектор** — если есть provider и активная модель: вектор поискового документа тела (`search.search_text`) против свежих векторов активной модели (`search._vector`), до 20 кандидатов, схожесть = 1 − cosine distance.

Пороги:

| Итог | Текст | Вектор | Сколько кандидатов |
|---|---|---|---|
| `duplicate` (warning) | ≥ 90 | ≥ 0,92 | все выше порога |
| `related` (info) | ≥ 60 | ≥ 0,80 | до 5 |

Пороги — константы модуля; пилот их калибрует.

**Сущности.** Кандидаты — того же класса. Схожесть — лучшая пара среди подписей и `aliases`. `duplicate` предлагает `same_as`.

**Внутри пачки** атомы одного вида и сущности одного класса сравниваются попарно, текстом.

**Без вектора.** Если provider нет (`AMEM_BACKEND=none`, нет модели) или модель покрывает документы не полностью, работает только текст, а отчёт получает `degraded` с причиной. Журнал выдачи (`retrieval`) уровень 4 не пишет: это не поиск пользователя.

## 7. Статусы, риск и запись

### 7.1. Политика по статусу существующей записи

| Запись | Ревизия | Статус |
|---|---|---|
| Новая | Текущая | Атом: `needs_review` при предупреждении или риске, иначе `draft`. Сущность: `needs_review` при предупреждении, иначе `auto_verified` |
| `draft`, `needs_review`, `auto_verified`, `rejected` | Текущая | Как у новой |
| `verified` | Ждёт решения (`pending`), текущая не меняется | Не меняется |
| `deprecated`, `superseded` | — | Ошибка `retired_record` |
| Тело совпало с текущей (`created = false`) | Новой нет | Не меняется; пункты не ставятся |

Предупреждение — замечание с важностью `warning`; `info` на статус не влияет. Риск записи — список: `template:<code>:always`, `template:<code>:numeric`, `conflict`.

### 7.2. Пункты очереди при записи

| Итог | Пункт |
|---|---|
| Атом `draft` | `semantic` — ждёт уровня 5 |
| Атом или сущность `needs_review` с риском | `high_risk` |
| Атом или сущность `needs_review` без риска | `warning` |
| Правка проверенной записи | `edit` |
| Сущность `auto_verified`, попала в выборку | `audit` |

У пункта есть `details`: коды замечаний записи, риск, кандидаты уровней 3–4.

### 7.3. Устаревание

Пункт устаревает, когда его ревизия больше не текущая и не ждёт решения. Такой пункт закрывается как `obsolete`:
- в транзакции записи — у записей, получивших новую текущую ревизию;
- при захвате и решении — лениво. Сюда же попадают пункты записей, которые получили статус `rejected`, `deprecated` или `superseded` мимо очереди.

### 7.4. Аудит

Аудит выбирает записи, перешедшие в `auto_verified`: сущность при записи, атом — после подтверждения уровня 5. Выборка детерминирована: запись попадает в аудит, если `sha256("amem-audit" ‖ revision_id)`, прочитанный как доля от 0 до 1, меньше доли аудита.

Доля аудита — `AUDIT_RATE = 0.02`. Она повышается до `AUDIT_RATE_HIGH = 0.20`, если в последних 50 решениях аудита больше 5 % `refuted`. Окно считается в двух разрезах, и действует большая из двух долей:
- по автору пакета;
- по типу файла первого источника (`media_type`, у источника без файла — `external`).

### 7.5. Транзакция записи

Порядок внутри транзакции:
1. Существующие записи блокируются по возрастанию id — как в `records.commit`, поэтому тупиков нет. Их статусы перечитываются, и по ним выбирается политика 7.1. Если статус сменился так, что правка стала невозможной (`retired_record`), транзакция откатывается и пакет отклоняется.
2. `records.commit` — его `transaction()` становится точкой сохранения. Статус новой записи передаётся через `Item.status`, у существующей — так же; правка проверенной идёт с `review_state = pending`.
3. Итоги сверки — `UPDATE source` (единственное изменение, которое разрешает триггер `amem_source_check`).
4. Устаревшие пункты закрываются, новые вставляются.

## 8. Очередь проверки

### 8.1. Таблицы

**`review_item`** — пункт очереди:

| Поле | Что хранит |
|---|---|
| `id` | UUIDv7 |
| `target`, `record_id` | Вид и id записи |
| `atom_revision_id` / `entity_revision_id` | Ревизия: ровно одно из двух, внешние ключи |
| `reason` | Причина из перечня `ReviewReason` |
| `state` | `queued`, `claimed`, `done` или `obsolete` |
| `changeset_id` | Пакет, после которого пункт появился (у `source_changed` и ручных — пусто) |
| `details` | JSON (разд. 7.2) |
| `created_at`, `created_by` | Когда и кто поставил |
| `claimed_by`, `claimed_until` | Кто захватил и до какого времени |
| `closed_at` | Когда пункт закрыт |

**`verification`** — вердикт, неизменяемый:

| Поле | Что хранит |
|---|---|
| `id` | UUIDv7 |
| `review_item_id` | Пункт; уникален |
| `method` | `llm_judge` или `human` |
| `outcome` | `confirmed`, `partial`, `refuted` или `uncertain` |
| `confidence` | 0–1, у `llm_judge` обязательна |
| `agent`, `note`, `created_at` | Кто, комментарий, когда |

Ограничения:
- на одну ревизию с одной причиной — не больше одного открытого пункта: частичный уникальный индекс по `(ревизия, reason)` при `state IN ('queued', 'claimed')`;
- триггер `amem_review_item_check` проверяет, что `record_id` — запись этой ревизии, и разрешает только переходы разд. 8.3;
- удаление и `TRUNCATE` запрещены у обеих таблиц.

### 8.2. Причины

| Причина | Откуда | Кто решает | Исходы |
|---|---|---|---|
| `semantic` | Атом `draft` | Любой агент, кроме автора пакета | `confirmed`, `partial`, `refuted`, `uncertain` |
| `warning` | Предупреждения уровней 1–4 | `person:` | `confirmed`, `refuted` |
| `high_risk` | Риск записи | `person:` | `confirmed`, `refuted` |
| `semantic_doubt` | Уровень 5 не подтвердил | `person:` | `confirmed`, `refuted` |
| `edit` | Правка записи, проверенной человеком | `person:` | `confirmed`, `refuted` |
| `source_changed` | Новая версия объекта (разд. 8.8) | `person:` | `confirmed`, `refuted` |
| `source_check` | Повторная сверка ухудшила итог (разд. 8.9) | `person:` | `confirmed`, `refuted` |
| `audit` | Выборка аудита | `person:` | `confirmed`, `refuted` |
| `calibration` | Поставлен вручную | `person:` | `confirmed`, `refuted` |

### 8.3. Состояния

```
queued ──claim──▶ claimed ──resolve──▶ done
  │  ▲               │
  │  └──release──────┤   (истёкшую аренду захватывают заново, claimed → claimed)
  └──────────────────┴──────────────▶ obsolete
queued ──resolve──▶ done              (решение без захвата — из карточки)
```

`done` и `obsolete` конечны.

### 8.4. Захват

```python
review.claim(conn, *, agent, reasons=None, limit=1, lease=timedelta(minutes=15), now=None) -> list[dict]
```

Захват берёт самые старые пункты, которые этот агент вправе решать (разд. 8.2): в состоянии `queued` или `claimed` с истёкшей арендой. Пункт `semantic` не достаётся автору его пакета. Выборка — `FOR UPDATE SKIP LOCKED`, поэтому параллельные проверяющие не берут один пункт. Устаревший пункт (разд. 7.3) закрывается как `obsolete` и не возвращается.

Каждый возвращённый пункт содержит:
- поля пункта;
- тело ревизии;
- источники с итогами сверки;
- автора пакета.

`review.release(conn, item_id, *, agent)` возвращает захваченный пункт в `queued`; сделать это может только тот, кто его держит.

### 8.5. Решение

```python
review.resolve(conn, item_id, outcome, *, agent, confidence=None, note=None, now=None) -> dict
```

**Проверки:**
- пункт в состоянии `queued`, или `claimed` этим агентом, или `claimed` с истёкшей арендой;
- агент вправе решать эту причину, исход допустим.

Затем блокируется запись (тем же порядком, что у писателей) и проверяется, что ревизия ещё текущая или ждёт решения. Иначе пункт закрывается `obsolete` и приходит `ReviewError`.

**Запись решения:** пишется `verification`, пункт закрывается как `done`, применяются последствия:

| Причина | Исход | Последствие |
|---|---|---|
| `semantic`, решает модель | `confirmed` и `confidence ≥ SEMANTIC_MIN_CONFIDENCE` (0,8) | `draft → auto_verified`; выборка аудита |
| `semantic`, решает модель | иначе | `needs_review`; пункт `semantic_doubt` |
| `semantic`, решает человек | `confirmed` / `refuted` | `verified` / `rejected` |
| `edit` | `confirmed` / `refuted` | `records.decide(accept=True / False)`; статус остаётся `verified` |
| Остальные | `confirmed` / `refuted` | `verified` / `rejected` |

Статус меняется через `records.set_status_locked` с агентом решающего и причиной `review:<reason>`. Ответ — id вердикта, новый статус, новые пункты очереди.

### 8.6. Ручная постановка

`review.enqueue(conn, ref, reason, *, agent, note=None)` ставит пункт на текущую ревизию записи. Причины — `calibration` или `audit`, а ставить вправе только `person:`. Уже открытый пункт с той же причиной не дублируется — возвращается его id.

### 8.7. Метрики

`review.stats(conn, *, days=7, now=None)` возвращает JSON:

| Раздел | Что внутри |
|---|---|
| `queue` | По причинам: `queued`, `claimed`, `expired` (аренда истекла), возраст самого старого `queued` в секундах |
| `done` | За окно по причинам: число и медиана времени от постановки до решения |
| `changesets` | За окно: `approved`, `rejected`, частота кодов ошибок отклонённых пакетов |
| `records` | Атомы и сущности по статусам |
| `sources` | Строки `source` текущих ревизий по `verdict`; пустой итог — `unchecked` |
| `audit` | По авторам и типам файлов: проверено, `refuted`, действующая доля выборки |
| `calibration` | Ревизии, у которых есть вердикт и `llm_judge`, и `human`: число пар и доля согласия. Согласие — когда «`llm_judge` подтвердил с уверенностью не ниже порога» совпадает с «человек подтвердил» |

`review.items(conn, *, state=None, reason=None, record=None, limit=100)` — список пунктов для интерфейсов.

### 8.8. Новая версия объекта

`objects.ingest` создаёт версию `n > 1` существующего объекта и в той же транзакции вызывает `review.on_new_version(conn, object_id, n, agent, at)`. Пункты `source_changed` получают текущие ревизии атомов и сущностей, которые ссылаются на этот объект с версией меньше `n`, — кроме записей со статусом `rejected`, `deprecated` или `superseded`. В `details`: объект, старые версии, новая.

Открытый пункт той же ревизии не дублируется (`ON CONFLICT DO NOTHING` по частичному индексу). Пункт уходит в `obsolete`, когда запись получает ревизию со ссылкой на новую версию.

### 8.9. Повторная сверка

```python
review.recheck_sources(conn, store, *, agent, scope="unchecked", limit=None, now=None) -> dict
```

Повторная сверка заново проверяет строки `source` текущих ревизий атомов и сущностей:
- `scope="unchecked"` — только с пустым итогом или `error`;
- `scope="all"` — все строки.

Каждая запись сверяется в своей транзакции. Копии нет в хранилище — итог `no_file`. Пункт `source_check` получает активная запись, у источника которой итог стал `fuzzy`, `not_found` или `no_file`. Ответ — итоги по видам и поставленные пункты. Числа здесь не сверяются: это работа уровня 2 при записи.

## 9. Текст xlsx и docx

### 9.1. xlsx и xlsm

`openpyxl.load_workbook(read_only=True, data_only=True)`:
- каждый лист книги в её порядке — страница;
- первая строка страницы — имя листа;
- дальше строки листа: ячейки через табуляцию, хвостовые пустые ячейки отброшены, пустые строки пропущены.

Значения ячеек:
- целое — как есть, дробное — `repr`;
- дата — ISO;
- `True`/`False` — `TRUE`/`FALSE`;
- перевод строки в ячейке — пробел;
- у формулы — сохранённое значение; если его нет, ячейка пустая.

Скрытые листы входят. Битая или зашифрованная книга — текста нет.

### 9.2. docx

`word/document.xml` разбирается стандартными `zipfile` и `xml.etree.ElementTree`. Сущности не раскрываются, а expat 2.4+ защищён от «billion laughs». Тело читается по порядку:
- абзацы: `w:t`, `w:tab` — табуляция, `w:br` — перевод строки;
- `w:ins` входит, а `w:del`, `w:delText` и `w:instrText` — нет;
- таблицы: строка таблицы — ячейки через табуляцию, абзацы ячейки — через пробел; вложенные таблицы разворачиваются.

Новая страница начинается на `w:br w:type="page"` и на `w:lastRenderedPageBreak` — так Word запоминает разбиение на страницы при сохранении. Документ без таких отметок — одна страница. Колонтитулы, сноски и примечания не входят.

### 9.3. Пределы и кэш

**Пределы.** Распакованный `document.xml` больше 256 МиБ или извлечённый текст больше 50 млн знаков — текста нет (`no_text`). Подрезанный текст дал бы ложное «цитата не найдена».

**Остальные форматы.** `.doc`, `.xls`, `.odt`, `.ods`, `.pptx` по-прежнему без текста.

**Кэш.** Миграция `0006` удаляет строки `object_text` страницы 0 у версий файлов с именами на `.docx`, `.xlsx`, `.xlsm`. Следующее обращение извлечёт текст заново. Ключ кэша остаётся прежним — `digest`.

## 10. Схема и миграция

**LinkML** (`amem_v1.yaml`, затем `tools/gen_schema.py`):
- перечни `CheckCode`, `ReviewReason`, `ReviewItemState`, `VerificationMethod`, `VerificationOutcome`, `HighRiskRule`;
- поле `Template.high_risk`;
- классы `CheckIssue`, `CheckReport`, `ReviewItem`, `Verification` — для JSON Schema отчёта и пунктов, которые отдадут сервер и интерфейсы.

Перечни в `CHECK` SQL совпадают с перечислениями схемы — это проверяет `tests/test_sql_schema.py`, как раньше.

**`0006_check.sql`:**
- `review_item`, `verification`, триггеры `amem_review_item_check`, запрет удаления и `TRUNCATE`;
- индексы: `review_item (state, reason, created_at)`, `review_item (record_id)`, `changeset (state, created_at)`;
- `template_active (code PRIMARY KEY, version, FOREIGN KEY (code, version) REFERENCES template)`. `db.load_vocab` в своей транзакции переписывает его по загруженным пакетам;
- удаление кэша страницы 0 у docx/xlsx/xlsm.

**Бэкап.** `backup.COUNTED` получает `review_item` и `verification`.

**Зависимости:** `ucumvert` (тянет pint и lark) и `openpyxl`. `requires-python = ">=3.11"`.

## 11. Ошибки и наблюдаемость

- **`check.CheckError(ValueError)`** — неверный вызов: пустая пачка, неизвестный `target`, соединение без autocommit. Ошибки данных — не исключения, а замечания отчёта.
- **`review.ReviewError(ValueError)`**:
  - пункта нет или он закрыт;
  - аренда чужая;
  - нет прав на причину;
  - исход недопустим;
  - `confidence` вне 0–1 или не задана у модели;
  - пункт устарел.
- **Ошибки окружения** (`StoreError`, `psycopg.OperationalError`, `EmbedError` явного provider) уходят наверх, в базе ничего не меняется.
- **Каждое ослабление** — нет вектора, у источника нет текста, нечего сверять с числами — видно в отчёте (`degraded`, `no_text`, `numbers_unchecked`), а не скрыто.

## 12. Приёмка

| Требование | Как проверяется |
|---|---|
| Ошибка уровня 1 или 2 отклоняет пакет целиком | Пакет из двух атомов, у одного нет источника: записей нет, `changeset.state = rejected`, отчёт с `where` |
| Шаблоны: сведение, наследование, правила | Пакет-пример с интерфейсами и `extends`: правило потомка заменяет правило предка; `required`, `min_count`, `selector_types` (через `refined_by`), `entity_classes`, `ucum`; `allowed` и `required` у связей, в том числе через `about` |
| Неактивный шаблон не действует | Пакет убран из `AMEM_PACKS` и `load_vocab` повторён — правило его шаблона больше не срабатывает |
| Шаблоны проверяются при загрузке | Цикл `extends`, неизвестный `applies_to`, путь на несуществующее поле — `PackError` с файлом |
| UCUM | `kPa`, `W/(m2.K)`, `Cel`, `1`, `%` проходят; `кПа`, `KPA`, `m/s/` — нет |
| PDF: страница и цитата | PDF без `page` или без цитаты — отклонён; цитата на соседней странице — `moved`, номер исправлен в `source.page` |
| Таблица на настоящей странице | Тестовый PDF: числа таблицы на её странице находятся, а при ссылке на соседнюю страницу — `number_not_found` |
| Числа | `0,17` / `0.17`, «1 200», `−5` и `–5` находятся; тире диапазона «5–10» не делает 10 отрицательным; `role: derived` даёт предупреждение вместо ошибки |
| Нечёткая цитата | Отклонена, `details` — точный текст документа |
| Предупреждение → `needs_review` | Источник-переписка: атом `needs_review`, пункт `warning` |
| Высокий риск всегда к человеку | `decision` без замечаний — `needs_review` и пункт `high_risk`; правило `numeric` пакета-примера |
| Диапазон и противоречие | Значение вне диапазона — `out_of_range`; другое значение той же величины у той же сущности при тех же условиях — `conflict` и риск; при других условиях — нет |
| Дубли | Похожий атом — `duplicate` с кандидатом; без provider — только текст и `degraded`; дубль внутри пачки находится |
| Сущности | Без замечаний — `auto_verified`; похожая — `needs_review` с предложением `same_as` |
| Правка проверенного | Ревизия `pending`, текущая прежняя, пункт `edit`; решение `confirmed` делает её текущей |
| Итоги сверки в `source` | `verdict`, `page`, `anchor`, `checked_at` записаны; все значения входят в `SourceVerdict` |
| xlsx и docx | Цитата на листе xlsx и в docx находится; селектор `sheet` даёт страницу; разрыв страницы в docx — новая страница; кэш страницы 0 у старого docx сброшен миграцией |
| Ответ: «в очереди» ≠ «сделано» | У атома `complete: false`, `levels["5"] = "queued"`, пункт в `queued`; у пакета из одной сущности без выборки — `complete: true` |
| Очередь: захват и аренда | Два параллельных захвата не берут один пункт; истёкшую аренду забирает другой; `release` чужого — ошибка |
| Права | Автор не решает `semantic` своего пакета; модель не решает `warning`; человек решает всё |
| Решение | `semantic confirmed` с уверенностью 0,9 → `auto_verified`; с 0,5 → `needs_review` и `semantic_doubt`; `refuted` человека → `rejected` |
| Устаревание | Новая ревизия закрывает пункты старой как `obsolete`; решение по устаревшему — `ReviewError` |
| Аудит | При доле 1,0 пункт `audit` появляется; при 5 % ошибок в окне доля выборки — 20 % |
| Метрики | `stats` считает очередь, возраст, решённое, отклонённые коды, источники, аудит и согласие калибровки на подготовленных данных |
| Новая версия объекта | Изменённый файл → пункты `source_changed` у текущих ревизий со ссылкой на старую версию; повторный приём не дублирует их |
| Повторная сверка | Испорченный текстовый слой → `not_found` в строке и пункт `source_check`; `error` перепроверяется |
| Неизменяемость | `verification` нельзя изменить или удалить; у `review_item` запрещённый переход отвергает триггер |
| PostgreSQL 18 и 16 | Все тесты базы — на обеих версиях |

## 13. Риски

| Риск | Что делаем |
|---|---|
| Сверка чисел ложно отклоняет верные атомы (формат числа, пересчёт единиц) | Отчёт перечисляет ненайденные числа; пересчитанное помечается `role: derived`; разбираемые форматы растут по примерам пилота |
| `lastRenderedPageBreak` устарел, номера страниц docx расходятся с Word | Цитата ищется по всем страницам, расхождение даёт `moved`, а не отказ |
| Пороги дублей и уверенности не откалиброваны | Константы модуля; метрика `calibration`; пилот меняет их одной правкой |
| Очередь растёт быстрее, чем её разбирают | `stats` показывает возраст и объём; уровень 5 разгружает `semantic`; правило «предупреждение — к человеку» пересматривается по данным пилота |
| Тупик между записью и решением | Решение и запись блокируют записи в одном порядке — по id; решение по одной записи — одна блокировка |
| `ucumvert` медленно стартует | Ленивая инициализация один раз на процесс; без единиц в пакете он не загружается |
