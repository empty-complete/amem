# amem — подпроект 5, часть K «Карточка по настоящему профилю»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** карточка сущности показывает то, что действительно отдаёт ядро (`profile.card`, `amem.card/1`), а не форму, придуманную для моков. В README появляется настоящий снимок карточки.

**Откуда задача.** Карточку интерфейс до сих пор видел только на моке `card-e3.json`. Настоящая карточка из профиля пакета области отличается от него:

| Поле | Ядро | Мок и интерфейс сейчас |
|---|---|---|
| `group` | код группы правила (`body`, `environment`) — словаря подписей нет | слово («Условия»); интерфейс выводит `group` как есть, на настоящей базе — кодом |
| `ask` | у кого спросить, если значения нет («изготовитель») | текст заданного вопроса, только у `asked` |
| `hint` | где искать | где искать (совпадает) |
| `origin` | код словаря `parameter_origin` — откуда обычно берётся значение | не показывается |
| `when` | когда поле нужно | не показывается |
| `rule` | шаблон, давший правило (`code@version`) | не показывается |
| `inherited_from` | ядро не заполняет | в моке есть, интерфейс показывает «унаследовано от …» |
| `asked` | вопрос — атом в `atoms` | текст из `ask` |

**Спецификация:** `docs/superpowers/specs/2026-11-06-amem-subproject-5-web-ui-design.md`, разд. 5.5. Подпроект 3c — профили и карточки.

**Ветка:** `subproject-5k-card` от `main`. Проверки — в CI, локально не гонять.

### Task 1: Пакет-образец «метеостанция» с профилем
**Files:** `tools/sample-pack/meteo/{pack.yaml, vocab/*.yaml, templates/*.yaml}`, `tools/seed_sample.py`, `web/playwright.service.config.ts`, `.github/workflows/web.yml`, README (en/ru).

- [ ] Пакет `meteo` без зависимостей, по образцу тестового пакета `ontology`:
  - класс `sensor` (`broader: artifact`);
  - свойства, которые пишет образец: диапазоны, погрешности, рабочая температура, степень защиты;
  - `parameter_origin` (паспорт, измерено, по методике);
  - `parameter_group` с подписями групп;
  - профиль `sensor` с группами, `origin`, `ask`, `hint`, `when` и одним умолчанием.
- [ ] Образец ставит датчикам класс `sensor`, значения пишет теми же свойствами. У датчика В-2 в карточке будут поля всех видов: известно, нет данных с подсказкой «спросить … · где …», умолчание к принятию.
- [ ] `AMEM_PACKS` указывает на `tools/sample-pack` в e2e против службы (конфиг Playwright), в CI и в быстром старте README.

### Task 2: Карточка по настоящей форме (веб)
**Files:** `web/src/features/card/{CardTable,CardPage,card}.tsx|ts`, `web/src/i18n/*.json`.

- [ ] **Группа** — подпись из словаря `parameter_group`. Это соглашение для пакетов: словарь необязательный, ядро его не проверяет. Нет словаря или кода — код по-человечески (`environment` → «Environment»).
- [ ] **Подстрока поля:**
  - `hint` — «где: …»;
  - `ask` — «спросить: …»;
  - `origin` — подпись из словаря `parameter_origin`;
  - `when` — «нужно, если: …».

  Всё мелко и в одну строку, пустое не показывается.
- [ ] **`asked`** — ссылка на вопрос (атом из `atoms`, который не из значений), а не текст `ask`.
- [ ] **`rule`** — подсказка у названия поля: «по шаблону sensor@1.0.0».
- [ ] **`inherited_from`** остаётся: поле в контракте есть, ядро может начать его заполнять.

## Риски

| Риск | Что делаем |
|---|---|
| Пакеты областей без `parameter_group` | Запасная подпись — код по-человечески; авторам пакетов — абзац в справочнике |
| Ядро позже начнёт заполнять `inherited_from` или поменяет смысл `ask` | Контракт описывает поля; моки сверяются с ним во время тестов |
| Пакет-образец разойдётся с моками | Те же свойства и профиль; карточка проверяется и на моках, и против службы |
