# amem — подпроект 5, часть D «Запись человека»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Человек пишет в базу так же легко, как читает. Правило — «одно поле, Enter, звезда».

- **Правка записи на месте:** карандаш `⌘E`, свойства по шаблону вида, тело в редакторе с маленькой панелью, исходник `⌘\`.
- **Новая запись** `/new` — тот же экран в правке.
- **Окно по `N`:** одно поле, вид выводится из текста.
- **На странице объекта:** строка «Добавить заметку»; пустое поле карточки заполняется на месте, умолчание — кнопкой «Принять».
- **Окно отмены** 6 с и звезда, которая загорается в небе.
- **«+ Источник»** с местом в файле: страница и цитата, лист и диапазон, рамка, строки.
- **Папки:** создать, переименовать, перенести запись.
- **Конструктор вида** в пакете «Мои виды».

Всё работает на моках контракта, а пакет уходит в `check.submit` тем же путём, что у агентов.

**Architecture:** новая фича `web/src/features/write/`:
- вывод вида и полей из текста (`infer.ts`);
- сборка предложения из документа и шаблона (`proposal.ts`);
- отправка с окном отмены и `keepalive` (`useSubmit.ts`);
- черновики (`drafts.ts`);
- редактор тела (`BodyEditor.tsx`, CodeMirror, лениво);
- свойства в правке (`PropertyEditor.tsx`);
- выбор вида (`KindPicker.tsx`);
- окно по `N` (`QuickWrite.tsx`);
- выбор места в источнике (`SourcePicker.tsx`).

Конструктор вида — `features/kinds/`, папки — правка `app/shell/Folders.tsx`. Экран записи части B получает режим правки, а не дублируется. Шаблон вида в UI — это `TemplateView` из контракта (Task 1): форма, тело, виджеты. Ничего о видах не зашито в код: код только знает типы свойств.

Спецификация: `docs/superpowers/specs/2026-11-06-amem-subproject-5-web-ui-design.md`, разд. 5.4, 5.9, 5.11, 5.13, 3c (политика `person:` → `verified`). Эскизы: `v8-note` (правка, вид, конструктор), `v4-notes` (заметки у объекта, заполнение карточки), `v9-source` (папки). Антипример — `v7-editor`.

**Tech Stack:** то, что уже есть после A–C, плюс `@codemirror/commands`, `@codemirror/autocomplete` (`[[`, `@`, `#`) и `@codemirror/language` (уже стоит). Всё в ленивом куске редактора.

**Ветка:** `subproject-5d-writing` от `main` после слияния части C (PR #20). Worktree: `~/projects/amem-web-d`.

**Связь с подпроектом 4.** Папки (`POST/PATCH/DELETE /folders/{path}`, `PATCH /records/{ref}/folder`, `FolderRenamed`) и `/submit` (`Proposal`, `LinkProposal`) вносит в контракт служба своей веткой 4a; шаблоны, «Мои виды», объекты и задачи она реализует частью 4d. Если 4a ещё не в `main`, Task 7 берёт эти пути из её ветки. Остальные дополнения (Task 1, шаги 2–5) — этой веткой; со службой согласованы 07.11. Если 4a сольётся раньше — синхронизировать копию контракта в пакете службы (`amem/service/http-v1.openapi.yaml`). Библиотеке нужно:
1. записывать шаблоны в пакет «Мои виды» (пакет в базе, не файл);
2. хранить у шаблона блок `ui` (тело, виджеты, подписи и подсказки свойств);
3. отдавать форму шаблона (`TemplateView.form`), выведенную из `FieldRule.path` и `parameters`.

### Task 3: Вид и поля из текста

**Files:** Create `web/src/features/write/infer.ts`, `infer.test.ts`.

- [ ] **Step 1: Тест** (таблица):

```ts
import props from "../../mocks/fixtures/vocab-property.json";
import { infer } from "./infer";

const cases: [string, Partial<ReturnType<typeof infer>>][] = [
  ["Нужен ли обогрев В-2 зимой?", { kind: "question", label: "Нужен ли обогрев В-2 зимой?" }],
  ["Решили ставить мачту на 2 м", { kind: "decision" }],
  ["Принято: опрос раз в минуту", { kind: "decision" }],
  ["Оказалось, иней искажает показания", { kind: "lesson" }],
  ["Урок: проверять отвес после ветра", { kind: "lesson" }],
  ["Влажность в будке: 87 %", { kind: "parameter", quantity: { label: "Влажность в будке", amount: 87, unit: "%" } }],
  ["Температура −3,5 °C", { kind: "parameter", quantity: { label: "Температура", amount: -3.5, unit: "Cel" } }],
  ["Проверить крепление мачты\nхомуты верхний и средний", { kind: "note", label: "Проверить крепление мачты", body: "хомуты верхний и средний" }],
];

test.each(cases)("%s", (text, want) => {
  expect(infer(text, { properties: props as never })).toMatchObject(want);
});

test("@объект и #тег вынимаются из текста, но текст не портится", () => {
  const r = infer("Обогрев @В-2 нужен с ноября #зима", { properties: [], objects: [{ ref: "ent:3", label: "Датчик влажности В-2", codes: ["В-2"] }] });
  expect(r.about).toEqual(["ent:3"]);
  expect(r.tags).toEqual(["зима"]);
  expect(r.label).toBe("Обогрев В-2 нужен с ноября");
});
```

- [ ] **Step 2–3: Реализация `infer(text, ctx)`** — чистая функция:
  - первая строка — заголовок, остальное — тело;
  - вид по правилам разд. 5.9, по порядку: `?` в конце первой строки → `question`; «Решили/Решение/Принято» в начале → `decision`; «Урок/Оказалось» → `lesson`; «Имя[:] число единица», где единица — из подписей `vocab-property` (`%`, `°C`, `гПа`, `с`, `В`, `м`) или их кода → `parameter` с `quantity`; иначе `note`;
  - число: запятая и точка, минус `−`;
  - `@` — объект по коду или началу подписи (из `ctx.objects`), в тексте остаётся подпись без `@`;
  - `#тег` — в `tags`, из текста удаляется.

  Вывод — подсказка: плашка вида меняется одним нажатием, и это сильнее вывода.
