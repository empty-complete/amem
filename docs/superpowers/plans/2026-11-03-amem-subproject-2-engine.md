# amem — подпроект 2 «Движок»: план реализации

03.11.2026. Исполняет `docs/superpowers/specs/2026-11-03-amem-subproject-2-engine-design.md` (редакция 1).

**Цель:** библиотечный поиск по атомам и сущностям, четыре именованных рецепта, локальные эмбеддинги, очки полезности и проверяемый бэкап. Всё работает на PostgreSQL 18 и 16; старая серия тестов остаётся зелёной.

**Формат:** задачи выполняются по порядку, каждая — через падающий тест → минимальную реализацию → focused test → полный прогон → коммит. Нельзя переходить дальше с красным тестом или отключать проверку ради скорости. Если реализация обнаруживает противоречие со спецификацией, сначала исправляется спецификация с записью причины, затем план.

**Рабочее дерево:** `~/projects/amem`, ветка `amem-engine-v1` от `main` (`f75dc85`). Пуш в публичный `origin` разрешён; ветка сливается только после полного прогона и ревью.

**Команды:**

```bash
cd ~/projects/amem
docker compose --profile test up -d --wait db-test db-test-pg16
env -u PYTHONPATH .venv/bin/pytest -q -p no:cacheprovider
.venv/bin/python tools/gen_schema.py --check
```

Тестовые базы обязательны: их отсутствие — ошибка, не skip. Каждый коммит задачи содержит краткое сообщение о числе новых проверок. Модель эмбеддингов в тестах не скачивается.

Ранги RRF начинаются с 1. Начальные веса: `exact_fact` — `code_exact=4`, `code_prefix=2`, `fts=1`, `vector=0.25`; `similar` — `vector=2`, `fts=0.5`. Константы собраны в одном `RANKING_V1`, не размазаны по SQL.

### Task 8: Выдача `retrieval` и очки полезности

**Files:** `amem/usefulness.py`, `amem/search.py`, `amem/recipes.py`, `tests/test_usefulness.py`.

- [ ] **Step 1: падающие тесты выдачи.** Текстовый поиск создаёт один `retrieval` с автором, задачей, рецептом, запросом и `ranking_version`; `retrieval_item` содержит только атомы и их окончательные места. Поиск только сущностей допустим и даёт выдачу без atom items; `what_changed` журнал не создаёт.
- [ ] **Step 2: права на отметку.** `mark_helpful` принимает только атомы из этой выдачи, при совпадающей непустой `activity`. Сначала проверить всю пачку, затем записать: чужой атом, сущность, другая задача или выдача без задачи отклоняют всё без частичных строк.
- [ ] **Step 3: идемпотентность.** Повтор той же отметки за задачу не увеличивает счёт; две разные задачи дают две отметки; один атом в двух retrieval одной задачи — одна. Проверить поведение под unique constraint, без UPDATE журнала.
- [ ] **Step 4: формула.** При фиксированном `now` отметка возраста 0 весит 1, 180 дней — 0.5, 360 — 0.25; сумма и множитель `min(1.25, 1 + 0.05*ln(1+score))` сходятся с независимо посчитанным эталоном. Будущая отметка отклоняется.
- [ ] **Step 5: интеграция ранжирования.** Множитель применяется после RRF и до сортировки; новый атом имеет 1; `usefulness=False` отключает и чтение отметок, и их влияние. Тест: точный код остаётся первым, очки не меняют status/review/confidence и не появляются в карточке.
- [ ] **Step 6: пережить правку.** Новая ревизия того же атома сохраняет его счёт; старый `retrieval_item` продолжает ссылаться на атом, а не ревизию. Комментарий для будущего `kb_merge` оставить в модуле, сам merge не реализовывать.

## Критерии готовности

- Четыре рецепта работают как библиотека и покрыты приёмочными тестами спецификации.
- Поисковая проекция не расходится с текущими ревизиями; полная перестройка безопасна.
- HNSW/`halfvec` и смена модели проверены на pg18/pg16 без скачивания модели в CI.
- `AMEM_BACKEND=none` честно сохраняет лексический поиск и помечает семантику недоступной.
- Полезность меняет только порядок; точный код, неизвестная уверенность и слабая роль источника защищены тестами.
- Дамп и полный OCFL-снимок реально восстановлены, поиск после restore выполнен на обеих версиях PostgreSQL.
- Вся прежняя и новая серия зелёная, `gen_schema.py --check` чист, CI на `main` успешен.
