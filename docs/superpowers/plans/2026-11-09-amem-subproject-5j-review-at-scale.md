# amem — подпроект 5, часть J «Очередь в сотни пунктов»: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** очередь проверки в сотни пунктов разбирается по документам, подряд, без потерь.

**Откуда задача.** Когда в базу заводят документы пачками, в очереди сразу оказываются сотни пунктов, а виды и классы записей приходят из пакетов области. На такой базе видно:
- **Очередь — плоский список по времени.** Пункты одного документа перемешаны с остальными. В строке не видно, из какого документа запись и о чём сомнение.
- **`/review/items` отдаёт не больше 100 пунктов** (умолчание ядра), а веб `limit` не передаёт. Лишние пункты молча пропадают.
- **Семья знания (цвет плашек и звёзд) зашита в веб списком** (`ui/families.ts`). Виды и классы из пакетов он не знает, хотя служба отдаёт `family` в словаре (`VocabEntry.family`).

**Спецификация:** `docs/superpowers/specs/2026-11-06-amem-subproject-5-web-ui-design.md`, разд. 4.4 (семьи), 5.7 (проверка). **Ветка:** `subproject-5j-queue` от `main`. Проверки — в CI (локально не гонять).

- [x] У `ReviewItem` — необязательные поля:
  - `source: {object, object_name} | null` — первый источник ревизии пункта (основной по порядку тела);
  - `about: [{ref, label}]` — о ком запись (у атома; у сущности — пусто).
- [x] Обогащение — пакетом на весь список: `lookup.revisions_sources` по ревизиям пунктов, имена объектов одним запросом, подписи — `_labels`. Без запроса на каждый пункт.
- [x] Тесты: пункт атома с PDF-источником — имя файла; атом без источника (`basis`) — `source: null`; сущность — `about: []`; ответ проходит схему контракта.
- [x] Части `test` и `web-service` CI — зелёные. Контракт меняется вместе со службой, как договорено в спецификации 4 (один файл, обе стороны).

### Task 2: Очередь по документам (веб)
**Files:** `web/src/api/queries/index.ts`, `web/src/features/review/{QueueList,ReviewPage,groups}.tsx|ts`, `web/src/i18n/*.json`, `web/src/features/review/review.css`.

- [x] Веб просит `limit=500` (предел контракта); если пришло ровно 500 — строка «Показаны первые 500 пунктов».
- [x] Переключатель «По времени · По документам» над списком. По документам — группы по `source.object_name`:
  - в группе — число пунктов;
  - группы «Без источника» и «Сущности» идут последними;
  - внутри группы — по времени.

  Выбор переключателя запоминается в адресе (`?group=source`).
- [x] Фильтр «Документ» и «Объект» — выбор из того, что есть в очереди (клиентский фильтр поверх загруженного; адрес `?object=…&about=…`).
- [x] Строка пункта: подпись, причина словами, **о чём сомнение** — первый кандидат («похожа на …», «расходится с …»; код из `details.candidates`, подпись — из `/records/{ref}` лениво или из `about`), документ мелко.
- [x] Клавиши `J`/`K` идут по порядку на экране (с группами — внутри и через группы); после решения открывается следующий пункт **той же группы**.
- [x] Виртуальный список остаётся (от 60 пунктов); заголовки групп — строки списка без выбора (`role="presentation"` у заголовка, пункты — `option`).

### Task 3: Семья вида — из словаря (веб)
**Files:** `web/src/ui/families.ts`, места вызова `familyOf` (`RecordList`, `KindChip`, `StarCard`, `sky/model.ts`), тесты.

- [x] Правило:
  - `familyOf(code, target, vocab)` — сущность всегда «объект»;
  - атом — `family` из словаря `kind`;
  - нет записи в словаре — «работа», как в ядре: «вид без family — work».
- [x] Список `SOURCE` в коде — только запасной, пока словарь не загрузился.
- [x] Словарь `kind` берётся из кеша запросов (`q.vocab("kind")`) — без новых запросов на каждую плашку.

### Task 4: Моки, образец, тесты

> **Итог.** Очередь на 120 пунктов в общие моки не добавлена: на восьми пунктах держатся счётчики и прежние тесты. Масштаб — сотни пунктов, группы, порядок, фильтры — проверяют unit-тесты `groups.test.ts` на синтетической очереди. Мок списка выводит `source` и `about` из записи, как служба. Двум записям из руководства в генераторе добавлен источник, поэтому в моках видны группа «Руководство» на 3 пункта и «Без источника». В образце службы уже два документа (PDF и xlsx), нового не понадобилось.
- [x] Моки:
  - очередь на 120 пунктов в трёх документах, с кандидатами и без источника — генератор `make-review-fixtures.py`;
  - словарь `kind` с видом из пакета области (`family: source`);
  - всё сверяется с контрактом (`src/mocks/contract.ts`).
- [x] Образец службы — ещё один документ и пакет пунктов, чтобы группировка была видна на настоящей службе.
- [x] Тесты:
  - unit — группировка, фильтры, порядок `J`/`K` с группами, `familyOf` по словарю;
  - e2e на моках — по документам, фильтр, решение → следующий в группе, строка «первые 500»;
  - e2e против службы — группы по документам и `source` у пункта;
  - axe на `/review?group=source`.
- [x] Бюджеты прежние.
